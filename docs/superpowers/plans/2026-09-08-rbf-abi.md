# RBF ABI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Load described FPGA packages through explicit ABI drivers and demonstrate
standalone Mistral Pong with video, controller input and Stop/relaunch.

**Architecture:** Keep raw MiSTer loading and format-1 bundles working. Add a
closed format-2 package, separate platform programming from core communication,
and share one lifecycle controller across old and new local protocols. Shared
definitions and fixtures precede component implementation.

**Tech Stack:** Go, Python 3.11+, C++14, Verilog/SystemVerilog, Verilator,
Yosys/nextpnr-mistral, Cyclone V HPS GP and ADV7513.

**Spec:** [Approved RBF ABI design](../specs/2026-09-08-rbf-abi-design.md).
Read it before this plan; field tables, wire values and bounds are normative.

## Global constraints

- Bare `.rbf` defaults to MiSTer; invalid packages never fall back to raw loading.
- `.fcore` is uncompressed restricted POSIX ustar containing `manifest.toml`
  followed by `core.rbf`, then exactly two zero blocks.
- Manifest: 1 through 65,536 bytes. Payload: 1 through 33,554,432 bytes.
  HTTP archive maximum: 33 MiB. Local protocol maximum: 65,536 bytes.
- Package identity includes exact manifest and payload bytes using the spec's
  length-prefixed SHA-256 construction.
- Target: `de10_nano`, `5CSEBA6U23I7`. First custom ABI: `fes.simple-game` 1.0.
- Required Pong interfaces: `fes.gamepad` 1.0 and `fes.video.fixed-720p60` 1.0.
- C++14 target; no Go emitter at target build/runtime and no runtime shell tools
  for package extraction. Generated consumers are checked in, never hand-edited.
- GP exchange deadline: 100 ms; complete discovery: 2 s, both bounded by the
  enclosing lifecycle deadline. Do not retry an ambiguous timed-out command.
- One physical lifecycle and existing kit lease. Preflight rejects without
  quiescing the active session. Preserve SNES save-failure behavior.
- UI and menu accelerator implementation are outside this milestone.
- Work in separate component worktrees. Only FES integration updates gitlinks.
- Commits/pushes/PRs require the user's authorization under repository policy;
  without it, checkpoints are tested diffs. No hardware support claims from fakes.
