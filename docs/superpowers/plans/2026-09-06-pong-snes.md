# Pong and SNES Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or
> superpowers:executing-plans to implement each bounded deliverable.

**Goal:** Three playable native systems with reliable switching.

**Architecture:** Retain package definitions, FPGA builds, physical lifecycle,
and product coordination in their existing owners. Introduce ROM-less Pong
before the fuller SNES cartridge and controller integration.

**Tech Stack:** Go, C++14, SystemVerilog, Verilator, Quartus 17.0.2, Buildroot.

**Spec:** [Pong and SNES design](../specs/2026-09-06-pong-snes-design.md).

## Global constraints

- Preserve the working Mega Drive launch and input mapping.
- Keep `sources/` clean; component workers use `out/dev/pong-snes/`.
- No commits, remote publication or parent pin changes in this initial slice.
- Software tests do not establish physical support.
- Reuse compiler/base caches; coordinate one FPGA build and kit operator.

## SNES native software implemented; hardware integration in progress

- Package owner: append explicit media transform (`raw` by default,
  `snes_cartridge` for SNES); append X/Y/L/R/Select controls, regenerate all C++
  consumers with a versioned shared layout. Preserve MD masks and Main index 0.
- Runtime owner: use native index 1, preflight the retained descriptor before
  programming, and stream a synthesized 512-byte prefix plus the ROM window in
  one transaction. Accept coherent ordinary LoROM/HiROM headers, power-of-two
  payloads up to 4 MiB, and optional validated copier headers. Reject unsupported
  mapper/chip formats and ambiguity; no whole-ROM buffering or pathname reopen.
- FogCast owner: exact SNES native identity/path and retained cartridge delivery,
  full controller capabilities, existing session/error recovery. Transformation
  remains in runtime. Persistent saves are not part of this slice.
- Builder owner: retain the first SNES timing-failed build and qualify a separate
  deterministic fitter trial without changing upstream RTL or timing constraints.
- Integrator: assemble one diagnostic image, exercise SNES and repeat the
  cross-system sequence. Keep parent pins unchanged until review/authorization.
