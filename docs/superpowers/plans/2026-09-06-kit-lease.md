# Kit lease implementation plan

**Goal:** Give game and development sessions exclusive, renewable ownership of
one kit, with expiry and explicit operator takeover.

**Architecture:** The existing FogCast target agent enforces a single in-memory
lease at admission to hardware and input requests. Revocation closes input and
waits for admitted operations before the existing coordinator cleans up. The
runtime remains the physical lifecycle owner.

**Spec:** [Kit sharing](../../kit-sharing.md), approved for implementation by the
user with explicit timeout/override requirements.

**Constraints:** Preserve the tested Pong/SNES worktrees and clean parent pins.
Work in `out/dev/kit-lease/`. Do not commit or publish. No compiler/Linux rebuild.
Use existing bearer authentication for deliberate operator takeover; ordinary
clients never invoke takeover automatically. Default TTL90s, renewal20s.

- [x] Target lease state machine: `FogCast/internal/kitlease/manager.go` and
  `manager_test.go`. Test simultaneous claims, renew/expiry, pending operations,
  old credentials, lost-response idempotence, blocked cleanup and takeover.
  Run `go test -race ./internal/kitlease` before integrating HTTP.
- [x] Target HTTP admission and startup wiring: `internal/httpapi/kit.go`,
  existing server/input routes and `cmd/mister-agent/main.go`. Test missing and
  foreign credentials, actual stream shutdown, in-flight revocation and startup
  recovery. The manager's `Begin` returns a revocation context and completion
  callback; hold that admission until the mutation finishes.
- [x] Host lease client in `host/kit_lease.go`, target clients and FogCast service
  composition. Share ownership with input including CONNECT; never claim merely
  to Stop an unknown session. Tests exercise renewal/loss and request headers.
- [x] misteross thin development client in `scripts/kit.py`: status, renewable
  session, repeated dev-RBF uploads, Stop/release, explicit takeover. Test through
  a local HTTP target and document commands and SSH/JTAG maintenance bypasses.
- [x] Review the assembled contract independently, run affected suites and parent
  consistency, then cross-build only changed Go artifacts. Use a separate
  diagnostic image and the designated kit to prove competing clients cannot
  Stop/load/input, abandoned leases expire, and explicit takeover recovers.
- [x] Update current guides and record exact artifacts/results/limitations.

Implementation uses test-first changes and checks each independently owned
component before integration. Review expiry against programming, slow uploads,
long-lived streams, restart and delayed cleanup from a previous owner.

Validation completed with the designated kit and matching host service. Hardware
checks exposed a Stop timeout/reconciliation lease-release bug; a full-service
regression reproduced it and passed after capturing ownership before dispatch.
Independent review also caught old-renewer and delayed-input-attach races; both
were fixed with failing-before/passing-after regressions. The target clock is
1970, so clients use `expires_in_ms` and local monotonic deadlines.

Target image/runtime/FPGA snapshots stayed fixed while host-only fixes were
rebuilt and retested. The normal host executable was replaced with the final
binary and its previous executable preserved. No commits, pushes or pin changes.
