# FES ZX81 Implementation Plan

> **For agentic workers:** implement task-by-task from this plan. Steps use
> checkbox (`- [ ]`) syntax. Do not skip the Quartus kit gate before Mistral.

**Goal:** Standalone described ZX81 computer with a custom GP ABI, Quartus
bring-up, then a Yosys/nextpnr-mistral package, showing BASIC, keyboard, `.p`
load, Stop and relaunch.

**Architecture:** Reuse format-2 packages, `fes-gp-v1` programming and the
existing GP transport. Add ABI `fes.simple-computer` 1.0. Extract the ZX81
machine from MiSTer Quartus RTL into an FES board shell. Quartus proves the
ABI and machine; Mistral is a second recipe of the same contract.

**Tech Stack:** Go, Python 3.11+, C++14, Verilog/SystemVerilog, VHDL (Quartus
lane only), Verilator, Quartus Prime Lite 17.0.2, Yosys/nextpnr-mistral,
Cyclone V HPS GP and ADV7513.

**Spec:** [FES ZX81 design](../specs/2026-09-10-fes-zx81-design.md). Read it
before this plan; opcodes, pin, clocks and first-slice exclusions are
normative.

## Global constraints

- Work in `out/dev/zx81/`. Keep root `sources/` clean. Do not move parent
  gitlinks from a component worker.
- Parent branch `feat/zx81` is based on FES `origin/main` `de2b917d7b5bff2809f2cd0b868f7ad9445a55a3`.
- Bare `.rbf` stays MiSTer. Invalid packages never fall back to raw loading.
- Do not extend `fes.simple-game`. New ABI tag 2, new media/keyboard opcodes.
- Reuse `FesGp::Exchange` / identity deadlines; dispatch on ABI id.
- No `sys/`, `hps_io`, SDRAM or OSD.
- Quartus kit evidence is required before Mistral PnR of the computer.
- Commits/pushes/PRs need user authorization. Uncommitted diffs are the
  default handoff.
- Simulation and image builds are not hardware acceptance.
