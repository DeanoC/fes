# Coleco MegaCart with two download-time ROM inputs

**Status:** Approved design, 2026-09-25
**Base:** FES `d7545210de07f0c46c64931d1d3d05c38110fe1f`
**Scope:** A separately selected Coleco development package; no factory-image replacement in this change.

## Intended result

A Coleco title selects an exact 8 KiB BIOS and an exact 128 KiB MegaCart image as two independent, private library assets. The host sends their source bytes, not a patched FPGA image. On the target, the existing non-Python linker optionally composes an SGM module built for the exact shell, patches both ROMs into the resulting blank RBF, and hands the final RBF to the runtime for one normal FPGA download. The package, both source digests, optional expansion digest, map digest and programmed-RBF digest remain visible through activation, status and restart adoption. A missing or incompatible input fails before programming.

The first gameplay claim is **MegaCart mapping with a synthetic test cartridge**, not compatibility with Opcode Time Pilot. [Opcode lists Time Pilot as a 1 Mbit SGM title](https://opcodegames.com/shop/colecovision/arcade-series/time-pilot/), but does not specify its cartridge mapper. The real image's layout and banking must be established privately before testing or claiming that title.

## Existing boundary

The factory `fes.coleco` format-2 package loads an optional firmware blob and a 1–32 KiB cartridge through application mailboxes. Its cartridge store is 32 KiB and has no banking. The linked v2 SGM expansion supplies RAM and AY sound, not cartridge mapping. Format 3 has one named ROM requirement and one source identity. The host explicitly rejects a format-3 cartridge package that also declares the reset-held firmware mailbox. Its existing source-only ROM transport and Go linker already bound ROM maps, expansion composition and final RBF bytes, but cannot represent two distinct required ROM assets or their identities.

Do not reinterpret format 2 or 3, combine the BIOS and cartridge into an opaque library asset, raise the old stream limit, or treat the host's 32 MiB import limit as FPGA capacity. The new development package omits `fes.media.blob`, `fes.media.blob-stream` and `fes.firmware.blob`; it starts with both ROMs already linked. The current factory package and its retail baseline remain valid only for their named artifacts.

## Chosen package and source contract

Introduce **core-package format 4** with the existing base `core.rbf`, one sealed `rom-map.json`, and two required named ROM inputs. Its manifest has an ordered `[[roms]]` array with exactly one `firmware` and one `cartridge` role. Each entry contains a unique ID, role, exact `source_size` and `source_offset` in a logical concatenation. Offsets begin at zero, are nonoverlapping and cover the combined input contiguously. A `[rom_map]` table records the one map file's length and SHA-256. The format-4 package identity uses a distinct `FES-CORE-PACKAGE-4\n` domain over exact manifest, base RBF and map bytes. Existing package domains and archive bytes remain unchanged.

For this producer, `core.id` remains `fes.coleco` with a new version and a separate development recipe. The input order is BIOS at offset 0, size 8,192, then cartridge at offset 8,192, size 131,072. The combined 139,264 bytes fit the existing ROM-map format-1 and linker's 256 KiB source bound. The map still covers every 1 KiB source block exactly once, references the original blank RBF digest, and contains globally unique CRAM destinations. The producer verifies every named routed M10K BEL, blank INIT bit, selected Mistral database geometry and exclusion from the v2 expansion socket. It extends the current single-column extractor to the actual multiple columns selected by the route; it does not invent CRAM coordinates from a presumed placement. The package schema, Python producer, Go inspector/linker and C++ runtime inspector must agree on exact keys, members, size bounds and identity.

A versioned source-only launch archive carries the sealed package, `bios.bin`, `cartridge.bin` and optional expansion archive in a fixed canonical order. Its receipt binds package ID, map digest, each named input's size and SHA-256, and the selected expansion ID. The target verifies those bindings independently, assembles the logical source buffer in manifest order, composes a selected SGM module after checking it against the new shell, then patches the ROM map once into the blank RBF. The resulting RBF is independently recomputed for restart adoption. The host never supplies a map, placement, or programmed RBF. The current format-3 transport and `rom_link` identity remain unchanged. Format-4 status uses a distinct two-entry `rom_links` identity, plus one final programmed digest, so old one-ROM fields cannot silently stand for both inputs. No new globally advertised capability changes the meaning of `rom_linking: 1`; package inspection and versioned source admission reject an older target before mutation.

The host reuses its household firmware slot for the BIOS and its per-title ROM selection for the cartridge. Admission requires both exact media IDs and sizes, a matching package selection, and an optional expansion archive bound to the same shell. The UI and API show both requirements and their readiness separately. A stale title, changed household BIOS, wrong package, wrong expansion or changed content digest refuses launch before FPGA programming. The target checks the same identities again at staging; the runtime receives only the verified sealed package and target-linked programmed RBF under its existing lease and physical lifecycle. Runtime status retains both ROM identities so the host can verify the selected assets after activation and after restart.

## MegaCart machine behavior

The new shell has an 8 KiB linked BIOS at `0x0000–0x1fff` and 128 KiB linked cartridge storage. It retains the current v2 CPU/SGM socket, VDP, controllers and audio behavior. [MAME's Coleco MegaCart device](https://github.com/mamedev/mame/blob/master/src/devices/bus/coleco/cartridge/megacart.cpp) is the mapping reference: the final 16 KiB ROM bank is fixed at `0x8000–0xbfff`; `0xc000–0xffff` reads the selected 16 KiB bank; reset selects bank zero. A read at `0xffc0–0xffff` selects the bank from the low address bits and returns the byte from that newly selected bank on the **same read**. For an exact 128 KiB image there are eight banks, selected by three low bits. Writes do not select a bank. The registered-memory implementation must prove that the selected bank and data settle in the CPU's read sampling window, including held and back-to-back reads.

The selected SGM module remains an independent expansion and may overlay its established RAM windows. It cannot claim cartridge reads. The enlarged ROM shell changes the shell RBF and package ID, so the existing sealed SGM archive cannot be reused: a new archive must be independently routed, sealed and checked against the new shell and reserved v2 rectangle. Empty-socket behavior remains a valid diagnostic. The synthetic 8 KiB BIOS used in tests contains only an original startup jump; it is not a shipped Coleco BIOS or a substitute for a required private BIOS in a retail title.

## Failure and ownership boundaries

**mister-packages** owns the closed format-4 manifest/archive schema and conformance fixtures. **misteross** owns ROM-lane RTL, MegaCart selection, map extraction, sealed package and matching SGM archive builds. Its Go linker owns both-source patching and composition. **FogCast** owns household BIOS and title cartridge selections, UI/API readiness, source-only transfer, target validation, status identity and restart adoption. **libmister-runtime** owns format-4 inspection, linked-RBF admission and physical lifecycle; it does not select library assets or patch ROM bytes. **FES** records compatible-source and exact-artifact evidence. The existing recipe registry permits one row per `core.id`, so the new `fes.coleco` producer is built and imported explicitly for development; the factory recipe row stays unchanged until promotion is separately reviewed.

Malformed or missing inputs, swapped roles, wrong lengths, duplicate/overlapping ROM map bits, altered blank INIT, changed package/expansion bytes, socket overlap and mismatched linked output fail closed before programming. An interrupted stage leaves no playable partial image. Once programming begins, Stop and recovery follow the existing runtime/kit-lease path; no new lifecycle coordinator or retry mechanism is added. The old format-2 Coleco path and format-3 ZX81/SMS/SG-1000 paths retain their existing semantics and tests.

## Verification and promotion gates

1. **Contracts and linker:** format-4 positive/negative fixtures in Python, Go and C++; canonical archive and identity round trips; separate BIOS/cartridge digest checks; exact 139,264-byte map coverage; blank-bit and socket exclusion checks; and byte-for-byte agreement between independent Python build-time and Go target-side linked RBFs, with and without the SGM module. Exercise restart reconstruction and status with both source digests.
2. **Machine:** synthetic BIOS and eight visually distinct 16 KiB banks; reset bank zero; fixed last bank; every `0xffc0–0xffff` selection; same-read result; boundary, held and back-to-back reads; writes that do not switch; unchanged BIOS/console RAM/VDP/controller behavior; vacant and populated SGM socket; Stop and relaunch reset. No proprietary bytes enter fixtures or Git.
3. **Physical build:** authenticated Coleco toolchain, sealed package and independently sealed SGM module; all final timing gates at or above 52.224 MHz system, 74.25 MHz pixel and 12.288 MHz audio; map destinations outside the reserved socket; vacant socket before composition; and composed CRAM changes confined to the v2 socket policy. Use Quartus as a timing oracle if nextpnr misses, then record a focused router issue rather than treating the oracle RBF as a product fallback.
4. **Kit diagnostic:** only after a sealed exact artifact and designated lease are available, run a synthetic two-ROM title with and without SGM, capture its visible bank-selection result, exact package/map/source/module/programmed identities, Stop, relaunch and free lease. This is diagnostic evidence for that artifact, not retail-game acceptance.
5. **Factory promotion:** separately review a stable source/package/image selection and run the appropriate parent integration and exact-image acceptance. A private retail game test requires the legitimately held image, its mapper confirmation and private BIOS; Time Pilot remains unqualified until those checks pass.
