# ZX81 Zon X full AY build qualification

The `fes.zx81` 1.4.0 shell and three-channel Zon X AY8912 cart pass
independent behavioral simulation, actual CPU diagnostic firmware, and
authenticated frozen-shell HIP routing. Both AY and RAM carts change zero
configuration bits outside the existing socket rectangle. These are host
qualification results; full-cart hardware diagnostics remain pending.

## Timing and containment

The shell and AY cart both achieve 55.5216 MHz system, 128.1394 MHz pixel,
and 210.7482 MHz audio against requirements 52.224, 74.25 and 12.288 MHz.
The cart uses GPU 0 and seed 2 against the exact sealed routed shell.
Its header matches the shell; 24,602 CRAM bits change inside the slot and
zero outside. The RAM regression cart also passes all three timing gates,
header preservation and complete-CRAM containment.

[build-result.json](zx81-zonx-2026-10-01/build-result.json) retains both
cart manifests, complete input/tool identities, clock results, linked hashes
and containment counts. Full compiler output remains under this task's
`sources/misteross/build/fes-zx81-oss/`, `build/zx81-zonx-cart/` and
`build/zx81-bus-validation-cart/` directories.

## Behavioral checks

The independent reference derives the nominal 3 dB volume progression
arithmetically and checks all three 12-bit tone channels, mixer combinations,
noise vectors, all sixteen envelope shapes, zero periods, high periods,
masks, invalid address selection and R13 restart behavior. The actual CPU
executes the generated open firmware through the machine, socket and cart;
its mute, isolated tones, mixed tones, noise, envelopes, reset and restart
phases pass. Clock tests establish exact average 6.5 MHz ULA and 3.25 MHz CPU
rates, edge polarity and bounded transport-cycle quantization. The physical
card's falling-edge divide-by-two supplies the 1.625 MHz AY enable.

All 49 focused Python producer/AY/CPU-firmware tests pass. The standard ZX81
and expansion simulations pass, including vacant and RAM-expanded BASIC,
keyboard, tape and 720p output. The corrected bus test selects R13 at CF
and verifies a stretched write restarts only once; DF is rejected by the
original A4 decode. Go expansion tests, FogCast composition/status tests,
native runtime composition tests and parent consistency checks pass.
Python and Go independently compose the actual AY archive to identical linked
bytes. Exact format-3/v2 shell bytes also pass Go composition staging, restart
adoption and cleanup with the sealed ROM map.

Independent RTL review approved the clock/reset, decode and AY implementation
after the DAC and falling-edge fixes. Analog mixing, the board's output
filter and unmeasured physical power-on phase are not qualified by digital
simulation; the [bus guide](../zx81-expansion-bus.md) records these limits.

## Hardware gate

No full-AY hardware acceptance is claimed. Kit 1's appliance update finished
during preparation, and its normal host became active. Exclusive operator
use must be established before replacing services or claiming a diagnostic
session. The prepared static runtime requires Linux 5.10 or later; the
designated kit reported 5.15.1-MiSTer.

The next run uses the exact frozen package/cart/open ROM, a private library
host, the existing renewable kit lease and temporary runtime/agent overlays.
It must record current image/boot, package/BUILD_ID, expansion, composition
and programmed ROM-link identities; capture A/B/C, mixer, noise, envelope
and mute phases; verify Hold, Stop and relaunch; then restore original
services and release ownership. Factory-image integration is a separate gate.
