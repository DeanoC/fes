# PC/386 diagnostic segment-prefixed CMP experiment, 2026-11-16

This is an unfinished, default-off 86Box-calibrated reference diagnostic. It does not fix #1902, establish physical 286 timing, qualify an artifact, or close speaker-pitch or tier-1 gates. It extends the preceding unprefixed 38/39 experiment to ordinary-RAM memory operands with 286 segment overrides, retaining execution budget 5 and independent refill budget 7. Newly admitted prefixed forms require `!CR0.PE` and exclude base+index+displacement (EA3). The prefix-history guard rejects any non-286 prefix, including an earlier FS/GS or size prefix overwritten by a later segment override. The prior unprefixed diagnostic behavior remains unchanged. `!CR0.PE` does not distinguish unreal-mode cached segment state, which is unmeasured. Excluded forms retain the prior diagnostic path, which itself is not a production timing or device-conformance claim.

## Prospective reference

The separately frozen 14-case `inputs/` fixture uses byte-identical timed guest loops and checks flags, registers, counter, both RAM words, canary, stack and segments. It covers 38/39 byte/word, CS/SS, repeated and overwritten 286 segment overrides, direct/indirect/indexed/displaced addresses and unequal values. Its scaffold differs from the preceding DS/ES survey; EA3 is excluded. The normal and intentionally failed programs temporarily use a private stack with SS=CS; both check restoration of original SS:SP and IF on their respective paths. All 14 FES controls passed with initial IF clear; on DOS the normal and deliberately failed paths returned `EVENT_CONTROL_VERIFIED` and `EVENT_CONTROL_FAILED` respectively, with the failure marker emitted only after the restoration check. This is a control of the fixture, not a device or interrupt-delivery conformance test.

The three reference outputs `reference/PF1.TXT` through `PF3.TXT` are byte-identical, SHA-256 `10bad386136841fd58cae99de468578bacf672330ec3f2aebe9767b713fcf746`. An isolated 86Box v6.0 Award 286 reference ran at 12.5 MHz with wait-state setting 1 and 1 MiB RAM. The full private recording yielded 980/980 samples matching the visually verified 100% indicator at 4 fps; it says nothing about speed between samples. The frozen reference manifest records emulator/ROM identity, settings and guest inputs without distributing ROM or disk contents.

The old diagnostic was approximately 2 clocks high on the affected whole loops. The frozen v3 candidate agrees with the 14 reference estimates within **0.018 clocks per loop**; the exact largest absolute delta is 0.017893515888090405 (`predictions/comparison.json`). Counts are 1,000-iteration blocks over 64 BIOS ticks, converted using `64 * 65536 * 12500000 / (1193182 * count * 1000)`. Tick quantization, ISR and block setup, and different DOS and RTL marker overhead add uncertainty. Three identical outputs in one boot are not independent boots or broad workload qualification. The original DS/ES prefixed cases were also measured in the preceding milestone; this holdout varies prefix, addressing and scaffold. A separate synthetic handler/frame whole-loop prediction improves by another two clocks versus the preceding candidate, but about 2.1 clocks remain on its P0 case; no general exception/interrupt entry correction is claimed.

## Validation and limits

The exact base is commit `d5f8c94a8dc0b68574efd74558955f86d72e4f0e`. The source manifest identifies the RTL SHA-256 `9ddc2319d5e3d72b33d966edbc9c2512005af49fe63087bca716862cc52323e8` and testbench. The exact-base combined CPU is SHA-256 `ab6aa42a61d5c4cd331b73432ac62b3f6d1834452928a81ef1ad7f4552facd97`; all 33 compiled CPU input hashes and this binary match the v3 candidate whose 14-case predictions were frozen before the reference outputs were opened. Its `GOV_N=5`, `GOV_D=3072`, `GOV_REFERENCE_DIAGNOSTIC=1` parameters, locked Verilator and linked objects are recorded in `binary-manifest.json`.

The focused governor bench passed, as did all 15 governor/inventory/reference Python tests. A 262,144-cycle randomized module differential against the exact base governor passed across presets and turbo with the candidate disabled. This is sampled module behavior, not formal, netlist, synthesis or hardware equivalence. `cpu-fallback/` preserves a separate real-mode predecessor-versus-v3 CPU comparison: 10 byte/word excluded forms (FS→DS, GS→DS, 66/67 and prefixed EA3) have identical marker-to-marker charged totals, supported DS-only controls differ by two clocks per loop, and unprefixed controls agree. Both executions passed flags, register, RAM, counter, stack and segment checks. Queue state was not directly observed. The synthetic bench additionally checks fallback metadata and both orders of mixed RAM/non-RAM accesses; it does not establish physical MMIO conformance. A separate identically instrumented whole-CPU predecessor/v3 control in `cpu-extra/` passed real-mode word reads crossing 9FFFFh→A0000h, protected default-32 code with 66h+67h and effective 16-bit sizes, and protected default-16 code with a DS override. Both runs have identical per-loop charges, cycles and final architectural state; telemetry reports 150 reads in the 9FFF0h–9FFFFh RAM region, 100 emulated A0000h MMIO reads and zero MMIO writes. This tests a specific simulated read crossing and two protected contexts, not real device behavior or all boundaries. Other mode transitions, unreal mode, RAM-to-hole crossings, abandoned/replayed instructions and long prefixes crossing fetch halves remain unqualified.

Independent full review of v2 found unmeasured protected-mode and prefixed-EA3 scope; v3 narrowed both without changing the committed unprefixed path. Fix-only review found that the unsafe-prefix fallback bench also set real-mode false, so it could pass without testing the unsafe bit. The only subsequent test fix sets real-mode true for that check; RTL did not change, the earlier log is retained, and the corrected bench passes. The 386 prefix history, address-space boundaries and replay limitations above remain explicit.
