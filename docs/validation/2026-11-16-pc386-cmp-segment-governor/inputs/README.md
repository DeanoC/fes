# Prospective CS/SS segment-prefix CMP holdout

This is a separate prospective held-out fixture, not an accuracy claim. Fourteen byte-matched loops cover 38/39 with CS or SS segment overrides, repeated CS/SS, overwritten CS→SS and SS→CS, byte/word widths, indirect/indexed/displaced/direct addressing, and unequal operand controls. Its scaffold (`PUSHF/POP DI; CMP [800c],0; LOOP`) differs from the first survey. `instruction-identity.json` binds the exact instruction and loop bytes and offsets in each guest.

The guest temporarily makes SS=CS with a private 0x7000 stack to ensure CS- and SS-relative addresses denote the same RAM on DOS and FES. It first saves original SS:SP and FLAGS, masks interrupts while changing SS:SP, then restores the original FLAGS (including IF) on the temporary stack. It checks effective SS, arithmetic flags, registers, both operand words, canary, relocated SP, segment registers and counter. On both the successful and deliberately failed comparison paths it restores and checks the original SS:SP and original IF; `RESTORE_CONTROL_FAILED` (DOS) or port 8e value fe (FES) is a distinct restoration error. `FAILCASE.COM` and `rtl-failure.bin` force the first case into the failure path; expected `EVENT_CONTROL_FAILED` or port 8e ff indicates that the failure path ran after the restoration check. Run these controls separately on both CPUs. Neither success nor failure restoration behavior has been executed or validated yet.

Complete loop timings include flag capture, memory CMP scaffold, LOOP, and block overhead. Reference outputs are block estimates with BIOS tick quantization, ISR and setup uncertainty; they do not isolate CMP or establish physical hardware timings. Reference commands are frozen but no VM or disk is created here. Any future execution requires a privately sourced/guarded disk, readback and clean result names, qualified host, complete 4 fps speed trace, no sub-100% or unreadable sample, and frozen source/binary identities. No model change or candidate is claimed.
