# i486 slice 1: fit spike method, 18 November 2026

This file is committed before any fit or lockstep run in this record has a
result. Bands and the meaning of each outcome are fixed here and are not
changed after a result is seen. Results go in `summary.md`, generated by
script from the committed reports. Tracker:
[#1962](https://github.com/DeanoC/fes/issues/1962); plan:
[`2026-11-17-i486-plan`](../2026-11-17-i486-plan/summary.md).

## The question

What the 486SX delta costs in ALMs and timing inside `pc386_system` on the
DE10-Nano and the DE25-Nano, and whether a runtime 386/486 strap costs
materially more than a build parameter. Deano's decisions on #1962 (18
November 2026) fix the target: a later-stepping 486 with CPUID and EFLAGS.ID,
without VME, so no CR4. The identity is a build parameter first; this spike
supplies the numbers for deciding whether a strap is worth having.

## The plan's slice 1, and where this departs from it

The plan defines slice 1 as "the SX delta's logic shape behind one input, as
Quartus 17.0.2 analysis fits inside pc386 with the area audit's per-module
method", needing "no working instruction semantics, only the logic's shape,
and no lockstep", and gated on "measured ALMs and slack for the SX delta
inside pc386 on the DE10 flow". This spike departs from it in these ways,
all set by the slice brief:

1. **Both boards,** the DE10 (Cyclone V, Quartus 17.0.2) and the DE25
   (Agilex 5, Quartus Pro 26.3), not the DE10 alone.
2. **Three arms,** not one input tied on: the baseline, the 486 as a build
   parameter, and both identities in one bitstream behind a runtime strap.
3. **At least four seeds an arm, the same seeds across arms,** not one.
4. **Working semantics,** checked by the slice 0 directed cases in level-4
   lockstep, not logic shape alone. The RTL is still a spike: it is not
   validated beyond the count of cases that agree, and it does not merge.
5. **CPUID and EFLAGS.ID are in the delta** (the plan's option B, as Deano
   chose).
6. **The DE10 fits use the sealer's own project** (the board shell, pins,
   SDC and settings `build_fes_pc386_quartus.py` writes), not an analysis
   envelope. They are still not seals: no package, no record, no kit.

## What is fitted

### Base and branches

- **Base:** main at `1ec59267039b12b5879dd90af856ac232b9d014c`.
- **Spike RTL:** the branch `deano/i486-s1-spike-rtl`, pushed and not for
  merging, cut from the base. Its RTL commits change only files under
  `sources/misteross/cores/fes-common/rtl/i386/` and
  `sources/misteross/cores/fes-pc386/rtl/pc386_system.sv`. The generator
  checks that `git diff` from the base to each arm's commit touches only
  those paths, and records each arm's commit.
- **Lockstep:** a separate throwaway branch that merges the spike RTL with
  slice 0 (PR #1976, or main once it merges) and adds the lockstep
  testbench's identity wiring. Slice 0 changes `bochs_oracle.cpp`, a sealed
  pc386 input, so it is kept out of every fitted tree. Nothing on that
  branch merges, and `i486-expected-stops.txt` is not edited on anything
  that merges.

### The three arms

| Arm | Tree | The 486 identity |
| --- | --- | --- |
| **a** baseline | the base, unchanged | absent |
| **b** build parameter | the spike RTL, `pc386_system` ties the CPU's identity input to 1 | 486SX, constant: Quartus may remove the 386-only paths |
| **c** runtime strap | the spike RTL, the identity input driven by a strap | both: chosen at each CPU reset |

The CPU gets one identity input. In arm b it is the constant `1'b1`. In arm
c it is bit 1 of the `fes.pc386.machine` record's word 2 (`settings[33]`,
beside the `queue16` code-profile strap at `settings[32]`), latched by the
CPU at reset as `queue16` is. `fes_computer_storage` holds all 128 settings
bits in registers loaded from the mailbox, so the fitter cannot fold the
strap to a constant. That this held is checked after the first arm c fit:
the latched identity register and the 486-only registers (CR0's new bits,
EFLAGS.AC and ID, TR3) must appear in the fit, not among the removed
registers. If they do not, arm c is not a two-identity fit and its results
are withdrawn, not reported as the strap's cost. The record word, ABI and
FogCast changes a real strap would need are out of scope: the spike only
needs the bit to be live.

### The delta the spike RTL builds

Each item as costed, with the shape chosen:

- **BSWAP** (0F C8–CF): decode and an EX byte permute.
- **XADD** (0F C0, C1) and **CMPXCHG** (0F B0, B1): register and memory
  forms, with LOCK, in the CPU's existing uop or microcode machinery. Real
  execution, not a stub.
- **INVD, WBINVD** (0F 08, 09): CPL 0 only (#GP(0) elsewhere, as the
  privileged instructions are); executed as the existing FLUSH path's
  request or as a no-op, whichever the RTL already offers, and named in the
  record. Either is invisible on this machine's coherent caches.
- **INVLPG** (0F 01 /7): CPL 0 only; a full TLB flush, which the
  architecture permits, unless a single-entry invalidate falls out of the
  existing tag compare at no extra structure. The record names which.
- **CPUID** (0F A2): leaves 0 and 1 as constants (vendor string; family 4,
  a 486SX's model; no feature flags beyond what a 486SX has); EFLAGS.ID
  writable.
- **CR0:** NE, WP, AM, NW and CD stored, read back and written with a 486's
  mask; ET reading 1; the #GP for NW set with CD clear.
- **WP enforced** in both places the RTL checks page rights: the DTLB's
  rights check and the page walker's fault condition. Not stubbed.
- **EFLAGS.AC** (bit 18) and **ID** (bit 21): the flags register and every
  pipeline copy widened as the RTL needs, POPF/POPFD/IRET/task switch
  writing them.
- **#AC** (vector 17, error code 0): an alignment compare on each data
  access at CPL 3 with CR0.AM and EFLAGS.AC set, as a real fault. Not
  stubbed.
- **TR3** as storage beside TR4–TR7.
- **Reset values** with the identity on: CR0 60000010h, EDX 0000042xh (a
  486SX signature), DR6 FFFF0FF0h.
- **The identity gating:** each item above active only with the identity
  on; with it off the CPU is the base's 386.

Not built: CR4, VME, RSM and SMM (out by decision); the 486DX shell; the
cache and TLB test functions of TR3–TR7; governor cost rows; the BIOS's CD
and NW clear. Where the spike takes a shortcut that a real slice 2 would
not, the record lists it.

### The fits

| | DE10 | DE25 |
| --- | --- | --- |
| Device | 5CSEBA6U23I7, 41,910 ALMs | A5EB013BB23BE4SCS, 46,800 ALMs |
| Quartus | 17.0.2 (`cores/fes-pc386/quartus.lock`) | Pro 26.3.0 (`boards/de25nano/quartus.lock`) |
| Flow | the pc386 sealer's project and settings (`build_fes_pc386_quartus.py` `write_project`), `BUILD_ID` all zeros in every arm, real board shell | `scripts/fit_i386_device.py --design machine --device de25`, the virtual-pin envelope the Agilex fit record and the DE25 x87 envelope used, at the sealed 61.44 MHz period |
| Host | Powerboat, under the Quartus Lite builder lock | chip-30x0-ai-dev, under its builder lock |
| Seeds | 1, 2, 3, 4 in every arm | 1, 2, 3, 4 in every arm |
| Per-module split | one extra fit per arm, seed 1, with Yosys's `flatten` dropped (the area audit's method) | not run: the envelope harness flattens, and its port handling is defined for the flattened netlist only |

**One netlist per arm.** The machine netlist's bytes depend on every path
Yosys is given (DeanoC/yosys#80), so each arm is elaborated once, on
Powerboat with the pc386 lock's HIP Yosys slot, by
`fit_i386_device.machine_netlist`'s fixed-path elaboration (which is the
sealer's `machine_program`), and that one file is fitted at every seed on
both boards. The record carries each arm's netlist SHA-256 and every fit
checks it. The DE25 side applies the harness's two recorded attribute
rewrites; the DE10 side reads the netlist unchanged. The flatten-dropped
netlists are elaborated the same way, separately.

**Order:** arm a's fits start first on both boards, while the spike RTL is
written.

## What is reported

Per fit: ALMs needed, registers, ALUTs, M10K or M20K blocks, MLAB bits, DSP
blocks, and each clock's worst setup and hold slack at every corner
TimeQuest analyses. For the DE10, slack against the sealed 61.44 MHz clock,
and whether the fit closes: every setup, hold, recovery and removal slack
at every corner non-negative, the sealer's own rule. For the DE25, the same
slacks and each clock's Fmax at every corner, with both clock domains shown
analysed at every corner.

Per arm and board: the median ALMs needed over the seeds and the spread
(maximum minus minimum); the number of seeds that close. Seed-independent
measures from synthesis (Quartus Analysis & Synthesis on the DE10; Pro's
synthesis on the DE25): registers and ALUTs or the synthesis ALM estimate,
which do not move with the seed.

## Bands, and what each outcome means

All ALM figures are ALMs needed, medians over the same seeds.

### The SX delta: arm b minus arm a

Tested against the plan's estimate, 350 to 850 ALMs, which includes the
identity gating. The plan states the estimate for the DE10; the DE25's ALMs
are a different unit, so the DE25 delta is reported beside it and not held
to the band.

**Uncertainty of a delta between arms.** Two terms, and the larger is used:

- the seed spread: the larger of the two arms' spreads;
- the netlist floor: in the per-module fits, the change in the ALMs of the
  logic the spike does not touch (everything outside `fes_i386_cpu`) between
  arms. A different netlist moves untouched logic by up to about ±200 ALMs
  (the [area audit](../2026-11-08-i386-area-audit/summary.md)); this measures
  it for these netlists.

A delta smaller than its uncertainty is **not resolved**: it is reported as
"under N ALMs", where N is the uncertainty, and is not placed in a band
below that bound.

| DE10 outcome | Meaning for slice 2 |
| --- | --- |
| Delta below 350 | Under the estimate. Slice 2 is cheaper than planned |
| 350 to 850 | The estimate holds |
| Above 850 | Over the estimate. The record lists where, by module, and slice 2's budget is re-stated from the measurement |

### The 486SX machine against the DE10's ceiling

The working ceiling is 38,500 ALMs (92% of 41,910; the area audit's line,
stated as 38,557 in later records). The x87 slices' pc386 seals sat at 86.6
to 87.05% and Quartus has closed this machine up to about 88%.

| Arm b median | Meaning |
| --- | --- |
| At or under 36,880 (88%) | Inside the range the machine has closed at before |
| 36,881 to 38,500 | Under the working ceiling, past what has been closed before: the timing column decides |
| Above 38,500 | Over the working ceiling: a DE10 486SX does not fit as built. Slice 2 on the DE10 needs area found elsewhere first. This is reported; nothing is trimmed to fit |

For the DE25, the line is 92% of 46,800, 43,056 ALMs, and the same three
readings apply with 88% at 41,184.

### Timing on the DE10

Closing seeds are counted per arm on the same four seeds.

| Outcome | Meaning |
| --- | --- |
| Arm b closes on as many seeds as arm a, or one fewer | No timing cost the spike can resolve. The DE10's binding region moves by seed (placement, not depth), so one seed's difference is not a finding |
| Arm b closes on two or more fewer than arm a | The delta costs DE10 timing. The record names where arm b's failing paths are (the WP and #AC fault terms are the expected place); slice 2 must carry a timing fix. This is a finding, not something to tune here |
| Arm a closes on fewer than three of four | The base itself is marginal at these seeds; the comparison is reported but no timing cost is attributed to the delta |

No constraint, clock or setting is changed to make any arm close. A failing
seed is reported as failing.

### The strap: arm c minus arm b

The plan estimates the gating at 30 to 80 ALMs, likely under the
uncertainty above, so a non-resolution is an expected outcome and is stated
as such. The precommitted readings:

| Outcome | Meaning for the recommendation |
| --- | --- |
| Not resolved, and arm c closes on at least as many DE10 seeds as arm b, or one fewer | The strap costs no measurable area or timing over the build parameter: "under N ALMs", N stated |
| Resolved and at most 150 ALMs, the same timing reading | The strap costs a small, measured amount |
| Above 150 ALMs, or arm c closes on two or more fewer DE10 seeds than arm b | The strap has a material cost, stated in ALMs and seeds |

The recommendation in `summary.md` puts the measurement beside it. Deano
decides; the record does not.

### Seed extension

If, on either board, the SX delta or the strap delta is within one
uncertainty of a band edge, or a timing reading turns on one seed, all three
arms on that board get seeds 5 to 8, once. Never one arm alone; never a
second extension. Whether an extension ran, and why, goes in the record.

## The lockstep check

On the lockstep branch, `scripts/test_fes_i486_lockstep.py` runs the 48
directed cases (`scripts/fes_i486_cases.py`) against the level-4 oracle:

- **identity on:** the count that agree, against the 6 of 48 that agree on
  the 386 today (`i486-expected-stops.txt` at slice 0's head), with every
  remaining stop listed and explained;
- **identity off:** the stops must equal slice 0's committed list exactly,
  which shows the strapped RTL is still the 386 with the strap off.

Three cases cannot agree, by design, and are reported as such: the two
`mov-cr4` cases (the oracle's model has CR4; the target has none, by
decision) and `cpuid-1` (the oracle is Bochs's i486DX4, signature 0480h
with the FPU flag set; the spike returns a 486SX's, with no FPU flag).
Nothing is built to turn them green. The count of agreements is all that is
claimed: no random programs, no level-3 lockstep, no test386 or netlist
lockstep, no census, no seal and no kit. A level-3 lockstep and test386 run
with the identity off are run if time allows and reported as run or not run.

## What is committed

The record directory holds: this file; `summary.md`, generated by
