# D12 for the DE25 Spectrum 48, Spectrum 128 and ST packages

By the method in [method.md](method.md#the-other-de25-cores-agents-md-d12), run
by [d12-slat.sh](d12-slat.sh) on 23 Nov 2026 with base `dfacd28e1` (#2036's
head, which includes #2097) and arm `e4129d9aa` (this branch merged with
`dfacd28e1`). One Quartus Prime Pro 26.3 install, every job under a Pro slot of
the Quartus lease.

**ST:** B's gates pass.

**Spectrum 48 and 128: not measurable at this base.** The gate is not
recorded as a pass. Both packages fail one rule, TMC-20026 (empty collection due
to an unmatched filter). The filter is
`get_registers "${base}|transport|fetch_request"` at `machine-clocks.sdc:44`, the
native-variant probe from `spectrum-clocks.sdc`. The base fails the same way:
A's signoff DRC report at `dfacd28e1` has the identical TMC-20026 row (Medium,
1 violation) on the same filter for both Spectrum models, and neither the base
nor main reviews TMC-20026. The cause is #2162, which predates S-lat. ST's A
report has TMC-20026 at 0 violations.

No review rule is added and the SDC is not touched here. The precommitted
"B's gates pass" rule still stands for Spectrum. When #2162's fix is on main
and #2036 has merged main, the Spectrum producers rerun on this arm and the
base, and that result is recorded against the same rule. Until then S-lat is
not gate-ready for Spectrum.
