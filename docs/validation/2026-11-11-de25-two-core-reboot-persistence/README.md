# Two installed cores survive independent native reboot

TRWU8CBL passed a separate recovery/native cold initialization after the successful two-core install trial. Recovery freshly verified the fourteen existing staged files plus all three installed records, without DHCP/TFTP or SD writes. The record bytes match independently produced hashes for ZX81 trial, the original ZX81 and ZX80 trial. The bootstrap selection/catalog remained empty, so they were not substituted for installed-record discovery.

The same matched native image then cold-booted with a new programming/service lifetime. It discovered all three titles at logical generation zero and both target sources already installed. It issued no Install action. Both installed cores launched with the same package/build/ROM identities as the preceding installation run; ZX81 also consumed its expected 917-byte tape. The first core stopped to the menu; quitting the second completed return and final Park. Saved wire/poll-time replay passed with five configurations, two launches, three menu sessions, logical generation 5, firmware generation 29 and final contained reset mask 15.

An independent read-only audit verifies both private JTAG services absent, archived transport files unchanged, 15 MHz/automatic-adjustment 1 restored, exact USB permissions and free UART. The top board remains parked with the spare card under the continuing claim; the original factory card and bottom kit are untouched, and factory restore remains waived.

The persistence verifier independently joins the prior completed install receipt to the later run: immutable prior evidence hashes, chronological ordering, identical native image bytes, different source/admission and service lifetimes, three exact installed-record readbacks, new secure cold boot, zero Install actions, both matching activations and final cleanup. That conjunction establishes bounded reboot persistence for these two installed targets and preservation of the original title. The per-cycle observer/model flags remain persistence_verified=false because neither cycle alone proves it; the separately verified physical join records persistence_verified=true.

This is cold reinitialization with the card powered, not a power-cut or standalone SD-autoboot qualification. HDMI output and physical keyboard actions were not independently observed in this run. Native Ethernet, wider core/device support, hotplug and full DE10-equivalent appliance/core-loading acceptance remain open. The next integration work should move toward ordinary interactive/autonomous boot and package loading, using this verified installed catalog as the base.
