# ZX81 Zon X channel-A cart diagnostic

On 2026-09-30, kit 1 passed a normal library launch of an independently sealed
Zon X channel-A tone cart against the previously qualified shared-audio ZX81
shell. The open 8 KiB firmware programmed the cart through CPU `OUT (C),A`
on ports `00DF` and `000F`, alternating volume 15/0 approximately every
2.1 seconds. ShadowCast captured the expected approximately 6.375 kHz square
and all-zero mute intervals on both channels. Stop returned to the native
menu and muted the capture after the transition. Relaunch retained the
expansion selection and reproduced the signal with the same composition and
ROM-link identities and a new runtime generation.

This is exact-artifact diagnostic acceptance of the bounded channel-A cart,
not a complete AY/Zon X implementation or software-compatibility claim. It
has an eight-bit period assembled from R1/R0 low nibbles, a /16 divider and
linear volume; channels B/C, noise and envelopes are absent. No speakers were
connected. No factory image, runtime or agent was changed.

## Observations and limits

The [active receipt](zx81-zonx-2026-09-30/active.json) and
[relaunch receipt](zx81-zonx-2026-09-30/relaunch-active.json) show the exact
package/build, expansion, composition, ROM-link identities and PCM interface,
with runtime generations 3 and 4. The [first capture](zx81-zonx-2026-09-30/active.flac)
and [relaunch capture](zx81-zonx-2026-09-30/relaunch.flac) contain the expected
0/30720 samples. During stable tone windows, rising-edge periods measure
approximately 6375 Hz; intervening windows contain only zeros. This follows
the firmware's OUT-controlled volume changes rather than merely showing a
nonzero level. Detailed per-channel quarter-second windows, timing, archive
manifest and containment are in [result.json](zx81-zonx-2026-09-30/result.json).

The firmware does not generate a display file, so the
[active HDMI frame](zx81-zonx-2026-09-30/active.png) is intentionally blank.
The [idle frame](zx81-zonx-2026-09-30/idle.png) shows the native menu. The
[post-Stop capture](zx81-zonx-2026-09-30/idle.flac) has 47/46 nonzero transition
samples, then zero on both channels throughout the last five seconds.
The private host exited successfully, its credential was removed and kit 1's
lease returned free. The normal host service remains stopped and disabled.

The producer has no wider-socket fallback. Both RAM and Zon X archives use
the same timing, header, complete-CRAM containment and exact-shell checks.
The previous Zon X path through the wider diagnostic cart script is removed;
that script still handles the explicitly diagnostic QS cart. The new archive
imports and selects through the existing expansion API without runtime,
FogCast or shared-contract changes.

Validation: all 47 focused ZX81 producer tests pass, the RAM/Zon X/QS bus
simulations pass, and the Go expansion/linker suite passes. These checks and
the tone capture do not qualify private BASIC music programs, host restart
persistence, kit 2 or another independently routed shell/cart pair.
