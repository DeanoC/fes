# pc386 286 reference governor: shifts and instruction costs

This is an **unfinished, default-off diagnostic** for issue #1902. It calibrates a subset of timing against 86Box 6.0 at 12.5 MHz with one wait state, not a physical 286. The registered pc386 package does not enable it. It does not establish the user's Ultima VI speaker-pitch gate, a production fix, fresh timing/seal or exact-artifact hardware acceptance. The GPL-2 reference was inspected for timing facts; its source code was not copied into FES.

The frozen final enabled CPU executable has SHA-256 `a583e34c4ec711e86ed384f1a41386df4125cd919c63d9dc81869b6a2e46565b`; `final-candidate-manifest.json` records RTL/tool/link hashes and explicit `GOV_REFERENCE_DIAGNOSTIC=1`. Its source was reviewed independently with one fix-only pass. These changes add reference budgets for 16-bit MUL/DIV, PUSHA/POPA, LEA and nonzero group-2 shifts. The new rules for memory operations require every committed access to be ordinary RAM, including both lines of a crossing. An accumulator covers all accesses of multi-uop stack instructions; register operands and LEA do not require a memory access. The pre-existing TEST diagnostic is unchanged and its non-RAM behavior is still unvalidated. No claim is made that fallback timing or device behavior conforms to the reference.

For zero-count shifts, the diagnostic tracks the resolved masked EX count, including a WB bypass, and models the reference's skipped execution/fetch update only for registers or wholly RAM operands in default-16 code, with no prefixes other than 286 segment overrides. Immediate-count and segment bytes are deferred until the next modeled prefetch update. Zero-count EA surcharges are suppressed in this path. Prefix history tracks every consumed prefix, so an FS/GS override followed by DS remains unsupported. The queue holds up to 4,095 deferred bytes; on the next overflow it drains those bytes using the prior diagnostic path instead of wrapping the charge. That boundary is an explicit finite surrogate, not proven reference equivalence for unbounded instruction streams. Unsupported 386/LOCK/REP prefix histories, default-32 code, MMIO, ROM, holes and RAM-to-non-RAM crossings keep the previous diagnostic path. REP/fault/interrupt interactions with deferred bytes, arbitrary bus wait states, other instruction families, and sustained application behavior remain unqualified.

`training/` preserves the earlier failed 14-form matrix: memory shifts by CL, MUL/DIV, PUSHA/POPA and complex LEA missed by approximately 2–6 clocks per whole loop. Those failures remain evidence, not retroactive passes. The private prospective 17-form `forms-holdout/` used different encodings and a NOP-modified scaffold; its frozen shift candidate matched 16 cases within 0.033 clocks while zero-count SHL missed by nearly 12. `zero-holdout/` then froze a zero-count candidate before a further 13 cases: its first ten scoped cases matched within 0.029 clocks; the three explicitly excluded immediate/complex/prefixed controls remained failures of about 14–15 clocks. The later `zero-wide-holdout/` fixed the deferred-byte model before measuring 13 new forms, covering complex and odd EA, immediate zeros, multiple segment and immediate prefixes, mixed zero/nonzero shifts, and a following taken JMP. All predictions match within 0.030 clocks per whole loop. All three files in each group agree and the guest controls pass. Counts estimate whole-loop clocks and include timer/ISR and block setup; the RTL marker harness differs, so one-block quantization is not a complete error bound. Reference results for the first three groups were repeated in one boot with only point-in-time speed checks; the last has a continuous 4 fps indicator capture over all three runs. The retained compressed speed strips contain all 1,080 samples; they are pixel-identical to the OCR- and visually checked 100% indicator. The full raw window video is retained locally, not included here.

Candidate source patches under `source-patches/` reconstruct the historical prediction candidates from the byte-exact compressed base sources and hashes in that directory, originally taken from commit `22fdddd3704768946df40b6ff7333e9225486106`. The reconstruction does not require that branch-only commit to remain in Git history. Their manifests identify independently frozen binaries; comparisons made after observing the reference are labeled `final.json` and cannot be treated as prospective predictions. The final candidate replays the same three fixture programs within 0.034 clocks per whole loop. `memory-gate/` and `zero-mmio/` retain real CPU simulation of pure RAM, pure MMIO, RAM/MMIO crossing and mixed stack: only the measured RAM paths change; non-RAM paths retain the prior diagnostic charge. FES already performs a same-value write for a zero-count MMIO RMW where the reference does not; these controls do not fix or waive that architectural difference. The guest zero controls establish unchanged CF/ZF and RAM content, not the absence of a same-value write.

`reference_governor_tb.sv` adds directed queue, deferred-prefix, maximum-bound fallback, zero/nonzero and MMIO controls, adjacent-boundary reset, and mixed PUSHA/POPA access accumulation. The locked-Verilator frontend report is tied to the same package and qalign source bytes as the final candidate; its exercised frontend interfaces do not by themselves prove the new prefix metadata. `default-off/` records exact enabled-independent baseline and final CPU binary manifests and sampled max, 286, 386 and turbo comparisons. Passing simulations and sampled output equality are not formal, synthesized-netlist or physical equivalence proofs. Full logs, private ROMs/disks and the complete 4 fps recording remain in ignored local `out/dev/1902-*` paths.
