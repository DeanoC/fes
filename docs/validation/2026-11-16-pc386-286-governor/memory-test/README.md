# 286 TEST split-budget diagnostic, 16 November 2026

This is a default-off 86Box-reference experiment, not a physical-286 model or a production calibration. It separates the execution clocks charged for ordinary 16-bit memory TEST from the clocks available for fetch overlap: five execution clocks for both register/memory and immediate/memory TEST, with seven overlap clocks for the register/memory form and five for the immediate form. The new correction is restricted to unprefixed TEST in default-16 code (documented F6/F7 /0 and 84/85 memory forms). All prefixed TEST forms and default-32 code use the **prior diagnostic** cost/queue path; that path still suppresses global 286 access waits and is not equivalent to production timing.

`training/` contains 14 memory-form loops measured on the first VM boot. The byte/word immediate TEST loops used indirect `[bx]` and a DEC/JNZ scaffold and supplied the training observation. The other 12 instruction forms are controls. The CPU model executable `c950c2e6ed611a60216b916c5d28401dd5daa74341232c4a3962bf93714d34d4` corresponds to the manifest in that directory, with diagnostic enabled. The training `README.md` gives source and output hashes and records the negative controls. Three reference output files are byte-identical in one boot.

Before the holdout reference was read, eight whole-loop charges were fixed in `holdout/candidate.json` for a source-identifiable private candidate (governor source retained as `candidate-v1-governor.sv`, SHA-256 `31f99bf78e3813956be4602b4629ea1b04d1fd236209420e44beadcfcbaee230`; executable SHA-256 `a013d3c6850ea95ef79d176f3a27f4171838e64ec733827c41b853fd3fd40de6`). This candidate was derived from the training measurements and inspection of 86Box timing facts; no GPL implementation code was copied. The eight prospective cases add a NOP to the DEC/JNZ scaffold and vary byte/word, 84h/85h and F6h/F7h encodings, and indirect `[bx]`, `[bx+si]`, and direct addressing. Their timed loop instruction bytes match on both sides. The 3090-host reference VM used the checked reference COM SHA-256 `cb4b3bd1447dea20b6169578246cf1e8b19bbf21a7f407b60f3754cbfcf2c663` and the configured 12.5 MHz 286 with one wait state; its three result files are byte-identical and include a scratch-RAM read/write control. At the captured boot and result screenshots the emulator displayed 100%; no continuous speed trace was recorded. An initial Xvfb attempt failed before opening a guest window and supplied no measurements; the successful retry used a separate private display with GLX disabled. No shared disk or kit was used.

The reference estimates and candidate charges in `holdout/comparison.json` differ by 0.017–0.033 clocks per whole loop. They include timer/ISR and block setup, while the RTL marker harness has different setup; one-block quantization is not a complete measurement error bound. A later review found that the initial candidate also changed unmeasured prefixed forms. The final candidate narrows the correction to unprefixed default-16 code. Its executable SHA-256 `9beadd324d3a965987f1563a4a67f5e1c59ab6cba7ca0026c0e1e67506ee5b06` and source hashes are in `holdout/final-candidate-manifest.json`; its charges on all eight retained holdout cases exactly match the original predictions (`final-candidate.json`). This replay after seeing the reference is not an independent prospective prediction, but demonstrates that narrowing the scope retains the prior observed cases.

`modes/` compares actual CPU execution of ordinary TEST, 67h, 66h, FS, overwritten FS then DS, and DS. The excluded cases use the prior diagnostic path within 0.002 clocks of phase rounding; ordinary TEST changes by one clock. `default-off/` compares complete stdout of pre-change and final default-off CPU models for the same mixed-prefix program across max, 286, 386 and turbo configurations; all four are identical. The final default-off build produced the identical executable bytes as the compared narrowed candidate. This is a sampled behavioral differential, not a netlist, formal, Quartus or board equivalence proof. Package layout changed, so timing, seal and any exact-artifact tests need fresh evidence.

The 14 plus eight observed loops do not establish general waits, non-RAM accesses, interrupted/faulted reference timing, whole applications, or game speaker pitch. The `verify.py` in the parent fixture checks retained hashes and arithmetic; it cannot independently establish reference provenance. Private emulator, ROMs and disks are not included.
