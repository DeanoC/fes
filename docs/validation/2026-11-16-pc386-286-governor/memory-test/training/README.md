# 286 memory-form calibration: diagnostic, 16 November 2026

Fourteen timed loops were assembled for 86Box 6.0, 12.5 MHz 286, one wait state, and for FES CPU simulation with `GOV_REFERENCE_DIAGNOSTIC=1`. Both used 1,000 loop iterations; all 14 tested body and DEC/JNZ instruction encodings match byte for byte. The BIOS timer reports number of blocks in 64 ticks. `comparison.json` gives whole-loop estimates and one-block quantization; it does not isolate instruction cost. The fixed RTL predictions in `rtl.json` were reported before running the reference. Three outputs in a single reference boot are byte-identical and start with `SCRATCH_RAM_VERIFIED`; that validates an ordinary scratch write/read, not every instruction's result or MMIO.

Twelve of 14 loop estimates differ from the frozen RTL by at most 0.032 clocks. Immediate byte and word TEST loops show RTL around 0.97–0.98 clocks above reference. This result argues against uniformly adding a per-access clock to these tested forms, but is insufficient to establish general wait behavior for unmeasured opcodes, alignment, external memory, or device accesses. An independently predeclared altered-scaffold TEST holdout is in `../holdout/`, and a candidate cannot be treated as production-qualified on this sample.

The 86Box VM disk and ROMs are private and are not distributed here.
