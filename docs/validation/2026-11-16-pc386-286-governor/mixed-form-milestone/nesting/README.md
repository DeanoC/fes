# Private diagnostic nested ENTER evidence, 2026-11-16

This bundle records an experimental, default-off 286-reference governor candidate. It is not a product fix, a full-machine measurement, a physical 286/VGA measurement, an audio/pitch result, or hardware acceptance. No kit was used. Guest code, tiny text output, simulation logs, inputs/hashes and compact 4-fps speed crops are included; no private DOS disk, firmware/ROM contents, game data or CPU executable is included. Full raw traces and private VM state remain under `out/dev/1902-enter-nested/` and the respective private hosts.

`prior-miss/` preserves the initial independent ENTER_NEST1 miss: whole-loop reference 32.050 versus frozen v2 28.029 clocks, including its scaffold. Raw source, paired-loop manifest, sampled counts, prediction and identity files remain as originally recorded. It is not overwritten by the new measurements.

`fixture/` holds the corrected independent source and assembled bytes, ten byte-matched even-aligned loop bodies, and generator. Levels 0,1,2,3,4 use a stable BP frame and DEC SI/JNZ scaffold; variants use allocations 6,12,32,256 and one uses LOOP. Separate pre-timing interrupt-disabled guest checks verify stack pointer, frame pointer, copied frame words and flags before and after ENTER/LEAVE. The bench enables IF for timing; its timer handler preserves the registers it uses. DOS guest stack is explicitly saved/switched/restored. The diagnostic RTL executable was built beforehand and private executable/stimulus copies, producer metadata and before/after input hashes were frozen before reference output was read; `cpu/{v2,v3,v5}/` holds predictions and logs. The v2/v3/v5 binary hashes and exact source identities are in the producer and run manifests. The final guest loop stimulus SHA-256 is `85df0ef9d3e3ae548d4418f376f4b185c8f08aa7e9b2d2d543fbefe62cd8f1ae`; reference COM is `1508b9b7470e241e970e4ba84873ccba6497a26a25156552bc3f9fef2c544c14`.

`reference/` records the private 86Box v6 configured IBM VGA/286-12.5 MHz, one-wait-state VM inputs and driver, pre-run immutable hash/symlink manifests, exact commands, three tiny raw guest outputs, and whole-loop comparison. The guest output files are byte-identical (SHA-256 `512206c89af27e3955ce7be7c7bc3d3773a1b5e1c221876e545184addbc1cb7c`) and contain all ten results with no control failure. The three runs came from one VM boot. V5 vs reference clocks per DEC-scaffold whole loop at levels 0–4: 27.012/27.024, 32.013/32.026, 36.013/36.017, 40.013/40.019, 44.013/44.028. Allocation variants reproduce the respective level, and L2 LOOP is 38.017/38.044. Each estimate includes BIOS timer/ISR, block setup/checking, 64-tick quantization and harness differences; those effects make the quantization alone an incomplete error bound. A single boot and these short loops do not qualify other opcodes, instruction encodings or workloads.

`reference/speed/` holds the audit, template screenshot, complete per-sample compressed 56x18 grayscale indicator strip, extraction tool, geometry, source raw-trace digest and screenshots. All 1,020 samples at 4 fps exactly matched the boot screenshot's visually inspected 100% indicator; no inference is made between samples. The post-run immutable source/ROM/executable hash and symlink inventory matched pre-run; the VM disk and NVR were private writable state. The compressed strip retains all samples, not a subsample; the separate full display trace is retained locally under `out/dev/1902-enter-nested/corrected-results/run-enter/`.

`failed/` preserves the first reference fixture and diagnostics. That VM never returned from EN1; EN1 was empty and EN2/EN3 were absent, so it supplies no timing evidence. Its cleanup reused DS after changing it to the old INT 1Ch vector segment and consequently read saved SS:SP through the wrong segment. The corrected fixture restores DS=CS before reading those values and returns to DOS; it also enables interrupts and resets its private stack before printing any control failure. Both the unchanged diagnostic CPU stimulus bytes and the failed fixture are retained. The failed run's input disk SHA-256 was `7b02c82272b5cd616c7df4820cc9ba32c26eabef6d7aa98333e2b0a58132b3b4`, post disk `5b73ae8ac7142aa39d052f8f884be3490c5672723fd65d56cc35d7f7fa3d1762`, immutable manifest `f06cf6824012ed1ed9c559d09d4199e7c9ade19298af317f52bc0964708b0c6e`, and full speed trace `e184604b050fd61175b9594da95d2e2f851c4d88ac8af0bde53647cb98f3727f`. The 1,020 speed samples all matched 100%, but that does not rescue the invalid guest run.

`controls/st2/` records whole-CPU v3/v5 tests for RAM, source page end/cross, target line cross, source and target synthetic MMIO, MMIO-to-RAM target crossing, and prefixed fallback. Every case checks frame words and SP/BP. Only classified RAM or page-end/target-RAM-line cases change their v3 charge on v5; other cases match v3. The target mixed crossing also has another MMIO push, so its overall fallback does not isolate attribution to that one uop. `controls/paging/` adds noncontiguous source-page mappings and a partial nested-copy #PF: one handler marker, CR2=4fffh, remapping and restart, correct frame and final state; v3 and v5 match on both crossing/fault cases while the page-end case changes. This relative result does not prove the absolute baseline charge, nor distinguish implementation replay from an architectural page-fault restart. `controls/stack/` records the 16-bit-code SS.B transition controls and old-v11-off vs v5-off sampled equality of marks, charge, final architectural state and governor summary; no synthesis or physical equivalence is claimed. All CPU binaries were copied privately, with exact producer/source manifests and matching input hashes. Fault/replay timing beyond the shown page-fault control, real VGA devices, general protected cases and tier-1 acceptance remain open.
