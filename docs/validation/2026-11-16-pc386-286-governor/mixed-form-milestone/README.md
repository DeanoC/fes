# Default-off 286-reference mixed instruction milestone

This is a diagnostic emulator-calibrated timing model, not physical 286 timing, a production fix, an audio result, or tier-1 acceptance. The enabled path remains disabled in registered machines. The new rules cover unprefixed, effective 16-bit TEST AL/AX immediate, ordinary-RAM non-REP STOS, and ENTER/LEAVE on a 16-bit stack. ENTER's encoded nesting must be in 0–31; levels 5–31 are extrapolated from the general rule and have not been compared with the reference. Its modeled fetch consumption is three bytes; its execution budget is 10 clocks for nesting zero and `11 + 4 * level` clocks otherwise. The instruction-wide RAM check admits ENTER's source-to-stack micro-operation only when the source is RAM and entirely within one translated page, and the independently translated target and any crossed line are RAM. Prefixes, 32-bit stacks, other st2 operations and unsupported memory contexts retain the prior diagnostic path. This is still a surrogate, including the prior diagnostic's wider wait suppression; fallback does not mean production timing.

`original-mixed/` retains the source, raw guest sample, speed record and whole-loop comparison that exposed the BYTE_STREAM, ARITH_BRANCH and ENTER_LEAVE residuals. `form-holdout/` contains independent byte-matched alternate forms, source, guest sample, prospective CPU predictions, CPU before/after manifests, 4-fps speed strips and comparison. Fifteen of sixteen full-loop estimates were within 0.036 clocks of the candidate; the nested ENTER negative control failed with the earlier candidate (reference 32.050, candidate 28.029 clocks). The failure is retained and led to the separate nesting study.

`nesting/` retains the corrected independent levels 0–4 and allocation/scaffold study, raw outputs, predictions, source and binary hashes, controls, speed strips, and the first invalid reference run. The latter failed guest cleanup and produced no timing evidence. With the new model, reference and CPU estimates differed by at most 0.027 clocks per whole loop in those ten cases. Three identical reference files came from one emulator boot. The host also had an unrelated low-load Quartus fit. The 1,020 observed speed samples were 100%; speed between samples is unknown. ISR and block setup, guest versus RTL harness differences and coarse count quantization all affect the estimates. See [nesting/README.md](nesting/README.md) for details and its raw evidence index.

`st2-boundary/` and `paging-fault/` retain the CPU fixtures, result records and runner snapshots. They exercise ordinary RAM, exact and crossed source-page boundaries, a RAM target-line crossing, source/target synthetic MMIO and prefix fallback, plus noncontiguous physical pages and an architectural page-fault/map/retry. Those tests check architectural state and relative charges; they do not prove baseline timing, distinguish an implementation replay from page-fault restart, or qualify the actual VGA device. The protected-stack fixture and its diagnostic-disabled comparison are in `nesting/controls/stack/`.

`candidate/` identifies the frozen final enabled and disabled binaries and their source closures. The focused governor integration bench passed on the final source, including count 31, out-of-range fallback, prefixes, REP, RAM guards and stack width. Sixteen sampled default-off CPU program/mode pairs, covering max, 286, another preset and turbo, produced identical output to the preceding diagnostic-disabled binary. The independent protected-stack comparison also matched. These are sampled functional checks, not formal, synthesized-netlist, sealed-artifact or physical equivalence. Governor struct widths and CPU interface metadata change even when disabled.

The reference VGA wait mismatch and the divide-error pending-byte/queue issue remain open. No kit was accessed for these measurements. A registered enabled artifact, its normal timing and seal gates, and the actual Ultima VI pitch/remaining tier-1 gates have not been qualified by this milestone. Full traces and private disks/ROMs remain in ignored local output. Paths inside retained historical manifests name the original private runs; they are provenance, not a requirement that those paths still exist.
