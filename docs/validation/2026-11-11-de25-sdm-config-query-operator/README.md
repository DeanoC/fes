# Fixed CONFIG_STATUS Tcl transport capture

This source-bound experiment makes exactly one CONFIG_STATUS call on TRWU8CBL
through the installed programmer Tcl library. No flash open/select/register or
array operation, close, programming, mode change, reset, SD/flash write or UART
open is permitted. It tests output shape before designing a faster readback
transport. It is not authority for later flash IO and cannot establish a backup.

The installed internal package metadata says no executable currently supports
this package. Its pinned library and initializer were inspected and the fixed
wrapper passed injected system-Tcl tests, including zero IO on source, exact
opcode/cable arguments, ownership-address rejection, one-use retirement,
uncertain vendor errors and oversized returns. This remains an exploratory
pinned-tool interface, not a supported production dependency.

A new clean committed source, frozen complete source/artifact/tool closure,
current claim, fresh sixty-second parent/top USB observation, free UART, exact
USB node, owned single-kit JTAG service, fixed 3 MHz clock, vendor-first list and
fresh forced scan precede the consumed one-call attempt. Same cable/config/
service identity and ownership remain guarded. The returned Tcl value and all
stdout are retained. A completed capture is not configuration qualification;
independent interpretation of the actual response remains required. No fallback
or retry is permitted after any uncertainty. Bounds remain 30 seconds per tool,
300 experiment and 330 host. Host cleanup restores both clock parameters,
permissions and stops only the owned service; it must be independently audited.

Prior AFh identification, 16 MiB capacity inference and archived native final
Park remain separate evidence. Current CPU Park is not reobserved. Factory media
and the other kit are preserved. The complete selected input graph and exact
command policy are in `operator-source.json`.
