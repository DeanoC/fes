# pc386 governor probe: pre-measurement method, 16 November 2026

The established 86Box award286 reference and pc386 kit differ in the ratio of the Ultima VI calibration and delay loop costs. The earlier record did not distinguish instruction-fetch effects from table entries; a previously proposed order measurement was void because it changed the flags consumed by the branch. These experiments cannot by themselves select a repair or establish physical-286 timing.

Use only a private copy of the existing award286 VM, ROMs, emulator, and DOS disk. Run the same binary three times, on that 86Box interpreter with the original 12.5 MHz, one-wait-state settings. Each block counts 1000 loop iterations over 64 BIOS ticks, synchronised to a tick. Report each count, derive effective clocks/iteration as (64 * 65536 / 1193182) * 12500000 / (1000 * blocks), and include block overhead, quantization and interrupts in this effective number. The serial outer loop adds the same small overhead per block. Compare with unchanged loops and original BD calibration as controls; no kit claim is made.

1. **Order pair:** identical `inc word [mem]`, `cmp word [other],0`, and `loop` instructions and addresses, with `inc`/`cmp` swapped. Both increment and compare execute 1000 times and LOOP ignores flags. An additive class table predicts identical cost up to measurement quantization and alignment; use aligned loop starts and identical instruction length. A reproducible difference exceeding 0.2 clocks/iteration and three times observed within-variant repeat spread is evidence of sequence sensitivity that a simple additive class table cannot capture. It does not by itself prove fetch or explain the game's 1.98-clock difference. Below that threshold is inconclusive, not evidence of an additive machine.
2. **Prefix series:** identical `cmp word [mem],0; dec word [counter]; jne` with zero, one, or three DS segment override bytes on CMP. DS is already its default, the data access and instruction class are identical and loop starts are aligned. The current governor charges all three identically (it ignores instruction length and prefix). A reproducible monotonic difference above 0.2 clocks/iteration and three times spread shows the reference cares about an encoding detail the current governor does not; it does not separate prefix decode cost from instruction fetch, nor justify applying a linear per-byte charge. Identical times do not rule out fetch on other code.

Run three repeats. If the control differs from prior reference BD by more than 1% (2436 blocks), any timing inference is invalid until explained. A differing emulator configuration, missing outputs, or nonterminating probe is an invalid run. No threshold will be relaxed after seeing results. Existing reference files are read-only; only private copies may be run or modified.
