# Read-only mailbox-view mapping proposal

The consumed459acd8b2a920a67 Nano trial localized the initial FPGA configuration failure to the original response-doorbell timeout: software fill0,40 existing reads, final doorbell0, no descriptor allocation or response parsing. Native MMU/private-DDR/EL1/SD/FAT startup passed. Device acceptance and command consumption remain unknown. Its terminal result and complete archive remain preserved. The NS Device mailbox mapping is a hypothesis to investigate, not a proven cause.

This off-board prototype uses the exact retained BL31 ELF/table bytes from that image. It changes one previously unmapped entry in the existing OCRAM level3 table: virtual0x90000 maps only the4KiB physical mailbox page0x10a30000 as secure Device, read-only and execute-never. Every other ELF byte remains identical; adjacent holes and the original NS peripheral mappings remain unchanged. It consumes no new table, OCRAM storage, DDR reservation or peripheral-window permission. This is a proposed private EL3 observation address, with no command-writing capability.

An independent actual-ELF table walk verifies the alias attributes and neighbouring holes. A small AArch64 probe loads the retained tables with that controlled change at emulated A53 EL3. Nineteen translation/permission queries pass for the proposal, including denied alias writes, secure alias reads, expected physical target, both unmapped neighbours and unchanged NS mailbox read/write translations. The probe never accesses Nano device registers. Five negative controls each fail the same positive contract: writable alias, non-secure alias, wrong physical page, mapped neighbour and the original unmapped alias. The current selected production verifier rejects even the intended proposal with `EL3 ocram table permissions or descriptors differ`, proving no unsupported mapping was silently admitted.

These results establish emulated translation and actual descriptor restrictions only. They do not establish physical mailbox accessibility, valid register contents, FPGA command consumption, core loading or appliance acceptance. No selected source, firmware, boot image or board state changed. The producer still requires its existing exact tables.

Next implementation: explicitly bind the single read-only alias to a diagnostic MMU contract, then connect bounded read-only observations before and after MMU activation while the existing trusted owner holds every master/secondary CPU. Reuse the existing stack-free terminal exception path and preserve all normal identity mappings, mailbox commands, resets, acknowledgements, timeout values, first-failure policy and1s tape limit. Rebuild and verify the exact linked descriptors and adapter before any new single-use Nano trial. The original factory card remains preserved and the top remains parked under the continuing claim.
