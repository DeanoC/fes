## Why S8a breaks this tree

The lane mapping itself is fine: DE25 is `front_end = "quartus-pro"`, so it gets
`FES_TC_QPRO FES_PNR_QUARTUS FES_DEV_AGILEX5`, which sets both `FES_TC_QUARTUS` and
`FES_VENDOR_RAM`, and R3/R4/R6 plus core site 9 keep today's selection. The breakage is in three text
contracts:

**(a) Site 10, by construction.** S8a turns `cores/fes-zx81/rtl/zx81_tape_store.v:21` into
`` `FES_RAM_TDP `` and deletes the guard around `:21-25`. Both DE25 checks are byte-exact against
that file — *verified*:

- `test_tape_store.py:32-33` requires the wrapper's else-arm to equal the core file byte for byte,
  raising *"board behavioral branch must contain the entire portable source verbatim"*;
- `retarget_tape` (`zx81-hps/build.py:59-68`, contract check at `:64-66`) requires
  `native == source + b"`endif\n"` **and**
  `prefix.count(b'`ifdef') == 1` and `prefix.count(b'`endif') == 0`, raising *"ZX81 tape RAM
  adaptation contract changed"*.

That second clause constrains the fix as well as forcing it: `` `ifdef FES_DEV_AGILEX5 `` keeps the
single-`` `ifdef ``, zero-`` `endif `` prefix shape; a nested or multi-arm guard does not. The
wrapper exists because the portable `m10k_tdp` store does not map to Agilex 5 M20K with `OLD_DATA`
mixed-port behaviour, so this is a functional dependency, not a cosmetic one.

**(b) An enforced hash gate.** `link-proof/zx81-standard/reviewed-inputs.json` pins
`boards/de25nano/zx81-hps/tape_store.v` (`:68`), `cores/fes-zx81/rtl/zx81_dpram.v` (`:103`) and
`cores/fes-zx81/rtl/zx81_tape_store.v` (`:109`). `link-proof/zx81-standard/static_reference.py:83-84`
requires every bound hash to match — *"reviewed hardware/clock/integration source changed"* — and
that file's own sha256 is bound at `:27`. *Verified.* So S8a fails `build_zx81_static_package.py` and
`M/tests/test_de25_static_reference.py` until the reviewed-input set is re-approved and two pinned
files re-hashed.

**(c) `retarget_ram` survives S8a but breaks at S11.** Its three anchors are
`intended_device_family = "Cyclone V"` (`zx81_dpram.v:66`), `ram_block_type = "M10K"` (`:68`) and
`ramstyle = "M10K"` (`:79`), each required `count == 1` by `_derive` (`zx81/build.py:74-81`). S8a
changes only the guard at `:23`, so the anchors hold. S11's `fes_tdp_ram` deletes them, breaking
`retarget_ram` (`zx81/build.py:84-87`), its duplicate in `link-proof/zx81-ram/profile.py:68-70`, and
the assertions at `zx81/test_build.py:70-71`, `:75`, `:106` and
`link-proof/zx81-ram/profile_test.py:30-32`.

## What the record gets wrong about this tree

1. **The Quartus Pro row understates the work.** It says the header "is copied into the flat project,
   as DE25 copies its sources (`display/build.py:178-180`)". `display/` has no `QUARTUS` guard at
   all; the six guards live in `zx81/`, `zx81-hps/`, `shared-rtl/` and `link-proof/`, which stage
   into `fes_mailbox/` and `fes_link/` and declare files through `_hw.tcl` filesets — a different
   mechanism. One copy site in the record, four routes across five projects in fact.
2. **Site 10's reader list is wrong**, and its risk rating with it. See (a) above.
3. **The byte-patch inventory is incomplete** — it misses `zx81/build.py:84-87` (`retarget_ram`)
   and `:90-92` (`retarget_video`), `zx81-hps/build.py:59-68` (`retarget_tape`, whose contract
   check is `:64-66`) and `link-proof/zx81-ram/profile.py:68-70`. The `FES_RAM_*` table's
   Agilex 5 column produces exactly what these patchers produce, so S11 makes all of them superseded
   code to delete, which the plan should say under the no-shims rule.
4. **Three acceptance-regex holes** live here: `` `define QUARTUS ``/`` `undef QUARTUS ``
   (`test_tape_store.py:62`), the `.*QUARTUS` guard regex (`zx81-hps/build.py:341`) and the C1
   comment all survive the acceptance pattern.
5. **A dead guard the 18-site count has no slot for** (R2).
6. **The dependency arrow points the wrong way.** S8 names no DE25 artifact, and S16 lists S8 as
   *its* dependency, but the reviewed-input gate and the tape-store byte contract have to land inside
   S8a.
