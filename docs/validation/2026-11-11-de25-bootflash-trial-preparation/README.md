# Bounded native boot-flash trial preparation

This is host tooling and off-board evidence. No flash write, live programming
attempt, power cycle or autonomous power-on acceptance is recorded here.
The top kit is TRWU8CBL; the other DE25 remains outside the operation.

The native phase-one-only JTAG startup already passes automatic SD discovery
and two-core launch/return. Two separately admitted full factory main-array
reads match, and vendor-produced restore files decode to all the original
bytes. Those records remain separate:

## Operator and acceptance

The private retained workspace is `out/nano-bootflash-trial-20261111`.
Its helper hashes are recorded in `operator-source.json`; its source-bound
plan, tool/input closure and receipts remain alongside the operator. No approval
file is generated by preparation. `program.py --check-only` checks files
without opening devices or granting programming authority.

`flash_trial.FlashTrial` requires direct human authorization for the exact
plan digest and role. It checks both JICs and the factory backup identity,
then composes the existing one-use live-scan gate. A durable write-intent
record precedes the one program-and-verify callback. Failed or uncertain
attempts cannot be replayed by reinstantiation or a concurrent caller.
There is no alternative device index, automatic retry or automatic restoration.

The actual operator retains the top-only claim, fresh 60-second parent/top
USB observation, clean committed source, frozen inputs, private network
namespace/server/configuration, fixed 3 MHz with automatic adjustment off,
vendor-first enumeration and a fresh count-one/`4362C0DD`/IR10 forced scan.
It constructs exactly `IPV;<absolute pinned JIC>;A5EB013BB23B@1` as one
argument. The programmer has a 2700-second cap, the operator 2800 seconds,
and its supervisor 2900 seconds, with 12-second heartbeats. Each subprocess
has its own process group; timeout kills only that owned group. Cleanup
restores the original clock/automatic setting and exact USB permissions,
stops the private server and checks the free UART. An independent read-only
audit checks recorded log hashes, namespace/server absence and host restoration.

Programmer-reported success is a separate receipt from power-on boot.
After successful programming and cleanup, `capture.py` exclusively arms and
flushes the UART before the operator asks for a physical board power cycle.
It invokes no JTAG program/reset and sends no startup UART command. It requires
human confirmation bound to that capture, SDM POR boot kind 0, one complete
SPL beginning, the matched native decoder and the final EL1 handoff marker.
The sticky last-POR reset flag alone cannot establish a fresh power-on.
Missing cycle confirmation stays pending and grants no factory recovery.

The capture uses the existing 50-second handoff and 100-second initial menu
checks within the 450-second native phase. Its separate arming window is
180 seconds. Once startup and POR are verified, the existing installed-library
client executes two launch/return cycles and final Park; saved byte windows
and polling offers are replayed independently. It does not install a package.
USB/serial loss stops the attempt without reopening or replaying the console.

A failed native write, or a completed and confirmed failed native boot trial,
can admit one separately authorized factory recovery, with a fresh private
service and live scan. A pending power cycle cannot. Recovery does not itself
prove factory boot: that requires the original factory SD card, a subsequent
power cycle and independent factory verification.

## Software evidence and remaining gates

Host tests cover exact approval/target/array admission, changed ownership,
source/plan/approval drift, failed scan, uncertain programming, persistence
failure, concurrent/replayed attempts, pending cycles and conditional recovery.
The real retained native decoder accepts a deliberately modified POR model
and rejects the original JTAG capture as power-on proof. The modified trace
is synthetic. Real saved discovery/launch/return data replay, and a shortened
return rejects. A device-free test runs the actual wrapper's timeout path
against its own child/grandchild, checking that both stop.

The [actual collector model](capture-model-proof.json) executes the complete
private capture script with all device I/O injected. It covers a successful
two-core cycle, delayed confirmation with an intervening real menu frame,
a truncated final return, an unconfirmed cycle and a JTAG boot. Both latter
cases send zero App commands. Re-establishing the initial capture extent after
confirmation preserves every queued frame for independent replay.

The [software run](software-result.json) passes `make test-changed --base HEAD`,
including a 1,999-test parent run with five skips, and `make check`. The 21 new
contract tests also pass. The [actual image check](actual-image-proof.json)
uses the vendor JICs above. Model proof hashes describe their run-time helper
snapshot; the independent cleanup auditor was subsequently tightened to check
the physical USB identity too. That audit change grants no live cleanup proof.

The first retained-trace model exposed an early `loader_ready` indication:
truncating the final handoff could still leave that indication true. Power-on
acceptance now requires the final EL1 marker as well. The initial failed model
and a later sandbox setup failure remain in the private preparation logs.
Other failed model and result-publication attempts remain retained as failures.

No result here qualifies physical flash programming/restoration, autonomous
boot, whole-array post-program readback, current HDMI/keyboard behavior,
native Ethernet, additional package/device families or full DE10-equivalent
appliance behavior. Permanent boot-flash changes require explicit approval
under the repository's shared-kit rules before this operator may run.
