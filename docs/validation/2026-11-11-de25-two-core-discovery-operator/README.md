# Independent two-core reboot/discovery procedure

This separate procedure follows the passing two-core installation trial. It uses fresh recovery and native programming lifetimes with the same matched boot 6f54fe7c04d34128. Recovery reads fourteen existing staged files and all three installed records without downloads or writes. Native startup must discover both targets as already installed, preserve the original ZX81 entry, launch both with the expected identities/fetch/tape behavior and reach final Park. No Install action is permitted.

The two expected new records are generated from the production Go packagestore.PrepareInstall method using the exact staged artifact bytes. A separate Python canonical reconstruction verifies both generated records and reproduces the original physically verified 754-byte ZX81 record as a golden check. The expected startup order is derived from the actual FAT reader's sorted hash-derived record filenames: ZX81 trial, ZX81, ZX80 trial. Readback must match all three exact byte hashes, not merely self-advertised card metadata.

The dedicated discovery observer and saved-wire replay require both installed flags before any cycle and do not invoke Install. Their expected final counts are five configurations/logical generation 5, two computer launches, three menu sessions and firmware generation 29. Models cover the actual read-only script, wrong/missing records and source content, malformed receipts, native failure without retry, partial/uncertain UART writes and independent per-role cleanup. Initial model runs exposed fixtures that generated startup twice or retained first-install generation/order assumptions; the discovery fixtures now generate once and preserve the original startup snapshot. Those failed logs remain retained.
