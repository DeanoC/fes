# D12: MENU, ZX81, Spectrum and ST after the builder generalisation

The builder generalisation (design.md, "Closure") edits `hps/build.py`,
`scanout/build.py`, `scanout/linux_dma.py`, `scanout/integrate.tcl` and
`producers/`. All four other DE25 packages hold those files in their
closures, so all five `BUILD_ID`s move. Each takes the D12 comparison:

- its Quartus Pro project inputs byte-identical apart from `BUILD_ID` and
  paths;
- an RBF reproduction with main's `BUILD_ID`;
- its own producer's timing and signoff gates.

## Method

These ran on chip-30x0-ai-dev, with Quartus Pro 26.3 and the vendor archive
`DE25-Nano_revB_v.1.0.0_ResourcePackage.zip`, one job at a time.

- **A:** main at `8a162c536`, the branch's merge base, with each producer's
  `--compile-only`.
- **B:** the branch's full producer, which runs its signoff and repeat
  builds and the timing, async-input and audio-clock reviews.
- **C:** the branch's tooling with main's `BUILD_ID` forced
  (`d12_repro.py`, which replaces `build_identity` and runs
  `--compile-only`).

The scripts were `d12-de25.sh`, `d12-rerun.sh` and `d12-rerun2.sh`, with
`d12_cmp.py` for the input comparison.

B and C for every package ran at **`d44fbc782`**. C MENU exits 1 after
writing its RBF, because the MENU producer runs its async-input review even
with `--compile-only`, and that review refuses a `BUILD_ID` that doesn't
match its source record: the forced ID is exactly that mismatch. That is the
refusal working, not a design difference. The other producers skip their
reviews with `--compile-only`. The first batch's
Spectrum and ST B runs failed at the build record on
`spec.board.MACHINE_HZ`, fixed in `e88b2752c`, and its menu and ZX81 B and C
ran at `abb9e4994`, before `be044cb1a` changed their verifier closure. So
all ten runs were repeated at `d44fbc782`.

"Pass" means `package_timing_admission` true, and the signoff and repeat
RBFs are byte-identical.

**Project inputs.** `d12_cmp.py` compares every QSF, QPF, SDC, HDL, Tcl,
IP, qsys, hex, MIF and JSON file under `signoff/combined/hps/project`.

- **A against C** (the same `BUILD_ID`): 638 (MENU), 704 (ZX81), 736, 736
  and 748 files, all present on both sides. `integrate-mailbox.tcl`
  differs, and only in its absolute build directory. MENU's
  `peripheral_subsys.qsys` also differs, only in the one value described
  next.
- **A against B:** these also differ in the `BUILD_ID`. It appears as a
  hex literal, a binary Verilog parameter and a decimal qsys parameter, in
  the scanout IP's `.ip`, `_bb.v`, `_inst.vhd`, `synth/*.v` and
  `peripheral_subsys.qsys`.

**One informational qsys value varies between runs.** In
`peripheral_subsys.qsys`, the scanout master's recorded address map names
the F2SDRAM adapter's slave either `subsys_hps.f2sdram_adapter.axi4_sub` or
`subsys_hps.f2sdram_adapter_axi4_sub`. Platform Designer picks the spelling
per generation, on main as well as on the branch:
- main's A-menu, A-zx81, A-spectrum128 and A-st have the second spelling;
- A-spectrum48 has the first;
- one producer's signoff and repeat builds disagree (B ST, B Spectrum 128).

It doesn't reach the bitstream. B ST's and B Spectrum 128's signoff and
repeat RBFs are byte-identical across the two spellings, and so are A MENU's
and C MENU's. So it isn't a
design difference, and the comparison doesn't treat it as one.
