# D12: the other DE25 machines after the builder generalisation

The builder generalisation (design.md, "Closure") edits `hps/build.py`,
`scanout/build.py`, `scanout/linux_dma.py`, `scanout/integrate.tcl`,
`machine/board.py` and `producers/`. Every other DE25 package holds those
files in its closure, so every other `BUILD_ID` moves: MENU, ZX81, Spectrum
48 and 128, ST, and, since main's #2069 and the C64 standard machine, C64 and
PC/XT on the shared machine builder. Each takes the D12 comparison:

- its Quartus Pro project inputs byte-identical apart from `BUILD_ID` and
  paths;
- an RBF reproduction with main's `BUILD_ID`;
- its own producer's timing and signoff gates.

The Linux model of each machine is compared (C64 `pal`, PC/XT `xt`, Spectrum
`48` and `128`). The native-shell models (Spectrum 48 native, C64
`nativepal`) are not in this round.

## Method

These ran on chip-30x0-ai-dev, with Quartus Pro 26.3 and the vendor archive
`DE25-Nano_revB_v.1.0.0_ResourcePackage.zip`, one job at a time under the
chip's Quartus Pro lease, driven by `d12-run6.sh`.

- **A:** main at `c9f0bc2ee`, the commit merged into the branch at
  `b27ab3ae5`, with each producer's `--compile-only`.
- **B:** the branch's full producer at `bf50fc1dd`, which runs its signoff
  fit and the timing, async-input and audio-clock reviews. Since main's
  #2090 every DE25 producer fits once; there is no repeat fit to compare.
- **C:** the branch's tooling at `bf50fc1dd` with main's `BUILD_ID` forced
  (`d12_repro.py`, which replaces `build_identity` and runs
  `--compile-only`).

All 21 runs came from clean checkouts, between 21:58 UTC on 23 November and
02:07 UTC on 24 November. `d12_cmp.py` compares the inputs.

C MENU exits 1 after writing its RBF. The MENU producer runs its async-input
review even with `--compile-only`, and that review refuses a `BUILD_ID` that
doesn't match its source record. The forced ID is exactly that mismatch, so
the refusal is the review working, not a design difference. The other
producers skip their reviews with `--compile-only`.

Earlier rounds ran at `3401bb193` against main `f3140cb33` (MENU, ZX81,
Spectrum 48/128 and ST) and passed the same way. This round replaces them
because each merge of main moved every `BUILD_ID`.

**Project inputs.** `d12_cmp.py` compares every QSF, QPF, SDC, HDL, Tcl,
IP, qsys, hex, MIF and JSON file under `signoff/combined/hps/project`.

- **A against C** (the same `BUILD_ID`): 637 (MENU), 703 (ZX81), 737, 737,
  747, 749 and 813 (PC/XT) files, all present on both sides. Only
  `integrate-mailbox.tcl` differs, and it is byte-identical once each side's
  absolute build directory is replaced.
- **A against B:** these also differ in the `BUILD_ID`. It appears as a
  hex literal, a binary Verilog parameter and a decimal qsys parameter, in
  the scanout IP's `.ip`, `_bb.v`, `_inst.vhd`, `synth/*.v` and
  `peripheral_subsys.qsys`. No other file differs, for any of the seven.

The Platform Designer address-map spelling that varied between earlier
rounds no longer does: main's #2090 made the generation canonical.

**The PC/XT RBF: not measurable.** A and C have byte-identical project
inputs apart from the build path, yet their RBFs differ. Two further runs
separate the causes, each into A's own output directory with A's kept aside:

Main's own PC/XT compile does not reproduce itself: the same tooling, the
same `BUILD_ID` (`c7b4df32…`) and the same directory gave two RBFs and two
register counts. In the same-path C run every file Quartus reads under the
project is byte-identical to A's; only reports, logs and the staged
Python tooling copies differ. So the PC/XT has no reproducible main RBF for C
to match, and its RBF comparison is not measurable here. It is not a pass. Its
inputs comparison and its B gates pass. The other five machines whose C ran
reproduce main's RBF exactly. Main's PC/XT nondeterminism is issue #2182.
