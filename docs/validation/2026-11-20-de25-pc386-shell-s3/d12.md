# D12: MENU, ZX81, Spectrum and ST after the builder generalisation

The builder generalisation (design.md, "Closure") edits `hps/build.py`,
`scanout/build.py`, `scanout/linux_dma.py`, `scanout/integrate.tcl` and
`producers/`. All four other DE25 packages hold those files in their
closures, so all five `BUILD_ID`s move. Each takes the D12 comparison:

- its Quartus Pro project inputs byte-identical apart from `BUILD_ID` and
  paths;
- an RBF reproduction with main's `BUILD_ID`;
- its own producer's timing and signoff gates.

## Method

These ran on chip-30x0-ai-dev, with Quartus Pro 26.3 and the vendor archive
`DE25-Nano_revB_v.1.0.0_ResourcePackage.zip`, one job at a time.

- **A:** main at `f3140cb33`, the commit merged into the branch at
  `3401bb193`, with each producer's `--compile-only`.
- **B:** the branch's full producer at `3401bb193`, which runs its signoff
  and repeat builds and the timing, async-input and audio-clock reviews.
- **C:** the branch's tooling at `3401bb193` with main's `BUILD_ID` forced
  (`d12_repro.py`, which replaces `build_identity` and runs
  `--compile-only`).

All fifteen runs came from clean checkouts, driven by `d12-run3.sh`, between
16:00 and 23:45 UTC on 21 Nov. `d12_cmp.py` compares the inputs. The commit
after `3401bb193`, `dd5103afa`, changes only this directory, so the results
hold at the branch head.

C MENU exits 1 after writing its RBF. The MENU producer runs its async-input
review even with `--compile-only`, and that review refuses a `BUILD_ID` that
doesn't match its source record. The forced ID is exactly that mismatch, so
the refusal is the review working, not a design difference. The other
producers skip their reviews with `--compile-only`.

Earlier rounds ran at `d44fbc782` against main `8a162c536`. They passed the
same way, and this round replaces them because the merge of main moved every
`BUILD_ID`.

"Pass" means `package_timing_admission` is true in the signoff, repeat and
summary records, and the signoff and repeat RBFs are byte-identical. The
packages are MENU `b3129370…`, ZX81 `79d798c4…`, Spectrum 48 `0cf53ead…`,
Spectrum 128 `f697f98f…` and ST `7191ad62…`.

**Project inputs.** `d12_cmp.py` compares every QSF, QPF, SDC, HDL, Tcl,
IP, qsys, hex, MIF and JSON file under `signoff/combined/hps/project`.

- **A against C** (the same `BUILD_ID`): 637 (MENU), 703 (ZX81), 735, 735
  and 747 files, all present on both sides. `integrate-mailbox.tcl`
  differs, and is byte-identical once each side's absolute build directory
  is replaced. MENU's, both Spectrums' and ST's `peripheral_subsys.qsys`
  also differ, and are byte-identical once the one value described next is
  normalised.
- **A against B:** these also differ in the `BUILD_ID`. It appears as a
  hex literal, a binary Verilog parameter and a decimal qsys parameter, in
  the scanout IP's `.ip`, `_bb.v`, `_inst.vhd`, `synth/*.v` and
  `peripheral_subsys.qsys`. No other file differs.

**One informational qsys value varies between runs.** In
`peripheral_subsys.qsys`, the scanout master's recorded address map names
the F2SDRAM adapter's slave either `subsys_hps.f2sdram_adapter.axi4_sub` or
`subsys_hps.f2sdram_adapter_axi4_sub`. Platform Designer picks the spelling
per generation. This round, A MENU and A Spectrum 48 have the first
spelling and their C runs the second, while A Spectrum 128 and A ST have
the second and their C runs the first. Each of those A/C pairs still gives
byte-identical RBFs, so the spelling doesn't reach the bitstream. It isn't
a design difference, and the comparison doesn't treat it as one.
