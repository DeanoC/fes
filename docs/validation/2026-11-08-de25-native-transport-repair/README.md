# Native timing after qualified programming-path repair

The earlier7abe procedure reserved one native operation and stopped at a failed
fresh scan before invoking a native programmer. Its reservation remains
consumed1/max1 and its result remains failed. Nothing in this procedure deletes,
reopens or resumes that operation or reuses its scan evidence.

A materially changed host input set now has independent physical evidence: the
source-controlled scan producer and adapter-only discovery passed a fresh scan,
one durably consumed/traced qualified recovery load and a matched serial boot.
This distinct procedure allows one operation per recovery/native phase using
those repaired inputs. The compiled7abe firmware/runtime/entry remain exact;
there is no artificial image change or rebuild to obtain another allowance.
Previous native reservations1 and actual native programming calls0 are both
recorded explicitly. Each new operation still needs its own fresh live scan,
complete transport identity rechecks and durable consumption before programming.

The full candidate is freshly validated once, then its complete file/source/
sealed-project membership and hashes are rechecked by the existing file-only
admission loader. No new permission comes from that off-board record. Package,
firmware, CPU/RAM mapping, device ownership, boot/ROM, USB and input validators
remain unchanged. The original1s tape limit remains in place. The test can
perform the full existing seven-configuration/three-launch/four-menu cycle;
first failure stops all commands and retains only the bounded2s passive tail.

The original phase caps remain: recovery240s/process270, uploads300s/process320,
native450s/process480, launch100s/configuration20s/stop5s/menu100s. The whole
operation is tightened to800s, with host890s for independent clock/server/USB/
UART cleanup. One prior transport programming failure remains, two the maximum
before a repair. There is no automatic retry, saved scan grant or fallback.

Thirteen fixed files are uploaded and freshly read/hash-checked before native
programming. Root recovery boot files and the original factory card are
preserved. The top kit remains exclusively assigned, its spare card stays in
place, and the bottom kit is untouched. No physical key action is requested.
An uncommanded startup lifecycle input remains terminal.

The unchanged timing firmware splits existing sampled ownership costs into
before-state, USB binding, reset-register and after-state portions. These are
diagnostic sample estimates, including measurement overhead. A failed tape
load, direct reset callback, successful programming or recovered prompt proves
neither normal core return nor fabric drain nor ordinary appliance acceptance.

Focused actual-wrapper failure tests and the actual App exchange/receipt/startup
models pass; the checked-in producer/policy retain the preceding1752-test suite
and vendor build proof. New source, file admission, artifact/input closure and
prepared/result evidence are retained with archive readback and Git bundle
verification before/after hardware. Full DE10-equivalent core-load acceptance
remains the goal and is not replaced by this timing diagnostic.
