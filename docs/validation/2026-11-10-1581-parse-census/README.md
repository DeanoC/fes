# #1581 S1a: front-end parse census

Spike S1a of [RTL front-end lanes](../../design/rtl-frontend-lanes.md) (#1581, child issue #1626). It runs one minimal module per construct through every front end, then the OPL2 tree and three genvar-heavy i386 modules file by file and as whole blocks. Run on Powerboat on 10 November 2026. No production code changed.

## Result

- **Quartus Pro 26.3 reads every form in the census, correctly.** All of Quartus 17.0.2 Lite's rejections and misreads below are Lite only.
- **Lite rejects:**
  - `signed'()` straight after a unary minus;
  - inline `for (genvar …)`;
  - a generate `for` loop without `generate`/`endgenerate`;
  - the struct-index shadow.
- **Lite silently misreads `signed'()` of an `int`-typed constant expression.** It accepts the form and computes the wrong value, with no message. No FES file has that form today: OPL2's localparams are untyped, and Lite gets those right.
- **The undefined-macro check does not stop Quartus.** Lite and Pro give a Critical Warning, expand the macro to nothing and carry on. A missing `` `include `` stops all six readers tested and names the reason in the file name, so the header should use that instead.
- **`(* no_carry *)` needs no fence.** Lite warns that it does not know the attribute (10335); Pro ignores it. Both compute the right sum.
- **Neither Quartus predefines `SYNTHESIS`.** Yosys does; Verilator does not.
- **Both Yosys locks behave identically on every form.** The census found one new Yosys fork bug, filed as [DeanoC/yosys#74](https://github.com/DeanoC/yosys/issues/74).
- **Icarus was not run.** It is not installed on Powerboat or fes-build-3090, and Powerboat lacks `gperf`, which its source build needs.

## How each form is judged

Accepting a file is not enough, since Lite has been known to misread forms without rejecting them. So every form drives an output `ok` that is a constant 1 only if the construct was read correctly. Each reader reports `ok` in its own way:

- **Quartus:** full synthesis (`quartus_map`, `quartus_syn`) on a tiny top, so `ok` folds to a constant. The result is Quartus's stuck-pin warning (13410). Where the value itself matters, the form also drives a bus, decoded from the same warnings.
- **Yosys:** a SAT proof that `ok` is 1 for every input (`sat -prove ok 1 -verify`).
- **Verilator:** lint, plus a simulation testbench for the struct-index shadow (`tb_f04.sv`) and the preprocessed text for `SYNTHESIS`.

Two forms carry their own observable. `f09` compares the block RAM bits Quartus reports against a control (`f09b`) whose macro expands to nothing; Yosys checks that the attribute reaches the memory. `f12a`–`f12c` pass when the reader stops.

### Narrowing the `signed'()` results

- **Lite's rejection is the unary minus.** `-signed'(x)` is rejected in any position (`bisect/neg_*.sv`). The plain cast, a cast in a `?:` arm and `-(signed'(x))` all parse. `-(signed'(x))` is also accepted by both Yosys locks, Verilator and Pro. So `vibrato.sv:73` is the only OPL2 `signed'()` site Lite rejects. The other four sites Lite parses and computes correctly.
- **Lite's misread needs `int`-typed operands** (`bisect/h_*.sv`, `logs/bisect-signed-cast.log`). With untyped localparams, in a package or a module, Lite computes 0 as it should. With `int`-typed localparams in either place, `signed'(D - S - 2) < 0` is false and Lite takes the other arm. The same comparison without the cast is right (`f01f`'s control output `c`). `opl2_pkg.sv:79` uses untyped localparams (`DAC_OUTPUT_WIDTH = 16`, `SAMPLE_WIDTH = 16`), and `f01g` reproduces it with Lite giving the right shift. The shipped OPL2 is therefore not affected. Any future `int`-typed use would be wrong without a message.

### The new Yosys bug (`f06c`)

Both locks reject a cast to a type imported with `import pkg::*` in the module header when the cast comes after a procedural `for` loop that declares its own loop variable: "Static cast with non constant expression!". The operand does not matter: a constant and a struct typedef fail too. Writing the package scope (`p::e_t'(x)`), dropping the loop, or putting the loop after the cast all pass. The repros are `bisect/yosys74_*.sv`. This is a different path from yosys#72 (a cast as a `case` selector). No FES RTL is known to hit it.

## What this decides

**`FES_HAS_SIGNED_CAST`: not added.**
- Lite rejects one form, `-signed'(…)`, at one site. Rewriting that site as `-(signed'(…))` or `$signed(…)` is accepted by every reader.
- A macro cannot fix the silent `int` misread anyway: the form parses, so nothing could switch on it.
- The common-subset rule is therefore a source rule: files that Lite reads use `$signed()`, not `signed'()`.
- Today no file Lite reads natively has a `signed'()`: pc386 reaches Lite through Yosys. If S13 ever makes Lite read OPL2 natively, `vibrato.sv:73` becomes a D5 vendored edit (one token, recorded in `source.json` `local_changes`).

**`FES_NO_CARRY`: not added.** Both Quartus editions accept `(* no_carry *)` and compute the sum. Lite only warns that the attribute is unknown (10335). The 11 i386 sites need no fence on any lane. The attribute is a hint to Yosys's mapping, and Quartus is free to ignore it.

**Final common-subset list (17.0.2 rejections).** These apply only to files that Lite reads as SystemVerilog; Pro reads them all.
- inline `for (genvar …)` outside `generate`: declare the genvar outside and wrap the loop in `generate`/`endgenerate`;
- generate loops without the `generate`/`endgenerate` keywords (10170). Treat an unkeyworded generate `if` the same way; this census did not reach one;
- a variable index into a packed-struct member whose name matches a module signal (10734);
- `-signed'(…)`, and `signed'()` on `int`-typed constants (silently wrong): use `$signed()`.

And one for the Yosys locks, until yosys#74 is fixed: a cast to a wildcard-imported type that comes after a loop-scoped `for` variable writes the package scope (`pkg::type_t'(x)`).

**Header check mechanism: a missing include, not an undefined macro.**
- Quartus does not stop on an undefined macro: Lite gives Critical Warning 10191, Pro Critical Warning 13432, and both expand it to nothing.
- A failed check should instead write `` `include "FES_TOOLCHAIN_ERROR_<reason>.svh" ``. All six readers tested stop on it, and every one prints the file name, so the reason reaches the log.
- The doc's fallback, instantiating an undefined module, is not needed.
- `$error` in a generate block is not suitable: Lite stops only with a syntax error, and Verilator stops only when `USERERROR` stays fatal, which `-Wno-fatal` turns off.
- S8's header test should also check that no file named `FES_TOOLCHAIN_ERROR_*` exists on any include path.
- Icarus is untested. S8 must run the include check under Icarus before relying on it there.

**`SYNTHESIS`.** Neither Quartus edition defines it. A Quartus front end therefore reads `` `ifndef SYNTHESIS `` blocks; OPL2's assertion at `control_operators.sv:444` parses under Lite. This supports the design's rule that the header never defines `SYNTHESIS`, and that synthesis-only code keys on lane macros rather than on `SYNTHESIS`.

**Lite lock move: not worth proposing now.**
- No newer Lite is installed, so this record cannot test one.
- Pro 26.3 accepts every form Lite rejects. That suggests a newer release fixes them, but Pro's front end is not the same product as Lite's.
- No lane in the plan needs the change. The i386 reaches Quartus through Yosys, and native-Lite OPL2 needs a one-token edit.
- S15 stays conditional. If S13 or S14 ever needs Lite to read the i386 natively, test a newer Lite then, against the 36 genvar sites.

**Struct-index shadow.** In this form Lite rejects the read (10734) rather than misreading it, so it fails loudly. The misread `quartus_fes_i386.py:11-14` describes may need a different shape. The rule stays in the list either way.

## Not verified

- **Icarus:** not run. Every Icarus cell, including the header-check mechanism, is open.
- **A newer Lite:** none is installed.
- **Verilator build:** the lock's Verilator (commit `5e4151e3`) was not built. The system 5.032 was used, which is the version the design doc names.
- **Lite at a later SV standard:** Lite was run only at SV2005, the only SystemVerilog setting 17.0.2 has.
- **i386 elaboration under Lite:** not attempted, since every module stops at parse.
- **Elaboration-level errors in the 19 OPL2 files:** the per-file sweep is parse-only. The whole-block Lite elaboration covers them only in the `pc386_opl2` configuration, with `vibrato.sv:73` rewritten.
- **Struct-index shadow:** only the minimal form was tried.

## Files

- `forms/`: the minimal forms, `census_pkg.sv` and `tb_f04.sv`.
- `bisect/`:
  - `h_*.sv`: the `int`-typed `signed'()` misread;
  - `neg_*.sv`: the unary-minus rejection;
  - `yosys74_*.sv`: the yosys#74 repro and its two passing variants.
- `census.sh` and `run_all.sh`: one form through one reader, and the whole matrix (three jobs at a time). Set `YOSYS_PC386` and `YOSYS_I386` to the locked binaries first.
- `sweep.sh`: the per-file sweep. `elab.sh`: the whole-block elaboration.
- `summarize.py`: writes `results.md` from `census.sh` output.
- `logs/`: the message lines of every run, with paths shortened:
  - `forms-<reader>.log`, `sweep-*.log`, `elab.log`;
  - `bisect-*.log`.

To rerun: `run_all.sh <out>`, then `summarize.py <out>`. Rerun `bisect/` by hand: each file is one top for `quartus_map`.
