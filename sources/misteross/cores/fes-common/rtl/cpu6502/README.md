# cpu6502

Verilog NMOS 6502 used by FES Apple II, C64 and the development 1541.

Source: https://github.com/Arlet/verilog-6502
Commit: `e930327ffecc5062bfce70bbcfba2bbfa6de6e4c`
License: see the notice at the top of each file (use permitted provided the
notice and copyright are retained).

Local changes: `cpu.v` is renamed `cpu6502.v` with module `cpu6502`, and
`ALU.v` is renamed `cpu6502_alu.v` with module `cpu6502_alu`, so the global
Verilog namespace does not collide with other cores, and trailing whitespace
is removed. FES adds an optional active-low `SO` input with `ENABLE_SO=1`.
A falling edge sets V, including between CPU enables; a held low level does
not retrigger after CLV. In this mode instruction flag writes occur only on
an enabled CPU cycle and retain priority over a simultaneous pin edge.
The optional `ENABLE_SO_CLV_INHIBIT=1` discards a delayed SO edge in the CPU
cycle following CLV's flag write. It requires a phase-qualified SO input and
is enabled only by the 1541 wrapper. Its default is zero, preserving the
asynchronous interface used by the standalone SO test.
The original V-update logic remains selected by default. Apple II and the
C64 motherboard tie SO high; only the development drive enables it.
`make sim-fes-c64-so` checks BVC polling, status pushes, CLV under a held-low
pin and the disabled mode. The drive's phase and CLV-inhibit tests use pinned
NMOS transistor-netlist observations. Analogue sampling margins and other
instruction-specific SO inhibit windows remain unqualified.

The core expects synchronous memory: data for the address presented in one
enabled cycle is consumed on the next enabled cycle. FES drives `RDY` as the
CPU clock enable and holds `DI` stable between enables. Undocumented NMOS
opcodes remain incomplete. The stable SAX family (`$83`, `$87`, `$8F`, `$97`)
is implemented in all four addressing modes. It stores `A & X` without changing
registers or flags, including zero-page index and indirect-pointer wrapping.
`make sim-fes-c64-sax` checks the writes, enabled cycle counts and register/flag
preservation, including CPU enable gaps.

IRQ polling follows the synchronous opcode-prefetch pipeline. It retains I
at the polling point, handles the extra delay for a taken branch without a
page crossing, and uses restored I for instructions following PLP. I changes
only on enabled cycles. Hardware interrupt entry is latched so a withdrawn
IRQ or SEI cannot change the pushed B bit into a software BRK.
`make sim-fes-c64-irq` checks 480 independent transistor-reference cases with
three enable schedules and both held and withdrawn requests (2,880 cases).
It compares handler entry time and all three stack writes across 40 arrival
phases for NOP, CLI, SEI, PLP, RTI, taken/untaken/page-crossing branches and
absolute loads/stores/RMW and PHP/PHA. This does not qualify every NMOS
interrupt subphase,
NMI hijacking or the complete external bus sequence.

The checked-in vectors come from perfect6502 commit
`09fc542877a84318291aa42dab143a3e2c3db974`, using only the original open
programs in `cores/fes-c64/sim/irq_program.h`. The normal simulation needs no
external oracle. To reproduce the vectors from that source checkout:

```sh
IRQ_ORACLE_ROOT=/absolute/path/to/perfect6502
cc -O3 -I "$IRQ_ORACLE_ROOT" cores/fes-c64/sim/irq_oracle.c \
  "$IRQ_ORACLE_ROOT/netlist_sim.c" -o /tmp/fes-c64-irq-oracle
/tmp/fes-c64-irq-oracle > /tmp/fes-c64-irq-vectors.h
cmp /tmp/fes-c64-irq-vectors.h cores/fes-c64/sim/irq_vectors.h
```

JSR performs the NMOS dummy stack read before pushing the return address,
and reads the target high byte after both pushes. A separate low-byte latch
preserves the operand across these bus cycles. This ordering matters when
C64 BA stalls a call or when an operand overlaps the stack page.
`make sim-fes-c64-jsr` checks nine transistor-reference bus cases with enable
gaps and 20 call/write timings on the actual C64 motherboard around a PAL
badline. The cases include stack wrapping, a page-crossing return address
and an operand overwritten by a stack push. Generate `jsr_vectors.h` using
the same pinned oracle checkout and `cores/fes-c64/sim/jsr_oracle.c`.

PHP/PHA fetch the following opcode after the stack write. They do not retain
the earlier dummy read as an opcode prefetch: a push can overwrite that byte,
and the next read must stall when C64 BA falls after the write. Their total
instruction length remains three CPU cycles without stalls.
`make sim-fes-c64-push` checks 24 transistor-reference bus/state cases across
enable schedules, stack wrapping, page crossing, next-opcode aliases and
SP decrement and A/P preservation, plus 40 motherboard badline timings. The independent
vectors are generated by `cores/fes-c64/sim/push_oracle.c` with the same pin.

NMI edges are retained independently of the CPU enable, then polled at the
same instruction boundaries as IRQ, including the earlier taken-branch poll.
NMI ignores I and takes priority over a simultaneously asserted IRQ.
`make sim-fes-c64-nmi` checks 14 instruction sequences over 40 arrival phases,
three enable schedules and four stimuli: held NMI, a one-cycle pulse,
simultaneous IRQ/NMI and NMI released on the first stack write. These 6,720
cases compare entry timing and pushed PC/status with the transistor model,
and check that a held NMI does not retrigger. Another 1,120 cases use a
one-system-clock pulse entirely between guest enables, with NMI low on
every enabled edge; the captured edge must survive until the reference
polling point. The sequences cover CLI/SEI/PLP/RTI, branches, RMW,
PHP/PHA/PLA and VIC register stores. The 7,840 cases use fixtures generated
from the same pinned perfect6502 source:

```sh
cc -O3 -I "$IRQ_ORACLE_ROOT" cores/fes-c64/sim/nmi_oracle.c \
  "$IRQ_ORACLE_ROOT/netlist_sim.c" -o /tmp/fes-c64-nmi-oracle
/tmp/fes-c64-nmi-oracle > /tmp/fes-c64-nmi-vectors.h
cmp /tmp/fes-c64-nmi-vectors.h cores/fes-c64/sim/nmi_vectors.h
```

Late NMI hijacking of BRK/IRQ and every physical pin subphase remain outside
this polling regression.
