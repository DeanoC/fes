# fes_i386_cpu RTL

The first-party 386-compatible CPU proposed in
[the i386 CPU design](../../../../docs/i386-cpu-design.md). This directory
holds Phase 1's slices so far: the uop format, the front end from F1 to Q,
and `fes_i386_cpu`, which runs the real-mode instructions `fes_i386_decode`
lists from D to WB, with their memory forms, fixed uop sequences, the string
instructions and ENTER, I/O on an I/O port, the microcode ROM, exception
delivery, INTR and NMI, the multiply and divide unit, and the speed
governor ([Speed governor](#speed-governor)); Phase 2's three slices,
protected mode: unreal mode, delivery through the IDT, far calls and
returns, the LDT, TR and the system-segment instructions, privilege levels
with IRET to an outer one and deliveries to an inner one, IOPL and the I/O
permission bitmap (see [Protected mode](#protected-mode)); the ESC instructions of a 386
with an empty 387 socket (see [ESC with no 387](#esc-with-no-387)); and Phase 5's first slice, paging
(see [Paging](#paging)). It reaches guest memory through an L1I,
an L1D and a bus interface on HPS DDR port 0, with an uncached path to MMIO
(see [Memory](#memory)). There is no L2 yet.

## Front end

Fetch is sequential from the last redirect except where the branch target
buffer (`fes_i386_btb`) predicts a branch taken: F2 then sends F1 to the
entry's target on the next edge, one bubble, and the fetch buffer fills its
halves alternately so the target's block follows its branch's. A RET's entry
goes to the return stack's top instead (`fes_i386_ras`), which a near CALL's
entry pushes. An indirect JMP's or CALL's entry holds the target it last
went to. Q goes on at
the target after the instruction that ends where the entry says
(`fes_i386_fetchbuf`'s `jm`, `jt` and `jx`, registered from next-cycle state
as availability is). [The design's Prediction section](../../../../docs/i386-cpu-design.md#prediction)
gives the entry, its update and the checks that make every prediction safe.
The front-end bench writes no entries, so its fetch stays sequential.
The fetch port is the L1I's way-selected output (`fes_i386_l1i`), an M10K
read with address stall: `mem_data` is the block at the address registered
on the last edge with `mem_load`, and `mem_valid` says that response is
available, which waits for a fill on a miss. F2
holds its address and does not advance until `mem_valid`; it requests the next
block on the edge that accepts the current response. Nothing decodes M10K data
in F2 (design rule 7). A redirect flushes F2, L1, L2, the buffer and Q; a
change of CS.D (`code32`) needs one.

Length decode takes two stages. L1 runs the 16 decoders on F2's register and
registers what each byte's instruction is made of: its prefix and run flags,
its opcode and fixed-immediate bytes, its ModRM, SIB and displacement bytes
for each address size, and whether a 2- or 4-byte immediate or offset
follows. The decoders see the previous block's last four bytes and then the
block, so a block's bytes 0-11 are decoded as it passes L1 and bytes 12-15
when the next sequential block does. Those four bytes come from L2's
register, since the previous block may not have reached the buffer yet. L2
adds the classes up for each of the four prefix-accumulator variants (66h
seen, 67h seen), with CS.D and the byte's own 66h or 67h folded in, into each
byte's length, end and next-half bit. L2 writes block and decode into its half
of the buffer once Q has released that half, and in that cycle Q may already
use the block's bytes from L2's register. The second stage costs one cycle
on every redirect: the first instruction issues 5 cycles after a redirect
instead of 4.

The buffer also holds, per byte and variant, whether Q may use the
instruction there: its half is valid, its bytes 12-15 are decoded if it starts
there, and the next half is valid or being filled if it ends past its own
half. It is registered from next-cycle state. A release on that edge is
ignored for the byte's own half, since Q's start has just left it; the next
half's term assumes a release whenever Q is in that half now.

Q keeps a start position and a prefix accumulator. Each cycle it either
consumes one prefix that another prefix follows, or issues the instruction at
start, whose last prefix is part of the per-byte decode. Its loop picks the
stored availability and next start by the accumulator's two flags and then by
start: a select, with no add. Measured in simulation, with D always ready:

- one instruction per cycle on every prefix-free stream, once the buffer is
  full, including streams of 8- to 11-byte instructions;
- an instruction with k prefixes issues max(1, k) cycles after the one before
  it;
- an instruction longer than 15 bytes, or a run of prefixes that reaches a
  16th byte, issues with `too_long` set, for D to raise #GP(0).

Lengths follow the oracle's decoder for every encoding it defines. The i386
raises #UD for the rest, so their length is not architectural, and D decides
#UD. MOV to and from TR6 and TR7 (0F 24, 0F 26), which the design accepts and
the oracle does not, take the CR/DR rule: ModRM is always a register form.

## D's address operands and AG

D decodes the address registers from ModRM and SIB. A SIB index of 100b with a
nonzero scale scales the base, as the 386EX does (Phase 0 divergence
`invalid-sib-scales-base`). D reads the flip-flop register file, takes each
register's youngest in-flight value from the M1, M2, EX or WB result
register, scales the index and registers AG's operands.

D's forwarding selects are worked out a cycle ahead, per GPR. Each cycle a
table records, for every GPR, where its youngest value will be next cycle
among the uops then in M1, M2, EX and WB: in a result register, or only in the
register file. It is written from the destination tags of the uops now in AG,
M1, M2 and EX. Its state as an address operand, late from M1, EX or WB, or
further off, also counts the uop now in D when it leaves D: next cycle that
uop is in AG, younger than everything in the table, and what it writes is
late from M1 if its result is early, else further off. D's cycle applies each
GPR's registered select to the result registers beside the addressing decode
and picks base and index, and whether each stalls, by register number, with
no tag compare. If the stages behind D ever hold, the table must be written
from the held producers.

A value completing in the cycle the uop leaves D arrives late, from the
register it lands in when the uop is in AG: the previous uop's early-ALU
result (M1), load data from M2 (EX) or a late-ALU result from EX (WB). At most
one late value reaches AG, entering its last 3:2 row as a base or an unscaled
index. D stalls the uop when the late value would be a scaled index, when
both operands would be late, or when a value is further off.

AG adds the segment term, D's first-row operand and the displacement in a 3:2
row from registers, then the last-row operand (D's or the late value) in a
second, then one carry chain per sum. With a 16-bit address size every operand
is zero-extended; linear bits 31:16 come from the segment's high half or that
plus one, by the carry that bits 17:16 of the two sums leave once the wrap is
removed, so only the address-size select follows the 32-bit chain.

## D to WB

`fes_i386_cpu` puts DC, D, AG, M1, M2, EX and WB behind the front end, with
the L1D's data port (`fes_i386_l1d`): M1 drives a load's address, the L1D
registers it on the edge M1 advances, as an M10K does, and the 8 bytes from
the address's dword, as memory held them on that edge, arrive in M2 once
`dmem_valid` says so. A retiring store writes its bytes on the edge it
retires, and the L1D reads before it writes on the same edge.

**Freeze.** A load in M2 whose bytes have not arrived freezes D to WB: every
stage behind DC keeps its uop, D issues nothing and nothing retires, until
they do. Nothing moves relative to anything else, so the forwarding
distances, AG's late operands, the store merge and D's forwarding tables all
hold as they are. Whether M2 holds a load is a register set as it enters, and
the L1D's `dmem_valid` is the complement of a register (`stall`, computed from
the next cycle's state; see Memory), so the freeze is one gate on two
registers; WB's flush waits for it, which makes
a taken branch or a fault in WB wait out a wrong-path load. A multiply or
divide freezes them the same way while it works in EX (`md_busy`, a register
set as the uop enters EX), and so the freeze has one more registered input
and D's issue no new term. So does an I/O access in WB, until the machine
completes it (`io_wait`, set as the uop enters WB and cleared on the
completing edge; see I/O), and an INTR being taken, until the machine returns
its vector (`int_wait`, likewise; see Interrupts), and a store in WB while
the write buffer will not have room for it (`st_wait`, set as the store enters
WB or while it waits; see Memory). Each wait is one register, so the freeze
stays one LUT of six inputs, which every stage's enable takes.
What WB does with
its uop (flush, redirect, deliver a fault) is decided as the uop enters WB, so
each of those is one gate from the freeze too.

**DC** decodes Q's output register into a two-entry buffer of decoded
instructions: `dc` holds the instruction D issues, and `dc_skid` takes Q's
instruction when `dc` cannot. Q may load its output whenever `dc_skid` is
empty, so D's stall never reaches Q's loop as `d_ready`, and everything D's
issue waits on starts from a register. The decode costs one cycle on every
redirect.

DC decodes the instruction to one uop (`fes_i386_decode`): group 1, INC,
DEC, NEG, NOT, TEST, MOV (to and from a segment register in real mode, and
immediates), LEA, the shifts and rotates, SHLD and SHRD, SETcc, MOVZX and
MOVSX, CBW/CWDE, CWD/CDQ, SAHF, LAHF, the flag set and clear instructions,
NOP, HLT, the near JMP, Jcc, LOOP, LOOPE, LOOPNE and JCXZ, MUL, IMUL (all
three forms), DIV, IDIV, AAM and AAD, BT, BTS, BTR and BTC by an immediate
or a register, BSF and BSR, DAA, DAS, AAA and AAS, the stack operations below, and the
first uops of the string instructions and ENTER, with a ModRM memory
operand wherever they take one. A memory operand is a load, a store,
or both in one uop (read-modify-write), and stands for the register it
replaces: no GPR is read or written for it. Its segment is the override, else
SS for a BP-, EBP- or ESP-based address, else DS. LOCK on anything but a
read-modify-write of ADD, OR, ADC, SBB, AND, SUB, XOR, NOT, NEG, INC, DEC,
BTS, BTR or BTC, MOV to CS or to segment register 6 or 7, LEA of a register
and C6h/C7h with reg != 0 raise #UD; over 15 bytes raises #GP(0). Every
other encoding decodes as `FAULT_UNIMPLEMENTED`, which stops the CPU at WB,
so no check can pass over one. An immediate after a ModRM's operand bytes is the instruction's last
bytes, so DC takes it from the length, beside the decode. DC also registers
the address registers and scale a memory ModRM names (`fes_i386_amode`), or
ESP (EBP for LEAVE) for a stack operation.

**Stack operations** are PUSH and POP of a GPR, an immediate (PUSH) or a
segment register, CALL rel, RET and RET imm16, LEAVE and JMP r/m. Each is one
uop with a memory operand at SS:ESP (SS:EBP for LEAVE) at the stack's width
(SS.B), except CALL rel, which is two: the push of the next EIP, then JMP rel
by the displacement the push carries in its unused immediate. A stack
operation also writes ESP: AG has a third
adder for it (ESP less the size for a push, plus it for a pop, plus imm16 for
RET imm16, EBP plus it for LEAVE), and WB writes it beside the main
destination, which wins when it is ESP too (POP ESP). A 32-bit PUSH or POP of
a segment register moves ESP by 4 and transfers the selector's word only, as
the 386EX does. RET and JMP r/m take their target from EX's adder (CS's base
plus the EIP) and redirect from WB like any taken branch; a target past CS's
limit raises #GP(0) at the branch (see D). ENTER runs on the string engine
(below).

**Fixed sequences.** An instruction of several uops, decoded without the
microcode ROM, keeps its place in `dc` while they issue: as D issues each but
the last, `dc` takes the next from `fes_i386_seq`, so every field D reads is
a register at every step and the uops issue one per cycle. Every field a
sequence rewrites is set outright at every step, from the instruction's
first uop (`dc0`, kept beside `dc`) with every change of the steps before it
applied again, and the per-step controls are reset. No field is kept from
`dc` at some steps and not others, so `dc` loads on two enables from D's
issue: the rewritten fields at every issue, the rest at the instruction's
last. WB moves EIP only at an instruction's last uop, so a sequence
that faults part way leaves EIP at the instruction. Two temporaries, T0 (16 bits) and T1
(32), are destinations in RS_TEMP: WB writes them and no forwarding sees
them, so a uop reads one at WB, or waits in D until its writers retire.

**Far pointer loads and far transfers** (real mode):
- LES, LDS, LSS, LFS and LGS load the selector's word, past the offset by
  the operand size, into T0, then the offset into the register; WB writes
  the segment from T0 as a second destination (`seg2`), which D's
  segment-busy vector follows. Each part is checked against the limit on its
  own, the selector's offset wrapped by address size, as the 386EX does.
- A far jump is one uop: AG computes its target as the new CS's base,
  selector * 16, plus the offset, and WB writes CS, the selector reaching it
  in `c`. JMP ptr16:16/32 is that alone. JMP m16:16/32 first loads the
  selector into T0 and the offset into T1, and the jump takes them once
  those have retired.
- CALL ptr and CALL m16:16/32 (after the same two loads) read the return
  address's lower slot first, a probe that checks its limit, then push CS
  in an operand-sized slot, zero-extended, and the next EIP, then jump. A
  push that would cross the stack's limit so faults before anything is
  written.
- RETF and RETF imm16 load the offset into T1 and the selector into T0
  without moving ESP; the jump steps ESP at WB, as it flushes every younger
  uop and nothing needs the new ESP sooner.
- An offset past CS's limit, the limit CS has before the transfer, as Bochs
  checks a real-mode one, raises #GP(0) before anything is written
  (`far_chk`): at a far call's probe, ahead of the probe's own check, as
  Bochs checks before it pushes; at RETF's jump and IRET's FLAGS read after
  their own reads, at M1 (`cs_late`), as Bochs pops first. CALL r/m near's
  push checks T1 the same way, after its own check.
- Far transfers are taken branches, with no prediction yet: each redirects
  from WB.

**CR0, CLTS and WAIT.** The CPU holds CR0's PE, MP, EM, TS, ET and PG,
from `init_cr0`, and reads CR0 with bits 30-5 set, as Bochs's 386 does
(`arch_cr0`). WAIT is a NOP, or raises #NM when MP and TS are both set,
which DC decodes after every other check, as the design's
[FPU](../../../../docs/i386-cpu-design.md#fpu) section asks. CLTS clears TS
at WB as a system uop that jumps to the next instruction, so every
instruction after it decodes once TS is clear, and no wait in D follows it.
The jump is not cut to 16 bits: a CLTS that ends at FFFFh leaves EIP 10000h,
as any other instruction does. The ESC instructions raise #NM when EM or TS
is set ([ESC with no 387](#esc-with-no-387)).

**ESC with no 387.** Until the x87 phase the CPU is a 386 with an empty 387
socket, as the design's [FPU](../../../../docs/i386-cpu-design.md#fpu)
section specifies. DC decodes every ModRM of D8h-DFh:
- **#NM.** An ESC instruction raises #NM when CR0.EM or CR0.TS is set
  (`esc_nm`), after LOCK's #UD and the 15-byte #GP, as WAIT raises it when
  MP and TS are both set.
- **Stores of all ones.** FNSTSW m16 and FNSTCW store FFFFh, one uop each,
  and FNSTSW AX (DF E0) moves FFFFh into AX. FNSTENV and FNSAVE store the
  control word's all ones at the operand in DC's uop, then the ROM the rest
  of the 387's 16- or 32-bit layout by the operand size: the status and tag
  words' all ones, then the instruction pointer's offset and selector words
  and the data pointer's, each an operand-sized field (`SYS_RD_ONES`,
  `SYS_RD_FIP` to `SYS_RD_FDS`, through `b_sys`), in Bochs's order. FNSAVE
  then stores the eight registers' 80 bytes as all ones, a dword at a time.
  Each store checks its own limit, so one that faults leaves the fields
  before it written; each field's offset wraps by address size, as Bochs's
  do.
- **Reads, discarded.** FLDCW loads its word; FLDENV and FRSTOR load every
  field of the layout and FRSTOR the registers' 80 bytes, a dword at a time;
  FLD, FILD, FBLD and the arithmetic forms load their operand, a word or
  dword in one uop, and an 8- or 10-byte one from its highest part down
  (`frd8`, `frd10`: the dword at 4, or the word at 8 and the dword at 4,
  then the dword at 0). None writes a register. Each part is checked against
  the limit on its own, wrapped by address size.
- **No access.** FST, FSTP, FIST and FISTP of every size, FBSTP and the
  reserved memory forms (D9 /1, DB /1, /4 and /6, DD /1 and /5, DF /1)
  access nothing and check nothing: the operand's offset goes to AG as
  LEA's does, for the data pointer. The design measured FST and FIST and
  leaves FBSTP uncharacterized; this build gives FBSTP and the reserved
  forms FST's behaviour, a choice: each is a store the 387 would make, and
  the absent 387 never asks for the transfer.
- **Register forms** do nothing: FNINIT, FNCLEX, FENI, FDISI and FSETPM
  (DB E0-E4) are NOPs, and every other register form a NOP that writes the
  instruction pointer.
- **The ROM's addresses.** A word's `fpn` and `fpj` put its memory operand
  `fpn` operand-sized fields and `fpj` dwords past the ModRM operand; `seq`
  sums them into `dc.moff`, as it does LGDT's and SGDT's 2 (`plus2`), and D
  adds `moff` to the displacement, wrapped by address size.
- **Performance** does not matter here: no software uses the forms beyond
  detecting the coprocessor. A uop that reads the x87 pointers waits in D
  for every older uop that writes them to retire, as `t_rd` waits for T0 and
  T1.

**x87 pointers.** The 386 keeps the instruction and data pointers for its
coprocessor, and FNSTENV and FNSAVE store them even with no 387. The CPU
holds them in flip-flops (`fpu_ip`, `fpu_cs`, `fpu_dp`, `fpu_ds`), cleared
at reset, with the real-mode layouts' linear forms beside them (`fpu_lip`,
`fpu_ldp`: the selector times 16 plus the offset, a sum WB makes from
registers).
- **Who writes them.** An ESC instruction's last uop writes them as it
  retires (`x87p`): its CS selector and EIP (the instruction's first byte,
  prefixes included), and for a memory form the operand's segment selector
  and offset (16 bits under a 16-bit address size). The 387's control
  forms write nothing: FNINIT, FNCLEX, FENI, FDISI, FSETPM, FNSTSW, FNSTCW,
  FLDCW, FNSTENV, FLDENV, FNSAVE and FRSTOR. This is Bochs's partition
  (`FPU_update_last_instruction`), which follows Intel's. A form that faults
  writes nothing.
- **What this build chooses.** The design says FNINIT does nothing and
  FLDENV and FRSTOR read and discard, so FNINIT and FNSAVE leave the
  pointers and FLDENV and FRSTOR load nothing into them, where Bochs's 387
  clears or loads them.
- **The layouts.** Bochs's, with the 387's fields all ones: the control,
  status and tag words; the opcode; the 32-bit layouts' reserved halves.
  In protected mode (CR0.PE) the pointer words are the offset, then
  07FFh:selector (32-bit: the opcode's 11 ones above the selector), the data
  offset, then FFFFh:selector. In real mode they are FFFFh:the linear
  address's low half, then the linear address's bits 31-16 at 27-12 with
  the opcode's ones in 10-0 (16-bit: bits 19-16 at 15-12), and the data
  pointer's likewise without the opcode. A 16-bit layout stores each word's
  low half.

**Control and table registers** (any mode, CPL 0):
- MOV r32, CRn (CR0, CR2, CR3) and SMSW are an ALU move of the register,
  which D reads as src2's value (`b_sys`): SMSW gives a 16-bit register
  CR0's low word, a 32-bit one all of it, and memory a word, as Bochs does.
  CR1 and CR4-CR7 are #UD; the ModRM is a register form whatever its mod.
- MOV CRn, r32 and LMSW put their source in T1; a system uop from the ROM
  writes the register at WB from T1 and jumps to the next instruction, so
  the pipeline behind it refetches and DC decodes it under the new CR0. LMSW
  writes PE, MP, EM and TS and cannot clear PE. D raises #GP(0) for a CR0
  with PG set and PE clear; one that sets PE and PG together, from real
  mode, is a write like any other (32RTM's loader makes it). CR2 holds what
  is written and a #PF's linear address, and CR3 the page directory (see
  [Paging](#paging)).
- LGDT and LIDT load the limit's word into T0 and the base's dword, 2 bytes
  on (`plus2`), into T1, both checked before the system uop writes the
  register and jumps to the next instruction; a 16-bit operand size clears
  the base's top byte. SGDT and SIDT store the limit's word and the whole
  base, 2 bytes on, whatever the operand size, as Bochs does. GDTR's limit
  less 7 and IDTR's less 3 are kept beside them for the descriptor and
  vector checks.
- Real-mode interrupts and exceptions read their vector at IDTR's base plus
  vector × 4; an entry past IDTR's limit raises #GP(0), which a delivery
  takes as a fault in a delivery (below).

**Small forms:**
- XCHG of registers is three XORs that write no flags, each into the
  register the one before read; EX's arithmetic and logic flag selects
  follow the uop's flag-write bits. XCHG with memory loads the operand into
  T1, stores the register, then moves T1 into the register.
- MOV with a direct offset (A0h-A3h) is a memory operand with no base or
  index (`direct`). XLAT's index is AL zero-extended, which D's address
  forwarding masks (`index8`), holding the uop when AL would come late.
  SALC is SBB AL, AL writing no flags.
- CALL r/m near loads its target into T1, pushes the next EIP after checking
  T1 against CS's limit, then jumps to T1. PUSH m loads into T1 and pushes
  it. POP m reads the stack's slot into T1 without moving ESP, stores T1 to
  the operand, whose address registers DC kept beside the stack uop's
  (`m_*`), then pops into nothing to step ESP, so a store that faults leaves
  ESP as the 386EX does. A 32-bit address that reads ESP, as a base or as
  the 386EX's scaled base of an invalid SIB, reads it after the pop, which
  has not happened yet. The store waits for T1, so every older uop has
  retired and ESP is the register file's: D adds the operand size, scaled
  as ESP is, to the store's displacement (`esp_adj`), less 10000h so scaled
  (`esp_wrap`) when a 16-bit stack's SP wraps from its top slot to 0.

**Strings and ENTER** run on the string engine, as the design's string
sequencer describes. While one runs, D keeps copies of the next source and
destination offsets and of the count. Each step's address is a copy, which
the step moves on, so the uops issue from `dc` without waiting on
forwarding, and an offset wraps at its address's width.
- **The first uop** of MOVS, CMPS, STOS, LODS or SCAS is a NOP that loads the
  copies from ESI, EDI and ECX (CX by address size). It waits until they are
  in registers, until no older uop that writes DF is in AG to EX, and until
  neither its segment nor ES is being written. Its registers are fixed, so
  it reads each one's value and pending bit from D's forwarding directly,
  with no select by register number. Then the string runs:
  - one element per count under REP (F2h or F3h), else one;
  - a REP with a count of 0 is a NOP that ends the instruction;
  - each element steps by its bytes, down when DF is set.
- **The first element is built without the count**, which is still on its
  way into the copy when `fes_i386_seq` builds it. The first uop latches
  whether that element ends the instruction (a count of 0, or 1 but for
  CMPS) and whether it is the NOP (0). D then issues it as the last, or as
  the NOP, which writes nothing D tracks. Beside the copy of the count, D
  keeps whether it is 0, 1 or 2, which `fes_i386_seq` reads.
- **The elements.**
  - STOS is a store of eAX at ES:EDI, LODS a load of eAX from seg:ESI, and
    SCAS a compare of eAX with ES:EDI.
  - MOVS is one uop. It loads seg:ESI, then stores the value at ES:EDI, an
    address D computes and checks against ES's limit (`st2`). M1 raises that
    fault after the load's own.
  - CMPS is two: seg:ESI's value as a uop's result, then its compare with
    ES:EDI. The compare takes that result one stage ahead, since D issues
    it in the next cycle: nothing it waits on can change in between.
- **Each element's last uop** steps ESI, EDI and ECX at WB. A fault part way
  leaves them at the elements done, with EIP at the instruction, so no
  forwarding sees the steps. A uop that reads ESI, EDI or ECX waits in D
  while a string element that steps it is in AG to WB. Which of them a uop
  reads is decoded into `dc` (`rd_str`), so that wait is one AND.
- **REPE and REPNE** (F3h and F2h) CMPS and SCAS issue elements ahead of the
  flag result. An element but the last ends the instruction when its
  compare's ZF says so. It does that as a taken branch to the next
  instruction, whose address the first uop keeps, so WB flushes the
  elements behind it.
- **ENTER** uses the same copies.
  - Its first uop is the push of EBP at SS:ESP less the size, ESP unmoved.
    It loads the source copy (EBP less the size), the destination copy (ESP
    less twice the size) and the frame pointer (ESP less the size, its high
    half ESP's on a 16-bit stack).
  - Then come the level's (mod 32) less one copies of a slot below EBP to the
    next push slot, each one uop as a MOVS element, and the push of the
    frame pointer unless the level is 0.
  - The last uop writes EBP from the frame pointer and ESP from the next
    push slot plus the size less imm16, and checks the slot at that ESP, as
    the 386EX does.
  - ESP and EBP change only there, so a fault before it leaves them, with
    the pushes before it written.
- **Rates, without latency:** REP MOVS, STOS, LODS and SCAS issue an element
  a cycle, and REP CMPS one in two. ENTER is 2 uops at level 0, 3 at level 1
  and the level plus 2 above, and a load waits a cycle behind its push of
  EBP and of the frame pointer.

**I/O.** IN and OUT, with an imm8 or DX port, and INS and OUTS make their
access at WB, never speculatively, on the I/O port.
- **The access.** The uop in WB raises `io_req` with `io_port`, `io_size`
  and, for OUT, `io_wdata`: eAX, or OUTS's loaded value. D to WB freeze until
  the machine answers with `io_ack`, IN's data in `io_rdata`, and the uop
  retires on the edge after. A uop that enters WB with a fault makes no
  access, so INS's store and OUTS's load fault first, as on the 386.
- **The data.** IN merges the port's data into eAX by size at WB. INS stores
  it at ES:EDI as a STOS element would; OUTS loads seg:ESI as LODS does.
- **What follows waits.** Nothing younger issues until an I/O instruction
  has retired (`io_busy`, as `t_busy`): no load reads memory an OUT may
  remap, and no uop reads IN's data before the register file holds it. A
  REP INS or OUTS's own elements still issue back to back, each waiting in
  WB for its access; the next instruction's first uop waits.
- **The port and data registers** are used at WB, from the uop's record. EX
  takes one that its producer, one stage ahead, has just computed from the
  WB register into the record, as EX's own operands come.
- Real mode has no I/O permission check, and there is no write buffer yet:
  every older store has written when the access is made.
- **Rates, without latency, with an ack in the cycle the request rises:**
  REP INS and OUTS take 2 cycles an element. An IN or OUT takes 6 more
  than a NOP, mostly the next instruction's wait to issue.

**Interrupts.** INTR and NMI are taken at instruction boundaries, as the
design's commit rules ask, and between a REP string's elements.
- **When.** On the edge an instruction's last uop retires, a delivery's
  included, or a REP string element's (the one that steps ECX,
  `str_cx`), or while the CPU is in HLT.
  - NMI comes first, unless one is being handled: an NMI blocks the next
    until IRET's last uop retires (the microcode word's `iret` bit).
  - INTR is taken if IF is set after the instruction.
  - Neither is taken after MOV SS or POP SS, unless that one follows
    another, nor after an STI that set IF: the shadow, as Bochs keeps it.
    LSS has none. Before a REP string the shadow ends with its first
    element, since Bochs counts an iteration as an instruction.
- **How.** The decision is a register, `int_take`, from that edge.
  - An INTR first asks the machine for its vector: `inta_req` until
    `inta_ack`, with D to WB frozen.
  - Then WB flushes, as for a fault. The uop in WB, the next instruction's,
    neither retires, stores nor makes an I/O access, and EX's running flags
    go back to EFLAGS.
  - DC takes the vector routine's entry with D's EIP the next instruction's,
    so the routine pushes it. An NMI's vector is 2.
  - Between a REP string's elements that EIP is the string's own, since WB
    moves EIP only as an instruction ends. The elements done have stepped
    ESI, EDI and ECX, so IRET returns to the string, which runs on from
    there. The uop in WB, the next element's, is discarded with the rest.
- **HLT** waits for an interrupt now. `trace_halt` is HLT or the stop for
  good, which `trace_unimplemented` tells apart. A HLT that retires with an
  interrupt pending takes it at once.
- **Not built yet:** the debug traps.

**Microcode.** Longer routines come from an M10K ROM
(`fes_i386_ucode_rom`). `scripts/fes_i386_ucode.py` builds it from
`ucode.toml`, with the entry addresses in `fes_i386_ucode_pkg`, checking
every field and routine.
- **Words.** A word is a `ucode_t`: the uop fields a routine sets. The
  operand size, the vector and the memory operand come from the instruction
  in `dc`. A word's memory operand is a stack slot, the vector's entry, or
  the instruction's ModRM operand (`rm`); its registers are GPRs, or the
  instruction's register (`rg`), which DC's first uop carries in src1.
- **Issue.** DC decodes a routine's first uop, and `dc.upc` addresses the
  next word. Each later uop is a `SEQ_UCODE` step of the sequencer, so `dc`'s
  input select keeps its three sources.
  - The ROM's address is a register and its output is registered, so a word
    is there the cycle after `dc` settles. D waits a cycle for each
    (`rom_ok`, `uc_wait`), with `issue` kept off the M10K's pins.
  - Routines are straight sequences. INTO's JNO, a branch that ends the
    instruction only when taken, is the one microbranch, resolved at EX.
- **Stack slots.** A `STK_PEEK` uop reads or writes the slot at ESP plus a
  signed number of operand-sized slots, -8 to 7, without moving ESP. One
  that also writes ESP steps it past eight slots, down from a slot below ESP
  and up from one above.
- **INT's probe.** INT starts with a probe of its three slots. Under SS's
  real-mode limit, FFFFh, a slot faults only by straddling the 64 KiB wrap,
  which one does when they wrap at an odd offset. M1 flags that (`pbad`), and
  M2 raises #SS(0) from the register, before INT writes anything. Under any
  other SS limit INT is unimplemented. EX then checks the vector's offset,
  in T1, against CS's limit (the limit CS has before the jump, as Bochs's
  `real_mode_int` checks it after its pushes): T1's load, two uops ahead,
  has retired by then.
- **The routines:**
  - PUSHA and PUSHAD store each register in its own slot below ESP, from the
    lowest address up, ESP's being the unmoved original, and step ESP at the
    last. Each slot checks its own limit, so a block that wraps the stack
    misaligned stores the slots below the one that straddles and then raises
    #SS(0), ESP unmoved, as the 386EX does.
  - POPA and POPAD load each slot from ESP up the same way, ESP's into T1.
    POPAD on a 16-bit stack takes ESP's high word from it, as the 386EX does.
  - INT n, INT3 and INTO read the vector's entry first, at linear vector × 4,
    as the 386EX does. Then they push FLAGS, clearing IF and TF, CS and IP,
    and jump.
  - IRET reads its three slots, the FLAGS load (IRETD's RF too) checking the
    offset first, then jumps, stepping ESP at WB.
  - BOUND loads its upper bound, past the lower by the operand size and
    wrapped by address size, into T1, then compares the register with the
    lower bound, which it loads, and T1 with the register. Each compare
    raises #BR (vector 5) from EX's adder when its first operand is below
    its second, signed, at the operand size, and writes no flag. Both
    bounds load, and check their limits, before either compare, as the
    386EX does: a bound past the limit raises #GP(0) or #SS(0) whatever
    the register. A register operand is #UD.
  - `wcr0`, `wcr2`, `wcr3` and `lmsw`: the CR write from T1, a jump to the
    next instruction; `lgdt` and `lidt`: the base into T1, then the table
    register's write; `sgdt` and `sidt`: the base's store.
  - `pseg`, `ppop`, `plptr`, `pjmp` and `pjmpm`: protected-mode segment
    loads and far jumps; `pvec` and `pint`, the delivery through the IDT;
    `piret`, `pretf`, `pcall` and `pcallm`; `plldt`, `pltr`, `plar`,
    `plsl`, `pverr`, `pverw`, `parplr` and `parplm` (see
    [Protected mode](#protected-mode)).
  - `fnstenv`, `fnsave`, `fldenv`, `frstor`, `frd8` and `frd10`: the ESC
    forms with no 387 that take more than one uop
    ([ESC with no 387](#esc-with-no-387)).
- **Flags in EX.** PUSHF and POPF are single uops. EX's flag operations give
  FLAGS' image and load the writable real-mode flags in its running copy, as
  INT's and IRET's do.

**Multiply and divide** (`fes_i386_muldiv`) work in EX while D to WB
freeze, from EX's operands, which stay put meanwhile. Only registers lie
between the unit and EX:
- in its first cycle it makes its operands from what EX makes them of
  (EX's src1 and y registers, WB's result, the load, the bypass selects),
  bypassed and at the uop's size, and registers them with the uop's decode,
  so nothing of EX's logic drives it and the DSPs start from registers;
- in its last cycle it writes its result, merged into the destination's old
  value and registered by the cycle before, into the uop's record, which EX
  passes through LEA's select, and a divide error into the record's fault;
- the uop leaves on the cycle after with the unit's flags, which EX's flag
  logic takes off the adder's path.
- **Forms.** MUL and IMUL of AL or eAX by r/m, IMUL r, r/m and r, r/m, imm
  (whose multiplicand is src2 and multiplier imm), DIV and IDIV of AX,
  DX:AX or EDX:EAX by r/m, AAM and AAD. A 16- or 32-bit MUL writes EAX and
  keeps the high half, which a HI uop after it writes into EDX
  (`SEQ_MUL`). A 16- or 32-bit DIV first hands the unit EDX in a LOAD uop,
  which carries the divide's op in imm and reads the memory operand too, so
  a fault on it comes before anything is written; then the divide writes
  EAX and HI the remainder into EDX (`SEQ_DIV`). HI takes the kept half
  into its record as it leaves M2, and EX's lanes merge it.
- **Multiply.** The operands, registered (E0), four 18x18 DSP products of
  the 33-bit operands (E1), their sum as a 3:2 row and one carry chain
  (E2), the result halves and CF/OF (E3), and the undefined flags (E4): 5
  cycles.
  The 386EX multiplies a bit per cycle, right to left, and stops once the
  multiplier's remaining bits are all zeros, or all ones for a negative
  IMUL multiplier; SF, ZF, AF and PF are its last step's, which come out of
  the product shifted right by that step. AAD multiplies AH by imm, then
  adds AL with the ADD's flags.
- **Divide.** Restoring, a bit per cycle, as the 386EX's microcode, whose
  flags are its last step's trial subtract at the operand size. DIV first
  compares the dividend's high half with the divisor; if it is not below,
  the quotient overflows, and the 386EX keeps the subtract and takes one
  step fewer, so the flags a divide error pushes are those steps'. IDIV
  divides a negative dividend's one's complement by the divisor's magnitude,
  adds the one the complement owes and checks the quotient for its sign's
  range. On an overflowing dividend the steps leave a garbage quotient that
  now and then passes, as the 386EX's does (8-bit quotients of 80h).
  Its flags are those of the remainder's sign fix. The unit works 36 cycles
  on DIV r/m32 and 37 on IDIV r/m32, 12 and 13 on a byte (one fewer for a
  DIV that overflows). AAM divides AL by imm.
- **#DE.** A divisor of zero or an overflowing quotient raises `FAULT_DE`
  in EX, delivered at WB as vector 0 like any other fault, with the flags
  the divide changed.
- **The wait.** `md_busy` is set as the uop enters EX and clears in the
  unit's last cycle. A flush waiting in WB cuts it after a cycle, since the
  uop behind it is on the wrong path. The uop in WB waits out a multiply or
  divide too, so its retirement shows the wait.

**D** keeps the instruction's EIP with an incrementer. In 16-bit code EIP is
not cut to 16 bits, as on the 386 and in Bochs: an instruction that ends at
offset FFFFh leaves EIP 10000h, which faults next under a 64 KiB limit and
runs on under a larger one. An instruction that starts or runs past CS's
limit raises #GP(0) at its fetch, at its first byte, before any fault its
decode found, as Bochs's prefetch does, under any limit and in either mode:
D compares EIP plus the length with the limit plus one (`cs_gp`), which a
delivery's entry at length 0 passes at the EIP of an instruction that starts
just past the limit. The compare is split at bit 4 so it runs beside the
incrementer: the low nibble plus the length carries at most 1 into EIP's
upper 28 bits, which are compared with the limit plus one's upper bits and
those less 1, registered as CS is written (`cs_fl`). A near branch, call or
return whose target is past the limit raises #GP(0) at the branch, as
Bochs's `branch_near` does, only when it is taken: AG, M1 and EX check it
(below). Real-mode CS loads set CS's limit to FFFFh. D also picks the memory operand's access check (`seg_chk_t`): its
segment's limit less the access's bytes but one, or an expand-down
segment's upper bound so less and its limit below, and whether the segment
refuses the read or the write.

The uop's src1 is always its destination's register: a byte or word result
merges into the old value, an implicit source. src2 is the second register
or the immediate; a CL count is a third source. D reads all three from the
register file or the M1, M2, EX and WB result registers (`fes_i386_dops`),
with selects worked out a cycle ahead per GPR as `fes_i386_dfwd` does for
addresses. A data operand never stalls D: if its producer has not computed it,
the operand is pending and records how far ahead the producer is (1-4
stages). No stage behind D holds, so the producer reaches WB when the uop is
that many stages before WB, and the uop takes the WB result register there:
AG, M1 or M2 into its next pipeline register, or EX beside its operand, which
is EX's only forwarding mux. A late result reaches the next uop's ALU with no
bubble. LEA's offset is early when the destination is 32-bit and comes from
AG; a 16-bit LEA merges at EX like any other result. `fes_i386_dfwd` gives
a memory operand's or LEA's address operands and its stalls as before. Both
tables follow ESP from a stack operation as an early result from AG, so a
push or pop right after another takes its address with no wait. ESP read as
data waits in D while a stack operation is in AG (its value reaches the M1
register next cycle), and LEAVE on a 16-bit stack waits until ESP's high
half, which it keeps, is in a register. A
selector read (MOV r/m, Sreg), and a memory operand for its segment's base,
waits in D while an older uop writes that segment register; a register of
the segments in flight makes each wait one select. A load waits one cycle
behind a store, whose data EX computes in the cycle the load would be in M2.
The waits behind the uop in AG (behind a store, a shift, a stack operation
that writes ESP) read what that uop is from bits registered as it enters AG.
A MOVS element's store does not hold the load behind it: its data is its own
load, which is in EX when that load is in M2.

**AG** runs `fes_i386_agu` for a memory operand's linear address and offset,
for LEA's offset, or for a branch's target: CS.base + EIP + length +
displacement in one carry chain, wrapped by operand size. For CALL rel's
push, a fourth chain beside them gives the call's target, the next EIP plus
the displacement, wrapped by operand size (`ag_call`).

**M1** checks the segment limit with one compare, the offset against D's
limit, raising #SS(0) for SS and #GP(0) otherwise, and sends a load's address
to the data port. It checks a near branch's target, or CALL rel's push's,
against CS's limit (`tchk`): the push raises #GP(0) here, after its own
checks, as Bochs pushes before it checks; a branch carries the result to EX.
A far transfer's offset that D found past the limit (`cs_late`) raises
#GP(0) here when the uop's own checks pass. It also takes the load's distance from the stores in EX and
WB, which have not written when the port reads: the one in EX will be in WB
when the load is in M2, and the one in WB writes on the edge the port reads.

**M2** aligns the 8 loaded bytes to the access and takes each byte an older
store writes from that store: a MOVS element's store in EX first (its loaded
value, `pipe_t` ld), then the store in WB, then the one that retired on the
read edge. M1 takes each distance between physical addresses, so a store and
a load through two aliases of a byte (A20M, the reset alias) meet, and only
a store's bytes that write RAM are taken (`ram_bytes`, worked out as the
store is in EX, or in M2 for a MOVS element's): read-only RAM and holes drop
the store, and a device answers for itself. EX takes the value through its
bypass selects, the ones a WB result uses, so EX's front stays one LUT
level.

**EX** (`fes_i386_ex`) takes its selects registered: M2 decodes them from
the uop (`fes_i386_exctl`), so no opcode compare sits on EX's data paths. A
branch whose target is past CS's limit raises #GP(0) here and does not
redirect: RET's and JMP r/m's from EX's operand, a taken one by a
displacement from M1's check. M2
also prepares the operands: x and y cut to the operation's size with a high
byte moved down, y inverted for a subtract, and an add's operands filled
above its size so that its carry out is the chain's bit 32 at every size. An
operand whose producer is one stage ahead joins x or y from the WB result
register in one LUT level. EX has one adder for ADD, ADC, SUB, SBB, CMP, INC,
DEC, NEG and LOOP's count, with ZF from the operands, and beside it a second
chain whose carry out is the carry into the size's top bit, for OF and SF;
the logic unit; the funnel shifter (`fes_i386_shift`); and the result's
merge into the destination's old value by lane, so WB writes whole
registers. It keeps a running EFLAGS: every uop that passes EX updates it,
so Jcc, SETcc, ADC, SBB and RCL/RCR read it with no forwarding. A shift's
flags reach it a cycle late, from the WB register: WB takes CF and OF from
the result and the shifter bits EX keeps beside it (`fes_i386_shflags`), and
D holds a flag reader one cycle behind a shift. Undefined flags follow the
386EX (the Phase 0 divergence list): logic ops clear AF, shifts by a nonzero
count set it, and the shift OF and wide-count CF rules are in
`fes_i386_shflags`.

**Bit test and scan.** BT, BTS, BTR and BTC number their bit by the
shifter's count: the immediate, or the register with its bypass from WB, as
a shift's CL. EX builds the bit's one-hot mask after that bypass, mod the
size, and sets, clears or flips the bit for BTS, BTR and BTC. CF is the bit.
The 386EX writes OF as the two bits below it XORed, mod the size, and leaves
SF, ZF, AF and PF. LOCK is valid on BTS, BTR and BTC with a memory operand.
- **By a register, with a memory operand** (`SEQ_BTM`), the address moves by
  the register: (n >> 4) * 2 or (n >> 5) * 4, signed, added to the operand's
  offset and wrapped by address size, as Bochs and the 386EX do. AG has no
  fifth term for it, so three uops fold it into the displacement through T1:
  - the displacement into T1, from the register (`ALU_BITDISP`, wiring in EX);
  - T1 plus the operand's displacement into T1, an ADD;
  - the bit test at the operand's address with T1 as its displacement
    (`disp_t1`), through `far_off`, which already takes a far jump's offset
    from T1. AG wraps the offset by address size.
  No other path from T1 into D's AG registers is added: two that a first
  version had cost about 4 MHz on nextpnr.
  Each waits for the T1 before it to retire, behind one register (`t_rd`):
  about 12 cycles more than a bit test by an immediate, without latency, on
  a form game code rarely runs.

BSF and BSR scan y for its lowest or highest set bit in EX; a source of 0
sets ZF and keeps the destination. Their other flags are the 386EX's, which
`fes_i386_ex` lists, fitted to every SingleStepTests state of the two
opcodes.

**Decimal and ASCII adjusts.** DAA, DAS, AAA and AAS adjust AL in EX by AF
and, for DAA and DAS, CF, read from EX's running copy, so D holds them behind
a shift as flag readers. Each adds 6 to AL, or takes it away, when AL's low
digit is above 9 or AF is set, and DAA and DAS 60h when AL is above 99h or
CF is set; AAA and AAS carry into AH and keep AL's low digit. Each digit's
sum is a table and the compares are spelled out, so the adjust adds no carry
chain to EX. The flags the manual leaves undefined are the 386EX's:
SF, ZF and PF of the byte the add or subtract makes, before AAA and AAS clear
its high digit, and OF its signed overflow, fitted to every SingleStepTests
state of the four opcodes. Their flags take the multiply unit's select in EX.

**Branches** are predicted not taken. EX resolves them; a taken one redirects
F1 from WB, where every younger uop is flushed, and clears D's forwarding
tables. A fault, an unimplemented encoding or HLT stops D issuing after it.
At WB an unimplemented encoding stops the CPU with nothing retired, and HLT
retires and stops it. A fault is delivered:
- **Entry.** WB flushes everything younger and restarts the front end and
  DC. A fault detected before EX changes no flags there, so its delivery
  starts with the earlier EFLAGS. A divide raises #DE in EX after its
  multiply/divide flags reach EX's running copy, so its delivery pushes those
  flags, as the 386EX does; BOUND's #BR comes from EX too. The cycle after,
  DC's skid takes the exception's entry (`dc_exc`): a NOP, at length 0,
  that starts the ROM's `vector` routine with the fault's vector, the one
  INTO enters.
- **The frame.** D's EIP identifies the faulting instruction's first byte.
  Every real-mode exception or external-interrupt delivery redirect
  zero-extends EIP's low 16-bit IP before entry. Protected-mode deliveries
  keep the full EIP. The front end refetches from where it was, and the
  routine's far jump discards that. Protected-mode delivery goes through the
  IDT (see [Protected mode](#protected-mode)).
- **A fault in a delivery** is delivered in its place, as Bochs's
  `exception()` does: with EXT (bit 0) set in its error code, or as a double
  fault (vector 8, error code 0) when the delivery's exception and it are
  both contributory (#DE, #NP, #SS, #GP); a fault in a double fault's
  delivery shuts the CPU down (`shutdown`, held until reset, which the
  machine turns into a CPU reset as an AT does). An INT n, INT3 or INTO is
  an instruction, not a delivery: a fault in its routine is a first one,
  with EXT clear, and pushes its own EIP. In real mode the nested case is a
  stack that straddles the 64 KiB wrap at SP 1, 3 or 5, which faults again
  however the delivery is retried, and so ends in shutdown. WB decides as
  the uop enters it: `wb_nested` (a delivery is under way), `wb_df` and
  `wb_shut`, so nothing new sits on the freeze's path.
- The delivery's last uop retires with `trace_exception`.

**WB** commits in order: the GPR file and segment registers in flip-flops,
a string element's steps of ESI, EDI and ECX, EFLAGS, EIP and stores, the result's low bytes moved to the address's place
in its dword and the next (IN's data for INS), and I/O accesses. A real-mode segment load sets the base to selector * 16 and
keeps the limit and type, setting P and S, except a CS load, which takes
the 386's real-mode values (limit FFFFh, access rights 93h); a
protected-mode load takes the descriptor (see Protected mode).

**Reset and trace.** `init_*` is the architectural state reset loads,
CR0, CR2, CR3, GDTR, IDTR, LDTR and TR among it; a machine ties it to the
386 reset state, and the lockstep harness to a test's state. `trace_*` and `arch_*`
show each retirement.

## Protected mode

Phase 2's three slices, and Phase 5's call gates and debug registers:
protected mode with privilege levels, without task gates, task switches,
breakpoints or V86 (the design's
[segment-cache contract](../../../../docs/i386-cpu-design.md#architecture);
[Paging](#paging) is below).
CR0.PE is a register that only a CR0 write changes, which jumps to the next
instruction, so DC decodes with it (`pe`) and every stage sees one mode.

- **Segment loads.** In protected mode MOV Sreg, POP Sreg and LES and its
  kin load DS, ES, FS, GS and SS from the GDT or the LDT in microcode
  (`ucode.toml`'s `pseg`, `ppop` and `plptr`): DC's first uop puts the
  selector in T0 (POP's slot read without moving ESP, LES's selector past
  the offset); the ROM reads the descriptor's dwords into T2 and T3 at its
  table's base plus the index times 8 (`desc`: the first checks the index
  against the table's limit less 7, #GP(selector)); then one uop raises the
  descriptor's checks (`segchk`, in M1) and stores the access byte with the
  accessed bit set, which D drops when the bit is set already, and WB writes
  the segment from the descriptor (`seg2_pm`). A null selector reads
  nothing and loads a null cache (base and limit 0, access rights 10h, not
  present). LES's offset goes into T1 and the register after the load;
  POP's ESP steps last (`nochk`: no access and no check), at the width SS
  had for the read, as Bochs pops before it loads. A TI=1 selector reads the
  LDT at LDTR's base, checked against its limit less 7 (`ldt_lim7`); with
  LDTR not valid (after a null LLDT) it fails that check, #GP(selector).
- **The checks,** from Bochs's `load_seg_reg`: for DS, ES, FS and GS a
  system descriptor or execute-only code, or data or non-conforming code
  with DPL below CPL or RPL, is #GP(selector), and not present
  #NP(selector); for SS a null selector is #GP(0), RPL or DPL not CPL, a
  system descriptor, code or read-only data #GP(selector), and not present
  #SS(selector).
- **Far JMP** (`pjmp`, `pjmpm`) puts the selector in T0 and the offset in T1,
  reads the descriptor and raises `jump_protected`'s checks: null is #GP(0);
  a TSS, task gate or call gate with DPL at least CPL and RPL is not built;
  any other system descriptor or data is #GP(selector), as is
  non-conforming code with DPL not CPL or RPL above CPL, or conforming code
  with DPL above CPL; not present is #NP(selector); an offset past the new
  limit #GP(0). The accessed bit's store comes after them all, then the
  jump writes CS (RPL the CPL) and jumps to the descriptor's base plus the
  offset, which AG adds from T2 and T3.
- **Far CALL** (`pcall`, `pcallm`) reads the descriptor and raises
  `call_protected`'s checks (`segchk` call), which WB holds (`hold`): a
  code segment as the far JMP's checks it but the offset, or a call gate
  (Call gates, under Privilege transitions below); a system descriptor with
  DPL below CPL or RPL is #GP(selector), a call gate not present
  #NP(selector), a TSS or task gate not built, any other #GP(selector). To
  a code segment (`xc` direct): a probe of each of its two slots
  (`STK_PROBE` with a slot), then the offset against the held limit with
  the accessed bit's store (`hoff`, `hacc`), then CS and the next EIP in
  operand-sized slots below ESP and the jump, which writes CS from the hold
  and steps ESP past them (`STK_RETF` by its slot); that jump ends the
  routine (`xend`). Bochs pushes before its
  offset check, so where the offset faults the RTL writes less, as the
  386EX's far CALL does. On a 16-bit stack Bochs addresses the slots at SP
  less their place without the 64 KiB wrap (`write_new_stack_*`): `nwrap`
  makes M1 raise #SS(0) for a slot that wraps (`sdisp`, its displacement),
  or stop as not built under a limit past 64 KiB, whose address this build
  does not form.
- **RETF and IRET** (`pretf`, `piret`): the slots in Bochs's order, from the
  top, so a frame past the stack's limit raises #SS(0) before any read: DC
  reads IRET's EFLAGS slot into T4 or RETF's CS slot into T0, the ROM CS's
  into T0 (IRET) and the offset's into T1, each at SP plus its slot without
  the wrap on a 16-bit stack (`nwrap`), then the descriptor and
  `return_protected`'s and `iret_protected`'s checks with the offset's: null
  is #GP(0); RPL below CPL, system or data, non-conforming code with DPL not
  RPL or conforming with DPL above it, #GP(selector); not present
  #NP(selector), each held with xp for RPL above CPL, a return to an outer
  privilege (Privilege transitions below); an offset past the held limit
  #GP(0). RETF to the same privilege ends at its own jump (`xend`), which
  steps ESP past the slots and imm16 (`iimm`, the instruction's
  immediate). IRET loads the flags from T4 first:
  IRETD's RF too (FLAG_LOAD_RF, as real-mode IRETD does); an IRETD image with
  VM set returns to V86 mode, not built (`vmchk`, raised in EX from DC's
  load, under NT's check).
- **Delivery through the IDT** (`pvec`, `pint`): an exception's, INTR's or
  NMI's entry starts `pvec` (DC's `dc_exc` in protected mode), and INT n
  and INT3 start `pint`, DC reading the gate's low dword; INTO's JNO falls
  into `pvec`. The gate's dwords into T1 and T3 at IDTR's base plus the
  vector times 8, the first checked against IDTR's limit less 7
  (`idt_lim7`), #GP with the IDT entry (`FAULT_GP_IDT`, error code
  vector × 8 + 2); then `SYSOP_GATE`, whose check raises
  `protected_mode_int`'s: an interrupt or trap gate, else #GP, not present
  #NP, each with the IDT entry; a task gate is not built. At WB it puts the
  gate's selector in T0 and its offset in T1 (a 286 gate's 16 bits), with
  the gate's size (`gate32`) and kind (`gate_trap`); a software
  interrupt's gate with DPL below CPL is #GP with the IDT entry. The CS
  descriptor's dwords and their checks (`intcs`): null #GP(0); system, data
  or DPL above CPL #GP(selector); not present #NP(selector); then the
  offset past the held limit #GP(0) (`hoff`). Then a probe of each slot
  the delivery pushes, at the gate's size (`gsz` words take `gate32` for
  their operand size), and the stores: EFLAGS (FLAG_READ_PM: RF from the
  delivery, TF and NT cleared, IF too through an interrupt gate), CS, EIP
  and the error code (`SYS_RD_ERR`), whose probe and store D drops for a
  delivery without one (`errp`); the accessed bit; then the far jump,
  stepping ESP past the pushes. A nonconforming CS below CPL is a delivery
  to an inner privilege ([Privilege transitions](#protected-mode) below).
- **Error codes and EXT.** A fault's error code is worked out at WB
  (`wb_err`): the selector in T0 for `GP_SEL`, `NP_SEL` and `SS_SEL`, the
  IDT entry for `GP_IDT` and `NP_IDT` (from the gate's read, `idt_vec`), else
  0, with EXT set for a fault in a delivery; a double fault's is 0. Only a
  protected-mode delivery of #DF, #NP, #SS or #GP pushes it (`exc_haserr`).
- **RF.** IRETD's image sets RF (the architectural EFLAGS shows it until the
  next instruction retires: every uop but IRET's last clears it, as Bochs
  clears it before the next instruction runs). A delivery's EFLAGS image has
  RF set for a fault, and for an INTR or NMI between a REP string's elements
  (`int_rep`) or after an IRETD that set it (`del_rf`); EX puts it in bit 16
  from the uop's imm.
- **LLDT, LTR, SLDT and STR** (`plldt`, `pltr`): the selector into T0, its
  descriptor from the GDT (`dmode` gdt: nothing read for TI=1), then
  `SYSOP_LDTR` or a store and `SYSOP_TR`. LLDT: null loads an LDTR no TI=1
  selector passes (`ldtr_valid` clear, the rest kept, as Bochs); TI=1 or not
  an LDT #GP(selector), not present #NP(selector). LTR: null #GP(0); TI=1 or
  not an available TSS #GP(selector), not present #NP(selector); its uop
  stores the descriptor's high dword with the busy bit set (`desc` busy), as
  Bochs stores it, and TR takes the descriptor, busy. SLDT and STR are moves
  of the selectors (`SYS_RD_LDTR`, `SYS_RD_TR`): a word to memory, a
  register zero-extended at a 32-bit size. TR is only held: no task switch
  is built.
- **LAR, LSL, VERR and VERW** (`plar`, `plsl`, `pverr`, `pverw`): the
  selector into T0, its descriptor's dwords unless it is null or past its
  table (`dmode` probe, `t0_oor`: nothing raised), then a `SEGOP_ZF` uop:
  M1 puts in ZF (imm[0]) and LAR's access rights or LSL's limit (b) from the
  staged descriptor (`ds_lar_ok` and its kin, Bochs's checks at CPL 0), and
  EX writes ZF alone and the register only when ZF is set.
- **ARPL** (`parplr`, `parplm`): the source into T2, the destination's word
  into T1, then a `SEGOP_ZF` uop: D decides from T1 and T2 (`arpl_adj`) and
  drops the write, the register's or the store with its write check, when
  the RPL is not raised, as the 386 manual and test386 have it (divergence
  `arpl-no-write-no-fault`).
- **Group 6, LAR, LSL and ARPL** raise #UD in real mode, as the 386's do.
- **The descriptor's staging** (`ds_*`): each cycle registers, from T0 to
  T3 and T1, what a load would write (base, scaled limit, access rights with
  the accessed bit, a system descriptor's access rights for LDTR and TR,
  `seg_chk_t`), the checks it would raise for each kind of check, and LAR's
  kin's results. The uops that use them issue only once T0 to T4's writers
  have retired (`t_rd`), and nothing younger writes them first, so M1 reads
  the checks and WB the cache from registers, off D's paths; D itself reads
  only T0 to T4.
- **Access checks.** Every access, in every mode, is checked against its
  segment's cached limit and type as Bochs's `read_virtual_checks` and
  `write_virtual_checks` make them (`seg_chk_t`, worked out at each load):
  an expand-down segment faults at offsets up to its limit and past its
  upper bound; a not-present segment, execute-only code on a read, and code
  or read-only data on a write fault at any offset. Bochs skips the limit
  check of a flat segment (base 0, limit FFFFFFFFh), so an access that wraps
  past 4 GiB there faults only on the RTL.
- **Leaving protected mode.** Clearing PE makes CS a writable data segment,
  its limit, DPL, G and D/B kept, as Bochs's `handleCpuModeChange` does; the
  real-mode far jump that follows takes the 386 values.
- **CPL** (`cpl`) is CS's RPL once a protected-mode load has written CS,
  and 0 in real mode and on protected-mode entry, as Bochs keeps it; the
  lockstep reads it (`arch_cpl`). Only a protected-mode CS load changes it,
  a far transfer that flushes everything younger, so DC's decode and the
  staged descriptor's checks read it as it stands. The checks take it as
  Bochs's do: a data segment's DPL at least CPL and RPL (unless conforming
  code); SS's RPL and DPL equal to CPL; a far JMP's or CALL's code segment
  by `check_cs` (nonconforming: DPL CPL and RPL at most CPL; conforming: DPL
  at most CPL), with CS's RPL set to CPL; a gate's DPL at least CPL and RPL;
  LAR's kin's DPL at least CPL and RPL; a software interrupt's gate DPL at
  least CPL (`ds_fault_sgate`, which M1 picks when no delivery is under way,
  #GP with the IDT entry); a delivery's CS DPL at most CPL; IRET's CS RPL at
  least CPL.
- **IOPL and privilege.** In protected mode, DC raises #GP(0) at a CPL
  other than 0 for HLT, CLTS, MOV to or from a CR or DR, LGDT, LIDT, LMSW,
  LLDT and LTR, and at a CPL above IOPL for CLI and STI, each after LOCK's and
  the form's #UD, before any operand, as Bochs checks them. IOPL changes only
  at CPL 0, where it gates nothing, and reaching another CPL flushes, so DC
  reads EFLAGS' IOPL as it stands. POPF and IRET load IF only at a CPL up to
  IOPL and IOPL only at CPL 0 (EX, `fes_i386_ex`). IRETD's VM bit counts
  only at CPL 0.
- **The I/O permission bitmap** (`iochk`): IN and OUT at a CPL above IOPL
  put the port in T5 (DX or the imm8), then read the TSS's bitmap base at
  66h into T4 (`tss` iomap; #GP(0) unless TR is a 386 TSS of 104 bytes or
  more), the bitmap's word for the port at that base plus the port's byte
  into T2 (`tss` bitmap; #GP(0) at or past TR's limit), and check the
  port's bits for the access's size (`CHK_IOBM`, #GP(0) for any set), as
  Bochs's `allow_io`; the last uop is the access the first kept (`iof`:
  its direction in `ctl.cond`, its size in `src_size`). INS and OUTS there
  stop as not built (`WHY_IOPERM`).
- **Privilege transitions.** A far jump writes two segments and ESP, after
  every check, so it holds CS's descriptor while T0-T3 take the new SS's.
  The uop that checks CS (`hold`) makes WB keep the staged descriptor
  (`hs_*`: selector, base, limit, access rights, checks, the access byte as
  read) and whether the transfer changes privilege (`xp`), with the new CPL
  (`hs_cpl`). Routine uops marked `xc` issue only with xp, D turning them
  into NOPs otherwise, so one routine serves both. The accessed bit of the
  held CS is stored from the hold (`DESC_HACC`), after the pushes, as
  Bochs's `load_cs` touches it; the new SS's after it, as `load_ss` does.
  The jump (`xfer`) writes CS from the hold with RPL the new CPL, and with
  xp SS from the staged descriptor and ESP from T5 plus imm (by the new SS's
  width: a 16-bit one keeps ESP's high half, as Bochs's `SP =` does).
  - **IRET to an outer privilege** (`piret`, `iret_protected`): CS's checks
    (`CHK_RET`: null #GP(0); RPL below CPL or `check_cs(0, RPL)` #GP(sel); not
    present #NP(sel)) hold it, with xp for RPL above CPL. Then SS's word
    slot into T0, its descriptor and `fetch_ss_descriptor`'s checks
    against the new CPL (`CHK_SSRET`: null #GP(0); RPL or DPL not the new
    CPL, a system, code or read-only descriptor #GP(sel); not present
    #SS(sel)), and ESP's slot into T5, then the offset against the held
    limit (`CHK_HOFF`, #GP(0)). The flags load by the CPL the IRET runs at.
    The jump nulls ES, DS, FS and GS whose DPL is below the new CPL unless
    they hold conforming code (`validate_seg_regs`): the selector 0 and
    every access refused (`seg_rbad`, `seg_wbad`), the rest of the cache
    kept, as Bochs keeps it.
  - **A delivery to an inner privilege** (`pvec`, `pint`,
    `protected_mode_int`): a nonconforming CS below CPL holds with xp and
    the CS's DPL as the new CPL. The TSS's stack for that DPL: ESP into T5
    (`tss` esp, checked against TR's limit less 7 in a 386 TSS or 3 in a
    286 one, #TS(TR)), SS into T0 (`tss` ss); SS's descriptor (`dmode` ts:
    past its table #TS(sel)) and its checks (`CHK_SSINT`: null, RPL or DPL
    not CS's DPL, a system, code or read-only descriptor #TS(sel); not
    present #SS(sel)); the gate's offset against the held limit
    (`CHK_HOFF`). Its probes and pushes go to the new stack (`nstk`: the
    staged SS's base at T5 plus the slot, wrapped by its width, checked
    against its limits, #SS(sel)), the old SS and ESP first, then EFLAGS,
    CS, EIP and the error code two slots further down (`xs`), at the gate's
    size. A fault on the way leaves SS and ESP as they were, as Bochs's
    `write_new_stack_*` does.
  - **RETF to an outer privilege** (`pretf`, `return_protected`): SS's
    word slot into T0 and ESP's slot into T5, past the two slots and imm16
    (`pimm`; on a 16-bit stack without the wrap, `nwrap`, D's `sdisp`
    carrying the whole displacement), then SS's descriptor and the outer
    IRET's checks against the RPL (`CHK_SSRET`), the offset against the
    held limit, and the jump, which loads SS and ESP from T5 plus imm16 and
    nulls the data segments as an outer IRET does.
  - **Call gates** (`pcall`, `pcallm` through `xc` gate, `call_gate`): a
    GATE uop (imm[0]) puts the gate's selector (T2's high half) in T0 and
    its offset in T1 (a 286 gate's 16 bits), with its size (`gate32`) and
    parameter count (`pcnt`, bits 4-0 of its high dword); then CS's
    descriptor and the delivery's CS checks (`CHK_INTCS`: null #GP(0);
    system, data or DPL above CPL #GP(selector); not present #NP(selector)),
    held with xp for a nonconforming CS below CPL. With xp, the TSS's stack
    for CS's DPL and SS's checks as a delivery's (`CHK_SSINT`: #TS, or #SS
    for not present), then the stores on the new stack in Bochs's order at
    the gate's size: the old SS, the old ESP (SP from a 16-bit stack, `zx`),
    each parameter from the old stack's highest down, then CS and the return
    EIP (IP from 16-bit code). The parameter copy is two ROM words, a load
    into T4 at old-stack slot pcnt - 1 - pk (`nwrap`) and its store at
    new-stack slot -3 - pk, which `fes_i386_seq` repeats pcnt times by
    stepping the ROM address back (`pm`; past the count, or at a count of
    0, both are NOPs, `pdrop`); the words below them and the jump's step of
    ESP are pcnt slots further down (`PM_BELOW`). Without xp (`xc` gsame),
    CS and the next EIP are pushed at the gate's size, wrapping as PUSH
    does. The gate's offset is checked against the held limit after the
    stores, as Bochs checks it, so a fault there leaves them written; then
    the accessed bits and the jump (CPL the CS's DPL with xp).
  - **Dropped uops.** A uop its `xc` drops is a NOP that writes nothing at
    WB: no hold, transfer, segment or ESP.
  - **#TS** takes the last two fault codes: `FAULT_TS_SEL` with T0's
    selector (a delivery's new SS) and `FAULT_TS_TR` with TR's; it is
    contributory and pushes its error code.
- **Debug registers** (Phase 5's second slice): DR0-DR3, DR6's bits 15-12
  and 3-0 (the rest read as ones, as Bochs's 386 holds them) and DR7, whose
  bit 10 is always set. MOV r32, DRn reads them in D (`SYS_RD_DR*`; DR4 is
  DR6, DR5 DR7), and MOV DRn, r32 writes T1 at WB (`wdr`, `SYSOP_DR`, a jump
  to the next instruction). Both are CPL 0 only (#GP(0)), but with DR7.GD
  set either raises #DB first, after LOCK's #UD, as Bochs's MOV_DdRd does
  (`FAULT_DB`, vector 1, a fault with no error code). Taking it sets DR6.BD,
  clears B0-B3, bit 12 and BT, and clears GD; its EFLAGS image has RF clear,
  as Bochs clears RF before an instruction runs. No breakpoint is armed:
  DR7's enables do nothing yet (slice 5). Unlike Bochs, a DR7 write does
  not flush the TLBs, as a 386's does not.
- **Not built:** each stops the CPU with `trace_unimplemented`, its reason in
  `trace_unbuilt` (`why_e`, carried by the uop as `ctl.why`) and, for a
  delivery's, its vector in `trace_vector`: a delivery through a task gate;
  a far JMP through a call gate; a far JMP or CALL to a TSS or a task gate;
  an IRET to V86 mode; an
  IRET with NT set, a return from a nested task (`ntchk`: EX checks NT as
  it runs IRET's first uop, over that uop's stack fault, since Bochs
  returns from the task before it reads the stack); INS and OUTS at a CPL
  above IOPL; a protected-mode 16-bit stack slot past 64 KiB under a limit
  that reaches there.

## Memory

**Attributes.** With paging off a physical address is the linear one with
A20M masking bit 20 and FFFF0000h-FFFFFFFFh read as the F0000h shadow
(`fes_i386_pkg::phys`); with paging on, a page table entry's frame so
masked (see [Paging](#paging)). Guest physical memory is 64 MiB at most (`PA`). The
attribute map is an input: RAM below 640 KiB and from 1 MiB to `ram_top`;
640 KiB to 1 MiB in 16 KiB slots (`attr_upper`) of RAM, read-only RAM,
uncached MMIO or a hole; a hole above. Read-only RAM is cached and its stores
are dropped. A hole reads FFh and drops stores. The bus interface reaches
guest physical 0 at HPS address `RAM_BASE` (pc386: window offset 4000000h);
the CPU never writes a read-only range, so a machine may back the ROMs with
images in DDR or route those reads to an M10K.

**L1I** (`fes_i386_l1i`): 16 KiB, 4 ways, 32-byte lines, indexed by linear
bits 11:5 and tagged with the physical page. Its arrays re-read F2's block on
every edge F1 does not load a new one, so a fill shows a cycle after it is
written. F2 compares the tags in eight replicated hit sets with kept copies
of the page register. Valid bits are flip-flops. A miss fills the line from
the bus interface: the victim is invalidated, the beats written, then the
tags, then the valid bit a cycle later. A fill ends only with no store in EX
or WB, and a store WB commits into its line while it fills, a DMA write of
it or FLUSH spoils it. Each store reads a snoop copy of the tags as it enters
WB, and its commit clears a way that holds its line on the next edge, from a
register, so the valid bits' enables do not wait on the commit. The bytes
the front end already holds, a block F2 reads the cycle after the commit
among them, are the self-modifying-code check's (below). Fetches from MMIO
or a hole read FFh.

**L1D** (`fes_i386_l1d`): 16 KiB, 4 ways, 32-byte lines, two banks of even
and odd dwords, write-through with no write allocate. The lookup tags are
read a stage ahead, for AG's address on the edge a uop enters M1
(`ag_index`); M1 compares them with its physical page and registers the hit,
and M2 selects the hitting way, so no M10K output and no valid-bit lookup
reaches the freeze; the set's valid bits are registered beside it for the
victim choice. A clear of a set (DMA, FLUSH, a store running into the next
line) drops both on the same edge, and a fill re-reads M1's tags as it ends. M1 also registers the load's index into the
data arrays with its page and attribute. A cacheable load that hits inside
its line returns in M2. Anything else freezes D to WB for the slow path, on
`stall`, one register set from the next cycle's state: a miss reads its line once no write-buffer entry holds bytes
of it, returns the load's bytes and fills the line (victim invalidated, rows,
tags, valid bit, then the probe re-read for the store waiting in WB); an
access running into the next line reads each part on its own; MMIO is read
as dwords with the access's byte enables once the write buffer is empty; a
hole reads FFh. A store's line is looked up in a probe copy of the tags as it
enters WB, and its commit writes its bytes into a way that holds it, through
the arrays' write port; lanes running into the next line clear that line's
set. Fills happen with D to WB frozen, so no store commits during one.

**Uncached loads** read their device only as the oldest uop: nothing in EX or
WB, or only earlier uops of the same instruction that neither store, end an
instruction or REP element, branch, fault, multiply nor divide, and no
interrupt being taken. Then nothing older can flush the load, and every older
store has reached the device. A load that reaches M2 behind anything else
takes no data. Every uncached load first waits a cycle in M2 (`L_UNC`), so
the freeze never waits on the oldest test; then it reads, or the L1D marks it
`FAULT_REPLAY` (`L_REPLAY`), which EX treats as a fault
(nothing changes) and WB as a restart: WB flushes everything younger, the
front end restarts at the instruction through the reset path's `start`, once
`start_linear` holds CS.base + EIP, and D issues that instruction one uop at
a time (`serial`, until its last uop commits or anything else flushes), so
its uncached loads reach M2 as the oldest. A CMPS element's second load still
issues right behind its first (`x_prev`). Microcode writes nothing
architectural before its last uop that can fault, so a restart is safe where
a fault is, with two exceptions that repeat what they did with the same
values: POPA writes each GPR as its load retires, and a restart pops them
again from the same slots; ENTER with a nesting level pushes before its
frame copies, and a copy from MMIO that restarts ENTER repeats the pushes. Loads whose data nothing uses
(`pipe_t` `nodata`: INT's and a far CALL's probes, ENTER's last check, POP
m's pop into nothing, the multiply and divide unit's LOAD and HI) touch
nothing, so no device sees a read the instruction does not make.

**Bus interface** (`fes_i386_biu`). The write buffer holds four 32-byte line
entries with byte masks, in order. A committed store is registered on the
edge it retires (the commit register) and enters on the next, so nothing in
the buffer waits on the freeze; the commit register counts as part of the
buffer for every read, DMA, FLUSH and I/O access that waits on it. Its RAM
bytes coalesce into the newest entry for the same line unless it is being
written (the newest entry's line is kept in a register for that compare), or
take a new one; its MMIO bytes take an entry of their own, so the device sees each
store as the instruction made it; its bytes in read-only RAM or a hole are
dropped. A store needs two free entries (its lanes may run into the next
line) once the store committing ahead of it has entered, counted as entries
of its own though it may coalesce, so WB holds a store while the buffer will
not have them (`st_wait`).
The oldest entry is written once a newer one exists, once it is full, an MMIO
store or two cycles old, or whenever something waits on the buffer: a RAM
entry as one two-beat burst on port 0, an MMIO one as a write per dword with
bytes, lowest first. Reads go one at a time, the L1D's first, then DMA's,
then the L1I's: a line read once no entry holds its line, an MMIO read once
the buffer is empty. I/O waits until the buffer is empty (`io_req`), so a DMA
buffer written before the OUT that starts the DMA, or a VGA store before a VGA
register write, is there first. DMA reads and writes a byte through port 0
in the buffer's order; a DMA write then clears its line's set in both L1s.
FLUSH empties the buffer and clears both L1s. A CPU reset clears both L1s'
valid bits and leaves the buffer to drain and any read in flight to finish
unseen; `cold_reset` also empties the buffer.

**Self-modifying code** (`fes_i386_cpu`). The instructions after the one in
WB came from the lines of the instructions in Q's record, DC's two and D to
EX (each one's first line and the next, which it may run into), and of the
blocks the front end holds or loads next (`fes_i386_fetchbuf`'s
`held_block`: F1's next, a predicted target F1 loads next, F2's, L1's, L2's
and the two halves'), among them every block F2 may still read from the L1I
before a clear of a line there lands. With prediction they are not one run
of lines, so each is compared on its own. A store WB
commits into one of those lines, or a DMA write (the bus interface's
`inv_valid`), may have changed bytes the front end holds. The CPU then
restarts an instruction after it, under the coherent profile and for DMA the
next one not begun: `smc_pend` until the instruction in WB ends, `smc_due`
after, or at once while WB is empty between instructions (`smc_open`), and
the next instruction's first uop takes `FAULT_REPLAY` as it enters WB, so WB
flushes it and everything younger and the front end restarts at it through
`start`, as for an uncached load but without serial issue. EX's running flags go back to EFLAGS, as for an interrupt, since that
uop has passed EX. By then the L1I has cleared the line, and the fill waits
for the store's write-buffer entry, so the instruction runs the new bytes
(the coherent profile). The instruction that stored completes as it was
decoded. Lines compare by bits 19:5 for equality, modulo 1 MiB, where linear and
physical agree under A20M and for the shadow at FFFF0000h: an alias 1 MiB
away, or a line of data next to code, restarts for nothing. Every input of
the check but the L1D's `unc_start` is a register, and its decision reaches
only registers, so the freeze and WB's flush keep their depth. Under the `queue16` profile input, sampled at reset, the 16 bytes
after a storing instruction (from `eip_next`) keep what the front end holds.
A store with no byte past them (`wb_q16`, worked out in EX), which may lie
behind them, its own encoding among them, where nothing younger is, needs no
restart. One with a byte past them restarts the first instruction that
reaches past them (`smc_defer`, with the window end plus one in `smc_t`), checked as
each instruction's first uop enters WB, as a 386 refetches once it runs past
its queue: a HLT in the window still halts, as the corpus's 386EX does after
a REP that stores over it. A byte the front end has not fetched yet is read
new. A second queue16 store during an active deferral retains the first
threshold and can refetch one instruction early relative to that later
store's window; this is conservative for coherence. A DMA write restarts the
next instruction not begun under either profile. While WB is empty, that is
the one whose first uop enters WB next,
if the last uop WB took ended an instruction (`smc_first`) and that one's
uncached load has not started to read its device (`uc_live`, or the L1D's
`unc_start` on the cycle it starts, when D to WB are frozen); otherwise the
one after it. An instruction restarted for self-modifying code is not
restarted again before it enters WB, so a stream of DMA writes cannot hold
the CPU: it may run bytes from before a write that lands meanwhile, which
restarts the one after it. An uncached load replays rather than read while a
restart may come. `trace_smc` marks each restart, and `trace_smc_open` the
cycles in which a DMA write would restart the next instruction.

Not built yet: the L2, critical-word-first fills, and
forwarding from the write buffer to a load that misses (it waits for the
entry to drain).

## Paging

Phase 5's first slice ([#1548](https://github.com/DeanoC/fes/issues/1548)),
the design's [Paging](../../../../docs/i386-cpu-design.md#paging): CR0.PG,
CR3 and CR2, two-level 4 KiB paging without INVLPG, global or 4 MiB pages,
as Bochs's `translate_linear_legacy` at CPU level 3.

- **CR0, CR3 and the flushes.** A CR0 write that changes PG, and every CR3
  write, flush both TLBs as the system uop commits (`tlb_flush`); so does a
  change of A20M or the attribute map, which an entry's page and attribute
  were made with. PG changes only at a system uop, which jumps to the next
  instruction, so every uop sees one PG. F1 loads the next instruction's
  block on the commit's edge: it looks it up with the new PG (`pg_ifl`) and
  takes nothing from the ITLB (`wb_tlbx`).
- **The DTLB** (`fes_i386_tlb`, 16 entries) at M1. Each entry holds a
  linear page, its physical page as `phys` gives the PTE's frame (A20M
  applied, past 64 MiB a hole, FFFF0000h up the F0000h shadow), that page's
  attribute, U/S and R/W of the PDE and PTE together, and the PTE's D. Port
  A looks up the memory operand's page, port B a st2 store's page (MOVS,
  ENTER's copies) or the operand's next page, which a page-crossing access
  uses. The L1D compares each tag with every entry's page in parallel and a
  way hits when the entry port A matches holds its tag, so the hit's path
  has the depth it had with paging off plus an AND-OR. M1 hands the L1D and
  the uop's record its physical pages (`pg_a0`, `pg_a1`, `pg_t0`, `pg_t1`),
  which every stage after uses: the store merge's memory types, WB's lines
  for the bus interface, the L1s and the self-modifying-code check, and the
  governor's MMIO charge.
- **What the DTLB does not serve** goes to the walker (`tx`), with D to WB
  frozen as for an L1D miss: a page it does not hold; a user access (CPL 3,
  not a system access or a new stack's) to a page the PDE and PTE do not
  give to user mode, or a user write to one they do not make writable; any
  write to a page whose D is clear; a st2 uop that crosses a page (its
  third page); a load whose byte has an older store's offset in another
  linear page (an alias, which M1 cannot see); and a fetch walk (below). A
  load whose data nothing uses (a probe, POP m's step, the multiply and
  divide unit's LOAD and HI) translates nothing (`nx`): Bochs pushes and
  faults on the pushes, as the stores then do. ENTER's last check
  translates as a write (`wx`, Bochs's `tickle_write_virtual`).
- **The walker** (`fes_i386_l1d`) runs only for the oldest uop, as an
  uncached load reads (`L_UNC`, then `oldest`), else the uop replays and
  its instruction issues alone, up to the end of the REP element it was in
  (`txr`), so a REP string that crosses into a page the DTLB does not hold
  runs on pipelined after that page's walk. So the walker never runs on a
  wrong path, and nothing older has a store to make. For each page the uop uses, in Bochs's order (the operand,
  its next page, a st2 store's, its next), it reads the PDE at CR3 plus
  bits 31:22 times 4 and the PTE at the PDE's frame plus bits 21:12 times
  4, each a dword through the bus interface once no write-buffer entry
  holds its line. A PDE or PTE not present, or a right a user access lacks,
  is #PF; otherwise it sets A in the PDE, then A, and D for a write, in the
  PTE, where clear, each a dword store through the write buffer once it is
  empty (`pw`, which clears that line's set in both L1s), and fills the
  DTLB (or the ITLB). A load then reads its bytes from memory through the
  slow path, unfilled and with nothing forwarded (`walked`), and a store is
  done: neither replays.
- **#PF** (`FAULT_PF`, vector 14) carries CR2's linear address and its error
  code to WB (`pf_lin`, `pf_err`): P for a protection fault, W/R, and U/S
  for a user access. CR2 is written as WB takes it, even when it becomes a
  double fault. Its error code never has EXT, and it is a class of its own:
  a #PF or a contributory fault in its delivery is a double fault, a #PF in
  a contributory fault's delivery is delivered (Bochs's
  `is_exception_OK`). A crossing access's fault on its second page has CR2
  that page's first byte, and nothing of a crossing store is written.
- **Deliveries under paging** issue one uop at a time (`ser_wait`), so each
  is the oldest when it walks and none replays, which a delivery cannot.
- **The ITLB** (8 entries, in `fes_i386_l1i`) is looked up in F1 on the
  block's linear page, beside the arrays' read, and its entry's page takes
  `phys`'s place in the page registers. A block whose page it does not hold
  reads as a hole and carries a mark (`ftag_t` tm), and each block carries
  its entry's U/S (ts) and its physical page's bits 19:12 (pp) through the
  fetch buffer to Q. D turns an instruction whose first byte's block or the
  block it runs into has a mark, or a supervisor page at CPL 3, into a walk
  (`ifw`): a NOP whose walk, as the oldest, fills the ITLB and restarts the
  instruction, or raises #PF (CR2 the instruction's first byte, or the next
  block's for its second page; U/S by CPL, W/R read). The BTB and the return
  stack stay linear: their checks catch a remapped target.
- **Self-modifying code** compares physical lines by bits 19:5: each fetch
  block carries its page's physical bits 19:12, each instruction from Q to
  EX its first line's and the next block's (`ipp0`, `ipp1`), F1's next
  blocks (not looked up yet) compare by bits 11:5 alone with paging on, so
  a store through another linear page of the same frame restarts the code
  it rewrites.
- **Not coherent:** both TLBs keep an entry across a store into its page
  table until a CR3 write, as a 386's (and Bochs's) do. A DMA write into a
  page table between the walker's read and its A/D store is not seen.

## Speed governor

`fes_i386_governor` is the design's [speed control](../../../../docs/i386-cpu-design.md#speed-control).
[`governor.toml`](governor.toml) holds the presets (cost table, frequency,
wait states, bus width) and the cost classes: the encodings each costs, by
the lockstep's stems, with their 80286, Intel386 and i486 clock counts.
`scripts/fes_i386_governor.py` checks it (no encoding in two classes, every
encoding the lockstep's scope builds in one) and writes
`fes_i386_gov_pkg.sv` (`classify`, `preset`) and `fes_i386_gov_rom.sv`, an
M10K-shaped ROM of `{taken or per-element cost, cost}` by `{table, class}`.
Classes that cost the same share a ROM row. Run it after editing the table;
`--check` fails if the checked-in files are stale.

- **What DC keeps.** `gov_t` (opcode, ModRM reg field and form, operand size,
  REP, base+index+displacement) is filled from Q's bytes beside the decode,
  rides in `decoded_t` and `pipe_t` through every uop of the instruction, and
  reaches WB with its last. An exception or interrupt delivery's entry
  (`dc_exc`) carries INT's opcode.
- **What it charges.** On WB's boundary (an instruction's last uop, or a REP
  element's, `at_boundary`): the class's cost as the instruction ends, its
  taken cost for a branch WB took other than a far jump (INTO's JNO taken is
  no interrupt), and the per-element cost as an element ends. On every uop
  WB commits: its memory bus cycles (a load or store one, a read-modify-write
  two, a `st2` store one more; a `nodata` probe none) times the preset's wait
  states, and on a 16-bit bus a dword access's second cycle.
- **ISA bus time.** Also on every uop WB commits: its I/O access's ISA cycles
  as the machine's `pc386_io` splits it (an 8-bit one a byte, and a 16-bit
  one where `word16()` finds the ATA data port among its bytes with another
  after it) less the data sheet's two-clock bus cycle; and for each of its memory
  accesses that is MMIO (`attr` of `wb_mp`, the operand's physical address,
  or of `wb_p0` for a `st2` store) a VGA cycle per 16-bit half it touches,
  less the bus cycle and wait-state charge it already has. Neither goes
  below zero. `governor.toml`'s `[isa]` gives the cycles in ISA clocks; the
  governor turns them into reference clocks at its frequency at reset
  (`ISA_STEP`/`2**ISA_FRAC` an ISA clock per 100 kHz, rounded as the exact
  figure is at every frequency the record can set).
- **The pipeline.** Registers from WB: the retirement; the class, the ROM's
  address and the memory charge; the ROM's word; the charge; the debt (in
  1/65536 reference clock, never below zero); `hold`, the debt over 64
  reference clocks. The step per clock is the frequency times `GOV_N`/`GOV_D`
  (100 kHz of the clock, set by the producer), worked out at reset.
- **D's hold.** `d_first` marks an instruction's or REP element's first uop
  (after a redirect, or once D has issued the last uop of either);
  `gov_block` is `hold` there, a cycle late, and one more term of `issue`. A
  sequence's later uops are never held, so a CMPS element's `x_prev` pair
  stays together.
- **Settings.** `gov_preset`, `gov_frequency` and `gov_turbo` are sampled
  while `reset` is high; preset 0 or turbo charges nothing and never holds.
  `trace_gov_hold`, `trace_gov_debt` and `trace_gov_charge` show it to the
  benches.

`scripts/test_fes_i386_governor.py` runs [`governor_bench.asm`](../../sim/i386/governor_bench.asm)
in the lockstep testbench's governor mode (A0000h-BFFFFh MMIO) under max and
every preset: each loop's charge must equal the table's, its time must be
within 5% of the table time at the preset's frequency, interrupt latency
must stay within the window, and the frequency override and turbo must act
as the record says. `sim_fes_pc386.py --suite governor` times the delay,
speaker (port 61h) and VRAM fill loops of `governor_test.asm` against the
BIOS tick on `pc386_system`, with the machine's device time.
`test_fes_i386_lockstep.py --preset N --same-as <max report>` reruns the
lockstep under a preset and fails on any architectural difference from max.

## Synthesis notes

The i386 RTL has its own toolchain lock, [`toolchain.lock`](toolchain.lock)
here: the DeanoC Yosys fork's main at `238eac9a49`, with nextpnr `bd7a1c0d`
and Mistral `8fcc4cb4`. The timing spikes default to it. The repository's
shared lock stays at Yosys `3a5accbd`, which reads this RTL wrongly, so check
and route the i386 RTL with this lock's Yosys. Each later Yosys fix is a
small bump of this lock, the removal of its one workaround, the `--yosys`
check and a re-measure.

Synthesis runs `proc -norom` first, by choice: it keeps case tables in
logic. Without it the length decoders' 0Fh opcode tables become M10K ROMs
whose registered read takes in F2's byte register, which puts an M10K read in
front of L1's decode, the shape [rule 7](../../../../docs/i386-cpu-design.md#platform-constraints)
keeps out of the pipeline. Measured on the corrected model, F2 fell from
86-91 to 73-77 MHz in the front-end spike. A `rom_style = "logic"` attribute
on the table's case statement does not keep it in LUTs.

Narrow sums (lengths, ends, counts) mark their `+` with `(* no_carry *)`, so
the locked Yosys builds them from LUTs rather than an ALM carry chain
([DeanoC/yosys#44](https://github.com/DeanoC/yosys/pull/44); the attribute
is opt-in and Verilator ignores it).

The locked Yosys still gets some SystemVerilog wrong. This RTL stays inside
what it reads correctly:

- named assignment patterns (`'{a: ...}`), and structs a function builds
  from constant arguments, read correctly in both locks since
  [#38](https://github.com/DeanoC/yosys/issues/38) and
  [#33](https://github.com/DeanoC/yosys/issues/33) were fixed (#48, #42);
- an unsized literal (`'0`) on a port of a parameterised cell in the
  `-chparam` top asserts, as a sliced signed wire does
  ([#71](https://github.com/DeanoC/yosys/issues/71)): size it;
- logic replicated to cut fanout merges back into one copy even on
  `(* keep *)` wires, so each replica needs its own kept input register
  ([#51](https://github.com/DeanoC/yosys/issues/51));
- compute an index into a wire of the index's width (`tail2`), not as a sum
  inside the brackets: the locked Yosys evaluates `a[i + 2'd1]` at 32 bits,
  so the index does not wrap ([#69](https://github.com/DeanoC/yosys/issues/69));
- read two or more fields of one variable-indexed record through a single
  whole-record copy (`at_start = dec[start]`), not as `dec[start].a` and
  `dec[start].b`: the selects share their `start * width` multiply, which
  then maps to a DSP multiplier and a carry chain
  ([#59](https://github.com/DeanoC/yosys/issues/59)). A constant index, as
  in a generate loop, is fine.

`dist` is a SystemVerilog keyword (the constraint operator); Verilator rejects
it as a signal name, so the forwarding modules spell the distance `dist_a` or
`ahead`.

`scripts/test_fes_i386_frontend.py --yosys <yosys>` and
`scripts/test_fes_i386_lockstep.py --yosys <yosys>` run every check on the
netlist Yosys writes from this RTL, which is what the spikes route. Run them
after any RTL change. The front-end runner also synthesizes Q's aligner on its
own and fails if any multiplier or carry cell appears there: Q has no wide sum,
and the front-end spike does not show #59's multiplier.
