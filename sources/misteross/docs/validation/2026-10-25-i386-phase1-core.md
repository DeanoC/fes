# i386 Phase 1: whole-CPU lockstep and the register-only real-mode core

Dated record, 2026-10-25. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit. It builds the next Phase 1 slice of the
[i386 CPU design](../i386-cpu-design.md): the whole-CPU retirement lockstep
that the design's verification plan names (item 5), and `fes_i386_cpu` from D
to WB for the one-uop register and immediate forms, behind the front end of
the [front-end fixes](2026-10-25-i386-phase1-front-end-fixes.md). It was
built and measured on the i386 lock at Yosys `d4ac300d9d`
([toolchain lock record](2026-10-25-i386-toolchain-lock.md)), then checked
and routed again on the lock's bumps to Yosys `ca51238cb9`
([bump record](2026-10-25-i386-yosys-ca51238cb9.md)) and `238eac9a49`
([bump record](2026-10-25-i386-yosys-238eac9a49.md)); nextpnr `bd7a1c0d` and
Mistral `8fcc4cb4` throughout. Run data:
[`2026-10-25-i386-phase1-core.jsonl`](2026-10-25-i386-phase1-core.jsonl), one
line per route with argv, tools, GPU, fmax, per-stage figures, utilization
and critical path.

## What was built

### The lockstep harness

`sim/i386/lockstep_tb.cpp` runs the CPU top beside the Phase 0 Bochs adapter.
The oracle steps one instruction; the RTL runs until it retires one. The two
architectural states are then compared:
- EIP;
- the eight GPRs;
- EFLAGS bits 0-17;
- the six segment registers with selector, base, limit and attributes;
- memory writes, as each side reports them;
- exceptions: an instruction that faults in the oracle must fault in the RTL
  with the same vector, with nothing retired.

The RTL does not deliver exceptions yet, so a faulting run ends at the fault.
HLT ends a run on both sides.

**Undefined flags.** Where the oracle and SingleStepTests disagree,
`divergences.toml` names the side the FES CPU follows. For an entry that
follows the corpus, each retirement it applies to leaves its fields out of
the comparison with the oracle. The oracle then takes the RTL's values, so
both sides run on from the same state. The testbench works out each entry's
opcode stem and `when` predicates from the retiring instruction, as the
vectors runner does. The corpus checks those values separately: each corpus
run's final RTL state must equal the corpus's final state, undefined flags
and RAM included.

**Latency.** The memory model delays each fetch block by a random 0-12
cycles and puts garbage on the port until the block arrives. The model's
`Latency` class is what the later slices' data, MMIO and I/O ports take.

**Programs.** `scripts/test_fes_i386_lockstep.py` drives two sources:
- **SingleStepTests/80386:** every state of the instruction forms the CPU
  executes, from its initial state to its HLT. The forms are the runner's
  `SCOPE` table, which each later slice extends.
- **Random programs:** register and immediate forms of the same instructions
  with segment, REP, 66h and 67h prefixes, forward branches, bounded LOOPs and
  backward jumps, and now and then a LOCK (#UD). They make results forward
  between instructions, and taken branches kill younger producers, which the
  single-instruction corpus states cannot do. Two seeds run again without
  latency and must retire the identical trace (a hash of every retirement's
  state).


### Fetch that stalls

The front end's memory port gains `mem_valid`: F2 waits for a block, and a
redirect replaces a request still waiting. The front-end check
(`test_fes_i386_frontend.py`) adds three streams with the same random 0-12
cycle latency and garbage while waiting. They reach the case the design's
"Requirement when fetch can stall" names, Q leaving a half while L2 holds no
block for it, which a fetch that never stalls cannot. This slice adds the
stall, so it adds the check. The L1I slice still has to repeat it with real
misses.

### The core

`fes_i386_cpu` runs F1 to WB. M1 and M2 carry uops through; the memory slice
fills them.

- **Q to D.** A one-entry skid register sits between Q's output and D. Q may
  load its output whenever the skid is empty; an instruction D cannot take
  that cycle moves into the skid. So D's stall never reaches Q's loop as
  `d_ready`. Q is the slowest stage alone, and its enables already carried
  `d_ready`.
- **D** decodes to one uop (`fes_i386_decode`); the forms are listed under
  [Coverage](#coverage). LOCK on any of them, MOV to CS or to segment
  register 6 or 7, LEA of a register, and C6h/C7h with reg != 0 raise #UD.
  Over 15 bytes raises #GP(0), after LOCK's #UD (Phase 0 divergence
  `lock-ud-before-length-gp`). Every other encoding decodes as
  `FAULT_UNIMPLEMENTED`, which stops the CPU at WB, so no check can pass over
  one.
- **EIP.** D keeps EIP with an incrementer beside the decode, not in series
  with it. In 16-bit code an instruction whose next EIP passes FFFFh is
  unimplemented too: fetch would have to wrap to the segment's start, and the
  CS-limit check is not built. No in-scope corpus state reaches it.
- **Data operands** (`fes_i386_dops`). src1 is always the destination's
  register, so a byte or word result merges into its old value, the implicit
  source. src2 is the second register or the immediate; a CL count is a third
  source. D reads them from the register file or the M1, M2, EX and WB result
  registers, by a second per-GPR table written a cycle ahead like
  `fes_i386_dfwd`'s. A data operand never stalls D. If its producer has not
  computed it, the operand is pending and records how far ahead the producer
  is (1-4 stages). No stage behind D holds, so the producer reaches WB when the
  uop is that many stages before WB. The uop takes the WB result register
  there: AG, M1 or M2 into the next pipeline register, or EX beside its
  operand. That 2:1 select is EX's only forwarding mux.
- **LEA** is an early result when its destination is 32-bit: AG's offset is
  the whole value. A 16-bit LEA merges at EX like any other result.
  `fes_i386_dfwd` supplies LEA's address operands and its stalls unchanged.
- **Segment registers.** A real-mode load (MOV Sreg, r/m) writes the selector
  and base = selector * 16 at WB and keeps the limit and attributes, as Bochs
  and a 386 do. A selector read (MOV r/m, Sreg) waits in D while an older uop
  writes that segment register.
- **AG** runs `fes_i386_agu` for LEA, or for a branch target: CS.base + EIP +
  length + displacement in one carry chain, wrapped by operand size.
- **EX** (`fes_i386_ex`): one adder for ADD, ADC, SUB, SBB, CMP, INC, DEC,
  NEG and LOOP's count, with ZF from the operands; the logic unit; the 64-bit
  funnel shifter (`fes_i386_shift`); and the merge into the destination's old
  value, so WB writes whole registers. EX keeps a running EFLAGS that every
  uop passing it updates, so Jcc, SETcc, ADC, SBB, RCL and RCR read flags
  with no forwarding. A flush kills only uops younger than WB, which have not
  passed EX, so the copy stays right.
- **Branches** are predicted not taken: near JMP, Jcc, LOOP, LOOPE, LOOPNE,
  JCXZ. EX resolves them; a taken one redirects F1 from WB, which flushes
  every younger uop and clears both forwarding tables.
- **WB** commits in order. A fault stops the CPU with nothing retired; HLT
  retires and stops it. D issues nothing after either.
- **Reset and trace.** `init_*` is the state reset loads. A machine ties it
  to the 386 reset state; the harness loads a test's state. `trace_*` and
  `arch_*` show each retirement.

**Holds behind D.** None of these stages holds: EX is one cycle, and nothing
behind it waits. So the inherited requirement, that D's forwarding tables
follow any hold behind D, has nothing to follow here, and no check is added.
The memory slice's L1D miss brings the first hold, and that slice must add
the check.

### The 386EX's undefined shift results

The corpus decides what the 386 manual leaves undefined. A Python model of
the slice was fitted to every in-scope corpus state before the RTL was
written; the RTL follows it:
- **OF.** After a left shift or rotate (ROL, RCL, SHL, SAL, SHLD), OF is the
  result's top bit XOR the new CF. After a right one (ROR, RCR, SHR, SAR,
  SHRD), it is the result's top two bits XORed. Both hold at every count, so
  one rule per direction covers count 1 too.
- **CF at wide counts.** A byte SHL or SAL by 16 or 24 sets CF to the
  operand's bit 0; a byte SHR, to bit 7. Otherwise CF is the last bit shifted
  out, or 0 past the width.
- **16-bit SHLD and SHRD by 17-31.** The 386EX shifts the 48-bit dst:src:src
  left (SHLD) or src:src:dst right (SHRD) and keeps the top or bottom 16
  bits. CF is the last bit out; OF follows the rule above. The funnel shifter
  does this by its arrangement, with no special case.
- **AF** is set by a shift with a nonzero count, and cleared by AND, OR, XOR
  and TEST.
- MOV r32, Sreg zero-extends the selector.

`divergences.toml` now states the wide-count rules in its corpus text.

**Unbuilt encodings.** Beside the lockstep, every one-byte and 0Fh opcode
followed by every second byte that `SCOPE` leaves out, 96,928 encodings, must
stop the RTL with `FAULT_UNIMPLEMENTED` before anything retires. Review found
the gap this closes: the group-1 decode let the r/m arm's `known = reg_form`
overwrite its exclusion of columns 6 and 7, so segment PUSH and POP and the
BCD adjusts (06h, 07h, 0Eh, 16h, 17h, 1Eh, 1Fh, 27h, 2Fh, 37h, 3Fh) retired
as ALU operations when the next byte had mod 11. The lockstep runs only what
`SCOPE` names, so it never reached them; the new check failed on exactly
those 704 encodings and passes after the fix.

The #UD states are LOCK on these forms, LEA of a register, MOV to CS or to
segment register 6 or 7, and C6h/C7h with reg != 0. The RTL raises #UD at
the same instruction with nothing retired, so the comparison with the oracle
covers them; the corpus's final state for them is after delivery, which is
not built, so it is not compared. No in-scope state crosses offset FFFFh or
reaches #GP.

Divergences applied, as retirements left to the corpus: `shift-rotate-of`
59,080, `shift-af` 49,444, `shift-cf-wide-count` 11,864,
`double-shift-wide-count` 2,262, `invalid-sib-scales-base` 56 (LEA). Every one
of those retirements then matched the corpus's final state.

### Where it lands, and why

- **The whole CPU's post-cut 58-67 MHz summary is the `ca51238cb9` result**;
  its detailed rows above are 58-66 MHz with qalign `fb98e024` and its
  `at_start` select. The older `238eac9a49` captures are 53-58 MHz and
  pre-`at_start`, where Q's record maps differently. This is below every
  isolated spike, as expected: the same stages lose 10-20% when placed among 10,000 LUTs
  instead of 2,000-6,000 (Q 66-72 against 79-83 alone, F2 78-79 against
  83-88, AG 74-81 against 86-96). Their paths are the isolated spikes' paths
  with more routing: Q's ends at `acc` as before.
- **EX limits every route.** Before the cut, its path ran from the WB result
  register (the bypass) or the EX record through the byte extract, the
  opcode-decoded operand selects, a few cells of the carry chain and the
  flags case into `ex_flags`: 13 cells, 17.1-19.3 ns, 11.4-13.5 ns of it
  routing. That broke rule 8 on both sides of the chain (three or four LUT
  levels before it, five after). The cut took EX from 52-58 to 58-67 MHz
  and the whole CPU with it.
- **After the cut EX's worst path no longer runs through the adder's chain.**
  It starts at the registered controls and ends at `ex_flags` or the WB
  register: 11-12 cells with at most one carry cell, 15.0-17.4 ns,
  9.4-11.9 ns of it routing. EX's deepest path before placement, 14 LUT
  levels, is the shifter's: the funnel arrangement, the five-level shift,
  the size's window, the result's ZF, SF and PF, and the flag select.
- **D is next, at 65-70 MHz,** against 86-90 for its address forwarding alone.
  Its worst register in every route is `ag_row`, AG's first-row operand,
  which `fes_i386_dfwd` gives for an LEA and the branch's EIP otherwise; its
  deepest path before placement, 10 LUT levels, starts at the skid
  register's select. The skid mux, the opcode decode that picks LEA's or the
  branch's operands, and the data operands' table are what the D+AG spike
  did not have.

### Against rules 7-9

- **Rule 7.** F2 keeps M2's shape; it routes at 78-79 MHz in the CPU.
- **Rule 8.** AG keeps two LUT levels before its chain and one after. EX did
  not, and the cut fixed the adder's side: the controls are registered, and
  the bypass, extract and operand preparation come before the chain, the
  size's carry select and the flag selects after it. The shifter has no
  chain but is now EX's deepest path.
- **Rule 9.** In these captures EX, D and Q miss 80 MHz on every route, F2 and
  AG on some; the `ca51238cb9` clock lands at about 58-66 MHz with the
  `at_start` qalign copy, while the older 53-58 MHz `238eac9a49` rows are
  pre-`at_start`. The next cuts the paths point at, for a later decision (none is
  made here):
  - **EX's shifter:** build the funnel's arrangement in M2 into the EX record,
    and have D hold a shift for a cycle when its shifted operand's producer
    is the uop just ahead (so M2 has the value), leaving EX the five-level
    shift, the window and the flags.
  - **D:** register the LEA-or-branch choice of AG's operands a stage
    earlier, or give the branch target its own small adder at AG so that
    `ag_row` comes from `fes_i386_dfwd` alone, and take the skid's select out
    of the decode's first level.
  - **Q:** the start-after-next idea ([#1097](https://github.com/DeanoC/fes/issues/1097)).

## What the design doc should change

This record does not edit `i386-cpu-design.md`. What it finds the doc
should take up:

1. **The uop has three register sources.** src1 is the destination's
   register and an implicit source for byte and word merges; a CL count is a
   third source; MOVZX, MOVSX and CWD/CDQ need the source's size apart from
   the operation's. `uop_t` gains `src_size` and `count_cl`. The Decode
   table's "up to two sources" should say so.
2. **Data forwarding.** The doc has uops in M1 and M2 capture late-ALU
   results from the EX result bus by register tag. This slice captures from
   the WB result register instead, at AG, M1 or M2 by producer distance, plus
   one 2:1 select at EX's input for the uop right behind. That keeps the EX
   result bus to one load (the WB register) at the cost of a mux before EX's
   adder. Measured: with EX's controls registered, the adder path is no
   longer EX's worst, so the bypass is not what limits EX now.
3. **Flags.** EX keeps a running EFLAGS, so no flag forwarding exists. The
   doc is silent on how flags reach Jcc, ADC and SETcc.
4. **Q to D.** D's stall must not reach Q's loop through `d_ready`; a
   one-entry skid register between them does it. The doc's Q budget assumes
   it.
5. **EIP in D.** D keeps EIP with an incrementer, a carry chain the D budget
   says D has none of. It is not in series with the decode. The doc should
   say where EIP lives.
6. **16-bit EIP wrap and the CS-limit check** are not built; D reports an
   instruction that crosses FFFFh as unimplemented. They belong with the
   microcode slice's #GP delivery.
7. **Segment writes** do not forward yet: D stalls a selector read behind an
   older write of that segment register. The doc says a real-mode segment
   write forwards like a GPR result; that matters once memory operands use
   the base (the memory slice).
8. **HLT** is a one-uop instruction here (retire, then stop). The doc lists
   HLT among microcode routines; with interrupts it needs the wake-up.
9. **Branches** all resolve at EX with the redirect from WB. Measured: the
   instruction after a taken branch retires 10 cycles after it (65%) or 11
   (30%), the design's +9; early branch resolution at AG is Phase 4.
10. **Fetch can stall** now. The "Requirement when fetch can stall" check
    exists (fetch latency in the front-end check and the lockstep); the L1I
    slice must repeat it with real misses.
11. **Timing.** The whole register-only CPU routes at 58-67 MHz against the
    about 80 MHz design point; EX (its shifter) and D limit it, and every
    front-end stage loses 10-20% against its isolated figure. The
    "Measured alone" column should gain a whole-CPU column, and rule 9's
    sentence should say where the whole CPU lands.
12. **`FAULT_UNIMPLEMENTED`** is a non-architectural value in `fault_e`: an
    encoding not built yet. WB stops on it, so no check passes over one; the
    doc's fault list should name it as test-only, kept out of package
    builds.
13. **EX's controls are decoded in M2** (`fes_i386_exctl`). The stage table
    should list it under M2 and EX's budget should say the selects are
    registered.
