# i386 issue cut: D's holds and WB's decisions from registers

Dated record, 2026-10-27. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit.

After [the small forms](2026-10-27-i386-forms.md), this slice shortens the
loop through D's issue, which set the CPU's nextpnr figure on most seeds
since the microcode slice. It is a timing cut only: no cycle changes
anywhere, which the latency-free comparison below shows.

Run data: [`2026-10-27-i386-issue.jsonl`](2026-10-27-i386-issue.jsonl).
- The before figures are the small forms'. Seeds 1-4 are its record's rows
  (`d073eaa778`). Seeds 5-8 are routes of `2ba1879e9f`, which has the same
  source fingerprint (`f7ef4a1b345f`): the files the CPU spike reads are the
  same.
- Routes and the full lockstep runs are of `36a3567502`. Its fingerprint also
  covers this slice's benchmark label change.
- Eight nextpnr seeds each, since one seed moves by about 2.5 MHz between
  builds with nearly the same netlist.
- A Quartus row's `fingerprint` is the first 12 hex digits of the SHA-256 of
  its `sources` map, as JSON with sorted keys.

## The loop

`issue` enables most of DC's buffer (`dc`, about 280 bits) and D's state, so
everything in front of it is on one loop. Before this slice that loop had
two halves:
- **D's hold terms.** Each started at a different stage register. D's
  address forwarding added two 8:1 selects (the uop in AG, then the table) in
  front of the stall. `issue` was 6 LUT levels deep in the netlist.
- **WB's flush and redirect.** These came through `freeze` and `exc_take`, 4
  levels from the data port's valid pin. They feed DC, Q and the stage
  registers.

## The cut

- **dfwd's table** keeps, per GPR, the state D's stall needs as registers.
  An address operand there is late (`lt`), from which register (`src`), or
  further off (`wt`). The uop leaving D is folded in as it leaves: what it
  writes is late from M1 if its result is early, else further off. D's stall
  is then a select by register number and one OR. `sp_wait` is `lt[4] ||
  wt[4]`.
- **D's holds behind the uop in AG** read what that uop is from bits
  registered as it enters AG: `ag_store`, `ag_shift`, `ag_wsp`. These cover a
  load behind a store, a flag reader behind a shift, and ESP as data behind a
  stack operation.
- **WB's decisions** are registered as the uop enters WB, beside `wb_s`:
  - `wb_flushes`: a taken branch, a fault or HLT;
  - `wb_redir`: a taken branch, or a fault it delivers;
  - `wb_deliver`: a fault it delivers.
  `wb_flush`, `exc_take` and `redirect` are each one gate from `freeze`. A
  fault entering WB is delivered unless a delivery is under way then: one is
  if `exc_active` is set and the delivery's last uop does not retire on that
  edge. Once halted nothing enters WB, so `exc_take` needs no `halted` term.
- **D's 32-bit near CALL check** was next on three seeds once the rest had
  moved. An intermediate build without this change routed 71.07, 71.55,
  73.14 and 71.32 MHz. On seeds 1, 2 and 4 its worst path ran from `dc`
  through three chained sums: `d_eip + length`, then plus `imm[15:0]`, then
  `imm[31:16]` plus the carry. Those sums set the push's fault and `d_stop`.
  - In 16-bit code the next EIP is EIP's low half plus the length, so the
    target's high half is imm's plus the carry out of the low halves.
  - That is now one sum (a 3:2 row, then one 17-bit carry chain), beside
    compares of `imm[31:16]` with 0 and FFFFh.
  - A carry of 2 needs the next EIP past 10000h, which faults the same way
    through the CS limit (`cs_gp`, `wrap16`), so it is left out.

| Netlist (Yosys `238eac9a49`) | Before | After |
| --- | --- | --- |
| `issue` | 6 LUT levels | 5 |
| `wb_flush`, `exc_take` | 4 | 2 |
| D's `stop` | 3 carry chains, 38 cells deep | 1 chain, 23 |
| Behind `issue`, into `dc`'s enables | 2-3 levels | 2-5 |

**The shaping limit.** ABC9 maps the hold terms as a chain through each
LUT's fast input. Its delay model sees no routing, and it recovers area where
it finds slack against the carry chains.
- Two further shapes were tried and dropped: `dc_valid` written as a plain
  function of `issue`, and a kept `go` net. Neither shortened the netlist; the
  kept net came out deeper.
- What follows `issue` is set by `dc`'s two enable classes:
  - fields `fes_i386_seq` rewrites at every step load on `!dc_valid ||
    issue`;
  - fields it keeps through a sequence load on `dc_load`, which Yosys builds
    on top of that, a second high-fanout LUT;
  - fields `seq` keeps on some steps and rewrites on others get the step's
    condition in their enable too. That condition includes the ROM word's
    `stk` for `mem.seg` in microcode, which put up to 5 levels behind `issue`
    in this netlist.

**The CPU's figure does not show the cut.** The average moves 70.2 → 71.0
MHz, inside the seed spread. The worst seed is lower, 67.73 against 68.53,
and it is Q's prefix loop (`align.acc`), which this slice does not touch. The
stage figures show the cut:
- **DC averages 72.5 MHz against 70.9**, but it still limits four seeds
  (72.8, 68.1, 71.4, 73.5). On each, the path is about 5 LUTs of hold terms
  to `issue` (about 7.8 ns), then `!dc_valid || issue`, then `dc_load`, then
  `dc`'s enable or `dc_skid_valid`. The last two are high-fanout hops, about
  6 ns between them.
- **D averages 77.0 against 72.3**: the CALL check is gone from every seed's
  worst list. Seed 7's D (69.9) is the address path into `ag_row`: the
  memory decode, then dfwd's selects, then the row select. That path is
  next for D.
- **EX averages 76.9 against 72.7.** Its worst endpoints are `wb_s`'s data in
  both builds, from EX's result and flags, and this slice does not change
  EX, so the gain is placement and is not claimed.
- **Q** is the front end's own prefix loop, now the CPU's limit on three
  seeds (67.7, 71.8, 72.9).

**Quartus averages 101.6 against 102.2**, Q-limited as before (EX on seed 4
at 99.4).

## What the design doc should say

This is reported for the doc's owner to write; the doc is unchanged here.

- **D's stall is per register.** dfwd's table keeps each GPR's state as an
  address operand (late, from which register, further off) with the uop
  leaving D folded in, so D's stall is a select by register number.
- **D's holds behind AG** read registered bits about AG's uop, not its
  record.
- **WB decides as a uop enters it.** Flush, redirect and delivery are
  registered beside `wb_s`, so each is one gate from the freeze.
- **The next DC cut is `fes_i386_seq`'s held fields.** A field `seq` keeps
  through a sequence makes Yosys build `dc_load` on `!dc_valid || issue`. A
  field it keeps on some steps adds the step's condition to its enable.
  Setting them outright at every step, or from static copies as POP m's
  `m_*` fields already do, would leave one enable on `issue`.
- **Q's prefix loop** now limits the CPU on nextpnr as often as DC, and on
  Quartus as before.
