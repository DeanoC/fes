# i386 lock bump to Yosys ca51238cb9: six workarounds removed

Dated record, 2026-10-25. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit. It moves the
[i386 toolchain lock](2026-10-25-i386-toolchain-lock.md) from Yosys
`d4ac300d9d` to DeanoC/yosys main `ca51238cb9`. It then removes the six
workarounds that pin's fork PRs make unnecessary, one commit each, and
re-measures the spikes. nextpnr `bd7a1c0d` and Mistral `8fcc4cb4` are
unchanged. Run data:
[`2026-10-25-i386-yosys-ca51238cb9.jsonl`](2026-10-25-i386-yosys-ca51238cb9.jsonl).

## What was removed

| Issue | Fork PR | The RTL now |
| --- | --- | --- |
| #33 | #42 | Builds `form_t` through `form(modrm, creg, imm)`, a struct-returning helper called with constant arguments: the construct that miscompiled |
| #35 | #45 | Names `SEG_ES`…`SEG_GS`, `REP_NE` and `REP_E` in `add_prefix` |
| #36 | #46 | Imports `fes_i386_pkg` in the front-end modules' headers for its types |
| #37 | #47 | Uses `return` in the opcode-table, ModRM and prefix functions |
| #39 | #44 | Writes narrow sums as `+` with `(* no_carry *)` on the operator. `small_add` and `small_add6` are gone. Verilator ignores the attribute |
| #40 | #50 | Fixed, but `proc -norom` stays, as a timing choice: see below. A new `rom` spike checks the fix |

Kept, with their issues open:
- **#38:** assignment patterns.
- **#51:** replicas need their own kept register.
- **#52:** fields of an array element go through whole-record copies.

**New: [DeanoC/yosys#55](https://github.com/DeanoC/yosys/issues/55).** On
`ca51238cb9`, calling an imported package function by its bare name trips an
assertion in the frontend (`simplify.cc: wire != nullptr`). The modules
therefore import the package for its types and still call its functions by
their qualified names. The #36 commit was written that way.

## Checks

Each commit ran `scripts/test_fes_i386_frontend.py --yosys` on
`ca51238cb9`'s netlist. Every run produced records identical to the
front-end fixes record's, field by field, for all three checks: the
exhaustive length sweep with every accumulator variant, the 14 front-end
streams with exact timing, and the cycle-by-cycle D/AG stream with its
latencies. No run left an implicitly declared wire.

The #40 row's check used plain `proc`; synthesis and the netlist check went
back to `proc -norom` afterwards.

Verilator at the README commit `703dca9f51` is identical too.

**#33's regression check.** The #33 commit's length sweep on the previous pin
`d4ac300d9d` mismatches 10,616,832 cases per default size, plus 16,384
directed cases. That is the same miscompile Phase 1 first measured, so the
sweep catches it if it returns.

**#39's mapping.** With the attribute, the front-end spike synthesizes with
carry cells only on the 28-bit fetch-address incrementers, as before. With
the same sums written without it, they take 942 more carry cells.

**#40's mapping.** Without `proc -norom`, each L1 decoder's 0Fh opcode table
becomes an M10K ROM: 17 M10Ks, 36 in the front-end spike instead of 19. The
fix connects CLK1 to the same clock as CLK2, and nextpnr packs and routes
them. The ROM's registered read takes in F2's byte register, though, so F2's
way select now drives 17 M10K address ports as well as F2's register. That
costs timing (below), so synthesis keeps `proc -norom`, now as a choice to
keep case tables in logic, not as a workaround. A `rom_style = "logic"`
attribute on the table's case statement did not keep it in LUTs. The fix
itself is checked by a new spike, `spike_rom`: a 256-address registered
case-table ROM synthesized without `-norom`. It maps to one M10K with CLK1
connected, packs, and routes at 220-242 MHz over seeds 1-4.

## Timing spikes

`scripts/benchmark_fes_i386.py`, seeds 1-4, HIP through `gpu-run` with
`NEXTPNR_REQUIRE_GPU=1`, nextpnr `bd7a1c0d`. Every route logged a live HIP
backend. The first column is the lock record's record-RTL figures on
`d4ac300d9d` (#1098).

| Stage | #1098, `d4ac300d9d` | `ca51238cb9`, all but #40 (`proc -norom`) | `ca51238cb9`, all six |
| --- | --- | --- | --- |
| F1 | 83.0-105.6 | 85.8-91.8 | 76.7-85.1 |
| F2 | 82.6-87.8 | 85.9-90.6 | **72.9-76.5** |
| L1 | 89.5-93.2 | 90.7-94.5 | 87.2-93.7 |
| L2 | 89.2-94.5 | 89.9-93.0 | 85.2-90.8 |
| Q | 78.7-82.5 | 77.4-85.3 | 74.5-78.4 |
| D | 85.8-90.1 | 84.1-89.4 | 84.9-95.6 |
| AG | 85.5-95.7 | 86.8-95.7 | 88.3-97.1 |
| M2 (control) | 97.8-106.5 | - | 97.8-106.5, identical routes |

Routed fmax in MHz, seeds 1, 2, 3, 4:

| Spike | #1098, `d4ac300d9d` | `ca51238cb9`, all but #40 | `ca51238cb9`, all six |
| --- | --- | --- | --- |
| Front end | 78.66, 81.34, 82.46, 80.80 | 79.86, 85.33, 77.44, 79.42 | 75.19, 72.90, 76.48, 74.88 |
| D+AG | 86.42, 90.07, 85.52, 85.82 | 88.18, 85.26, 84.06, 89.08 | 95.59, 84.90, 87.55, 87.77 |

- **#39 costs nothing.**
  - The front end is 77.4-85.3 MHz against 78.7-82.5.
  - It synthesizes to 5,731 COMB cells against 5,722.
  - The spread overlaps, and Q is still the slowest stage.
- **The D+AG RTL is untouched by the six changes.** Its differences between
  columns come from Yosys's netlist, plus whatever plain `proc` does to its
  small case statements.
- **Mapping the tables to M10K costs the front end about 7%**, which is why
  `proc -norom` stays:
  - F2 becomes the slowest stage at 72.9-76.5 MHz (85.9-90.6 with
    `proc -norom`), and F1 falls to 76.7-85.1.
  - F2's worst endpoints are the opcode-table M10Ks' address registers.
  - The front end synthesizes to 5,633 COMB cells and 36 M10Ks.
  - The Yosys bug is fixed, but mapping the tables to M10K puts an M10K at
    the start of L1's decode, the shape rule 7 keeps out of the pipeline.
- **No stage reaches 100 MHz** apart from M2. The middle column is the recorded
  `ca51238cb9` source state with #40 retained (`proc -norom`); its front-end
  figures are not this PR's current netlist. Later RTL removes the #52 and #55
  workarounds on Yosys `238eac9a49` and adds the `mem_ready` fetch
  qualification (the port is now named `mem_valid`). Those later trees were
  not re-routed in this record. Under
  rule 9 the middle-column clocks land at their measured figures: about 77-85
  MHz for the front end and 84-89 MHz for D and AG.

The opcode-table M10Ks are labelled F2: their address register is F2's byte
register.
