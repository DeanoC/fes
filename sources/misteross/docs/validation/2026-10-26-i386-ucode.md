# i386 microcode ROM and sequencer

Dated record, 2026-10-26. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit.

After [the far slice](2026-10-26-i386-far.md), the CPU gains its microcode
ROM and the real-mode instructions that run from it:
- PUSHA and PUSHAD (60h), POPA and POPAD (61h);
- INT n (CDh), INT3 (CCh) and INTO (CEh);
- IRET and IRETD (CFh).

PUSHF and PUSHFD (9Ch) and POPF and POPFD (9Dh) come with them, as single
uops.

Run data: [`2026-10-26-i386-ucode.jsonl`](2026-10-26-i386-ucode.jsonl).
- The before figures are the far slice's final commit, `465541e257` (the far
  record's rows).
- Routes and the full lockstep runs are of `54ff8b2149`. The commits after it
  change READMEs and merge the far branch; the RTL is the same.
- A Quartus row's `fingerprint` is the first 12 hex digits of the SHA-256 of
  its `sources` map, as JSON with sorted keys.

## The ROM

**256 words of 59 bits, an M10K with a registered output** (two blocks in
each flow). The routines use 28 words.
- `ucode.toml` lists the routines. Each uop names the `ucode_t` fields it
  sets; the rest are zero.
- `scripts/fes_i386_ucode.py` checks every field, value and routine and
  marks each routine's last word. It writes `fes_i386_ucode_pkg.sv` (the
  entries, `UC_<NAME>`) and `fes_i386_ucode_rom.sv` (the ROM, its contents as
  initial assignments, so Verilator, Yosys and Quartus read them without a
  file path).
- `--check` and `tests/test_fes_i386_ucode.py` fail when the checked-in
  files are out of date, or when the generator's field list differs from
  `ucode_t` in `fes_i386_pkg`.
- A word holds only what a routine sets. The operand size, the vector and the
  memory operand come from the instruction in `dc`.

**Issue.** DC decodes a routine's first uop with the instruction, and
`dc.upc` addresses the next word. Each later uop is a `SEQ_UCODE` step of the
far slice's sequencer, so `dc`'s input select keeps its three sources.
- A word is there the cycle after `dc` settles: the address is `dc.upc`, a
  register, and the output is registered.
- So D waits a cycle for each ROM uop (`uc_wait`). `rom_ok`, a register that
  says `dc` was held over the last edge, ends the wait. A first build put a
  compare of the ROM's address in the issue path instead.
- Routines are straight sequences. INTO's JNO, a branch that ends the
  instruction only when taken, is the one microbranch, resolved at EX.

**Stack probe.** PUSHA, POPA and INT start with a probe of all the slots they
will touch, before anything is written.
- Under SS's real-mode limit, FFFFh, a slot faults only by straddling the
  64 KiB wrap. Some slot does when the slots wrap and start misaligned to
  their size.
- M1 flags that as a constant compare (`pbad`), and M2 raises #SS(0) from the
  register. A first build's probe adder in M1 cost it a level.
- Under any other SS limit the three routines are unimplemented.

## The routines

| Instruction | Uops |
| --- | --- |
| PUSHA, PUSHAD | the probe of the eight slots; ESP into T1; the eight pushes, T1's in ESP's place |
| POPA, POPAD | the probe of the eight slots; the seven GPR pops, with ESP's slot read into T1; ESP from T1, kept only for POPAD on a 16-bit stack |
| INT n, INT3 | the vector's offset into T1; its selector into T0; the probe of the three 16-bit slots; push FLAGS, clearing IF and TF; push CS; push IP; the far jump to T0:T1 |
| INTO | a JNO to the next instruction, which ends INTO when taken; with OF set, INT 4's uops |
| IRET, IRETD | the offset's slot into T1; CS's into T0; FLAGS' into FLAGS, checking the offset against CS's limit first; the far jump, stepping ESP past the three slots at WB |
| PUSHF, PUSHFD | one push of EX's FLAGS image |
| POPF, POPFD | one pop into FLAGS |

- **The vector table** is a system access, base 0 and limit FFFFFFFFh, at
  linear vector × 4.
- **A real-mode interrupt's frame is 16 bits.** DC decodes INT n, INT3 and
  INTO at a 16-bit operand size whatever the prefix.
- **EX's flag operations** (`ALU_FLAGS`):
  - FLAGS' image has the high word zero, so PUSHFD pushes VM and RF clear.
  - INT's image also clears IF and TF in EX's running flags.
  - The load takes the writable real-mode flags, bits 0-14 except the fixed
    bits 1, 3 and 5.

## What the 386EX does

The corpus, as before, decides both.
- **POPAD on a 16-bit stack takes ESP's high word from the popped image**
  (divergence `popad-esp-high-word`). The divergence matched the file `6661`;
  it now matches opcode 61 under a 32-bit operand size (a new `opsize32`
  predicate), so random programs follow the 386EX too.
- **A real-mode interrupt reads its vector before it pushes** (divergence
  `interrupt-vector-before-push`, from the BOUND and divide-error states).
  INT's routine is built in that order. Bochs pushes first, so random
  interrupt blocks keep SS above the vector table, where the orders agree.

## Cycle costs

Without latency, measured on corpus states as cycles from start to HLT,
against a NOP's 17; an interrupt's run ends at its handler's HLT. A taken
transfer's figure includes the redirect: 10 cycles over the instruction's
own.

| Instruction | Extra cycles | 386, real mode (clocks) |
| --- | --- | --- |
| PUSHF, POPF | 0 | 4, 5 |
| PUSHA | 18 | 18 |
| POPA | 19 | 24 |
| INT n, INT3 | 22 | 37, 33 |
| INTO, OF clear | 11 | 3 |
| INTO, OF set | 25 | 35 |
| IRET | 20 | 22 |

- Each ROM uop waits a cycle for its word, so a routine of n uops issues in
  about 2n − 1 cycles. That is 9 of PUSHA's and POPA's cycles, 6 of INT's
  and 3 of IRET's.
- INTO with OF clear pays a taken branch's redirect, as the JNO that ends it
  is taken.

**Corpus.** 22,100 new states in 13 files: the eight stems, with the 66h
forms of PUSHA, POPA, PUSHF, POPF and IRET.

**Interrupts in the corpus.** The corpus records INT n, INT3 and INTO as the
test's exception, and its final state is the handler's, at its HLT, with the
pushed frame in RAM.
- The runner lets such a run go on into the handler and passes it when it
  halts there, with the last software interrupt the corpus's.
- When the delivery itself faults (#SS on the probe), the fault is the
  oracle's second event, after the interrupt.

**Random programs** add:
- PUSHA or POPA alone, or a PUSHA ... POPA or PUSHF ... POPF pair around 0-3
  instructions. A pair is fenced, so no backward jump lands inside it: a POPF
  without its PUSHF could set TF, and single-step traps are not built.
- Interrupt blocks:
  - SS set to 100h-EFFFh, above the vector table, and ES to 0;
  - two stores of the handler's CS:IP into the vector's entry;
  - INT n (vectors 20h-FFh), INT3 or INTO;
  - a JMP over the handler, whose body leaves the stack alone and IRETs.
- The random trace differs from the far slice's, as the generator's mix
  changed: 14.4M retirements against 15.3M.

**Holds.** The stack-after-stack hold leaves out PUSHA, POPA, INT n, INT3,
INTO and IRET, which are several uops, and anything after POPA, which loads
ESP.

Mutations, each on 3,500 corpus states from seven microcode files and
2 × 200 random programs, of `54ff8b2149`:

| Mutation | Result |
| --- | --- |
| D does not wait for the ROM's word | 2,891 corpus states and 233 of 400 programs fail |
| M2 does not raise #SS from the probe | 1 corpus state and 3 of 400 programs fail |
| INT does not clear IF and TF | 75 of 400 programs fail; the corpus passes, as all its INT states start with IF and TF clear |

## What the design doc should say

This is reported for the doc's owner to write; the doc is unchanged here.

- **ROM.** 256 × 59-bit words in two M10Ks, built from `ucode.toml`. A word
  carries what its routine sets, and the instruction in `dc` supplies the
  operand size, the vector and the memory operand.
- **Sequencer.** A routine's uops issue from `dc` as the far slice's fixed
  sequences do, the ROM giving the next.
- **The ROM's latency.** It costs a cycle per uop for now, because the word
  is read only once `dc` settles. Reading a word ahead (two entries: the next
  word and the one after it) would let the uops issue back to back, about 9
  cycles off PUSHA and POPA.
- **Microbranches.** None but INTO's JNO. Its taken case, OF clear, pays a
  redirect; ending a routine without one is a later option.
- **Stack probes.** A routine checks all the slots it will touch with one
  probe, its first uop, before anything is written. Only SS's real-mode
  limit is built.
- **Interrupts** read the vector's entry before pushing, as the 386EX does,
  and push a 16-bit frame in real mode whatever the operand size.
- **Clock.** On nextpnr DC's routed limit is D's issue into `dc`, a
  routing-dominated loop. Every hold term that joins `issue`'s AND costs
  there; this slice added the microcode wait. The uop bubble above is a
  separate cost from this loop.
- **Next.** Exception delivery: faults go through the vector table with
  INT's routine.
