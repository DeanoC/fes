# i386 POP m with 32-bit addressing

Dated record, 2026-10-28. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit.

This slice builds POP m (`8F` /0) with a 32-bit address (`678F`, `67668F`),
the two corpus files the lockstep's `UNBUILT_FILES` held back. It is stacked
on [the CLTS and WAIT slice](2026-10-28-i386-clts-wait.md).

Run data: [`2026-10-28-i386-popm32.jsonl`](2026-10-28-i386-popm32.jsonl).
- The checks, the routes and Quartus are of `23e879fcbe`. The head then
  merges the CLTS and WAIT branch (its record, and the BOUND branch's
  latest); on the merge, the new files with the 16-bit POP m's, CLTS's and
  BOUND's, 8 × 300 random programs and the 16 directed cases pass.
- The before figures are the CLTS and WAIT record's routes and Quartus
  runs of `a5e675ef20`, whose RTL is this branch's base's, with the same
  tools.
- Quartus runs at its best, the script of
  [#1184](https://github.com/DeanoC/fes/pull/1184) at its head `471d218a5b`,
  at a 120 MHz target.
- Eight nextpnr seeds. A Quartus row's `fingerprint` is the first 12 hex
  digits of the SHA-256 of its `sources` map, as JSON with sorted keys.

## The 386EX's POP m

Before any RTL, the corpus's two files (2,000 states) were fitted:

| Case | The 386EX |
| --- | --- |
| An address that reads ESP | Reads ESP after the pop: of the 37 states that complete with ESP in the address (all of them `[ESP + r * scale + disp]`), all 37 match ESP after the pop and 35 do not match ESP before it |
| A store that faults | Leaves ESP as it was: all 307 states that raise #GP(0) or #SS(0) push their frame at the unmoved ESP |
| A 16-bit stack's SP | Wraps: no corpus state reaches it with ESP in the address (no state has SP within the slot's size of 10000h there) |

Bochs computes the address after its pop too (its `POP_EwM` and `POP_EdM`)
and restores ESP when the store faults, so the lockstep compares against it
directly, the wrap included.

## How it runs

SEQ_POPM already stored before it popped, for the 16-bit forms: the slot
into T1 with ESP unmoved, the store of T1, then a pop into nothing that
steps ESP. A faulting store so leaves ESP, and that order stays. The store's
address must read ESP after the pop, which has not happened yet:

- **The store waits for T1**, so when D issues it every older uop has
  retired and ESP is the register file's, not in flight.
- **D adds the pop to the displacement**: the operand size, scaled as ESP
  is (`esp_adj`), and, when a 16-bit stack's SP wraps, less 10000h so
  scaled (`esp_wrap`). SP wraps only from its top slot, FFFEh for a word or
  FFFCh for a dword, since a slot past that faults first. That is one more
  input to the adder D already has for a far pointer's selector, beside a
  compare of SP's top bits.
- **ESP as the 386EX's scaled base** of an invalid SIB (index 100b with a
  scale) takes the same rule, the size scaled by the SIB's scale.
- `fes_i386_seq` sets `esp_adj` and `esp_wrap` at the store's step from the
  ModRM operand's registers, which DC kept (`m_*`).

## The testbench

- `UNBUILT_FILES` goes, so the corpus run takes `678F` and `67668F` (2,000
  states).
- Random programs gain a block: ESP set below 10000h (to 0 in a third of
  them, so the pop wraps SP from its top slot), a value pushed, then popped
  to `[ESP + disp8]`, `[ESP + r * scale + disp8]` or `[r + disp8]`, with r
  set small first.
- **Not checked:** ESP scaled by an invalid SIB. No corpus state has it, and
  the divergence `invalid-sib-scales-base` leaves every invalid SIB to the
  corpus, so in a random program Bochs takes the RTL's results. The block
  leaves it out.

**Depth.** Synthesized as `scripts/benchmark_fes_i386.py` does, before any
route, D's deepest path is 11 LUT levels, as at the base: the store's
displacement adds an input to an adder already there, beside a compare of
SP's top bits, both off that path. DC (12) and EX (12 and one carry cell)
