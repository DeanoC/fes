# i386 lock bump to Yosys 238eac9a49: the #52 and #55 workarounds removed

Dated record, 2026-10-25. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit. It moves the i386 lock from Yosys `ca51238cb9`
([previous record](2026-10-25-i386-yosys-ca51238cb9.md)) to DeanoC/yosys main
`238eac9a49`. That pin adds three fork PRs:
- **#53** fixes #52, member selects on packed struct arrays;
- **#58** fixes #55, bare calls to imported package functions;
- **#48** fixes #38, assignment patterns. The RTL never used them, so there
  is nothing to remove for it.

nextpnr `bd7a1c0d`, Mistral `8fcc4cb4` and the shared `toolchain.lock` are
unchanged. Synthesis keeps `proc -norom` by choice, as the previous record
explains. Run data:
[`2026-10-25-i386-yosys-238eac9a49.jsonl`](2026-10-25-i386-yosys-238eac9a49.jsonl).

## Removed

- **#52.** L1, L2, the fetch buffer, Q and the length-sweep wrapper read and
  write record fields directly as `arr[i].field`. The whole-record copies
  are gone.
- **#55.** L1 and Q call `is_prefix` and `add_prefix` by their bare names
  through the package import.

The RTL README's remaining rules are #38 (no assignment patterns) and #51
(replicas need their own kept register).

record's for all three checks, with no implicitly declared wire:

length sweep mismatches every one of 393,216,000 cases per default size and
leaves 224 implicitly declared wires. That is bug #52 itself.
