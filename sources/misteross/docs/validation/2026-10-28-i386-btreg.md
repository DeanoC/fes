# i386 bit test by a register

Dated record, 2026-10-28. Host simulation and routed diagnostics on Powerboat
and the CUDA route host. No package, RBF or kit.

This slice builds BT, BTS, BTR and BTC by a register (`0F A3`, `AB`, `B3`,
`BB`), the half of the bit tests that [the bit test and scan
record](2026-10-28-i386-bits.md) left: a memory operand's address moves by the
register, a term the AGU does not have. It also moves the bit tests by an
immediate onto the same bit path. It is stacked on that slice.

Run data: [`2026-10-28-i386-btreg.jsonl`](2026-10-28-i386-btreg.jsonl), each
row's `state` one of these:
- `before`: #1185's head, `592be15ebf`. Its record's nextpnr routes (of
  `3f345f7274`, the same RTL), and Quartus fitted here.
- `first`: a first version, `2c445382e1`, whose memory form put T1 into AG
  on two new inputs (see Result).
- `variant-base` and `variant-no-t1-inputs`: seeds 2 to 4 of the base and of
  the first version with those two inputs deleted (timing only), on the
  CUDA host.
- `after`: this slice's RTL, `0f52bb261f`, which every check below ran on;
  the head adds the docs and a merge of #1185's base.

Quartus runs at its best, DSP blocks for the four muldiv products (the
script of [#1184](https://github.com/DeanoC/fes/pull/1184) at `6966609b54`),
with a 120 MHz target on every side so no fit eases off at a met target, so
its figures are not comparable with #1185's at 100 MHz. nextpnr `bd7a1c0d`
routes eight seeds: `before` and `first` with HIP on Powerboat, `after` and
the variants with CUDA on the route host, whose route results are the same
for the same netlist. A Quartus row's `fingerprint` is the first 12 hex
digits of the SHA-256 of its `sources` map, as JSON with sorted keys.

## The 386EX's results

Bochs computes the address as `eaddr + 2 * (n >> 4)` for a word,
`eaddr + 4 * (n >> 5)` for a dword (n the register, signed), wrapped by
address size before the segment (`BT_EwGwM`, `BT_EdGdM`). The bit is n mod
the size. Before any RTL, that and #1185's flag rules (CF the bit, OF the two
bits below it XORed, SF, ZF, AF and PF kept) were checked on every
SingleStepTests state of the 16 files: all 14,250 that do not fault match,
register and memory forms, both address sizes. The 32-bit addresses need the
386EX's scaled base (a SIB with no index scales the base), which the RTL's
AGU already has.

LOCK is valid on BTS, BTR and BTC with a memory operand, #UD on BT and on
register forms, as for the immediate forms.

## How it runs

- **The bit number** comes through the shifter's count for every bit test:
  the immediate, or the register with its bypass from WB, as a shift's CL.
  EX builds the one-hot mask after that bypass, mod the size; CF and OF are
  the mask (and the masks one and two below it) ANDed with x and ORed; BTS,
  BTR and BTC set, clear or flip the bit. #1185's mask and bit indices in M2
  are deleted.
- **A register operand** is one uop, as BT by an immediate.
- **A memory operand** is `SEQ_BTM`, three uops through T1, since the AGU's
  3:2 rows already hold the segment base, base, scaled index and
  displacement:
  1. T1 ← the displacement (`ALU_BITDISP`, the unused XCHG slot): the
     register's bits shifted and sign-extended, wiring in EX after the
     bypass.
  2. T1 ← T1 plus the operand's displacement, an ADD.
  3. The bit test at the operand's address, base and index as decoded, with
     T1 as its displacement (`disp_t1`). T1 reaches AG through `far_off`,
     the input a far jump's offset from T1 already takes, so D's AG
     registers gain no input from T1. AG wraps the offset by address size
     as for any operand, which is Bochs's wrap of the sum before the
     segment. With a 16-bit address T1's top half is whatever the ADD left:
     AG's sums read only bits 15:0 of a 16-bit address's terms, as they
     already did of its base and index registers, and its port comment now
     says so.
  Each step waits for the T1 before it to retire, as POP m's do. D reads
  that wait from one register (`t_rd`, set by the sequencer for every step
  that reads T0 or T1), not an OR of the step's flags, so D's issue gains
  no input.
- **Cost:** a memory operand takes about 12 cycles more by a register than
  by an immediate, without latency: the corpus files' average per state is
  8.6 (BT) and 8.9 (BTS) cycles higher, about three in four of their
  states being memory forms.

## The testbench

- `SCOPE` gains the four stems: 16 files, 40,000 states.
- Random programs gain BT, BTS, BTR and BTC by a register, register and
  16-bit-addressed memory forms (the generator makes no 32-bit addresses, so
  those are the corpus's alone).

**nextpnr is 1.2 MHz lower, within the seeds' spread, and Quartus is not
lower.** nextpnr gives 60.5 against 61.7. On the three seeds routed on one
host, it is 61.1 against the base's 61.6. EX limits 7 of 8 seeds, at 60.8
against 63.6: its worst paths run from the shifter's count logic through
the adder into EX's result, where the bit's mask now sits after the count's
bypass. EX's netlist depth is the base's (12 LUTs and a carry). Quartus at
its best gives 102.2 against 101.5, Q-limited as before.

**The first version cost about 3 MHz on nextpnr, in D and DC.**
- It put T1 into D's AG registers twice: as the segment term of an address
  step, whose linear sum M1 returned (`addr_t1`), and as a new displacement
  leg (`disp_t1`). DC fell to 60.3 and D to 60.4.
- Neither input was on a critical path. The 32-bit `ag_disp` and
  `ag_seg_term` registers kept 0.4 ns or more of slack, and the nets out of
  T1 more than 6 ns. The slow paths were D's and DC's existing issue paths,
  routing longer: placement, not depth, for D's and DC's netlist depth was
  the base's.
- Deleting only those two inputs, which breaks the memory form, gave 60.4
  on seeds 2 to 4, against the first version's 56.5 and the base's 61.6.
- So the slice folds the bit's displacement into the displacement with an
  ADD, and the bit test takes T1 through `far_off`, which already carries a
  far jump's offset from T1. That gets D (62.4) and DC (64.6) back.

## What the design doc should say

This is reported for the doc's owner to write; the doc is unchanged here.

- **BT, BTS, BTR and BTC with a register bit offset** take their memory
  operand's address through a fixed three-uop sequence: the bit's
  displacement into a temporary, the operand's displacement added to it,
  then the access at the operand's address with the temporary as its
  displacement. AG gains no term.
- **A new 32-bit input into D's AG registers costs nextpnr even when no
  path through it is critical.** Here two cost about 3 MHz through
  placement. A sequence should reach AG through an input that already
  exists, as this one does through `far_off`.
