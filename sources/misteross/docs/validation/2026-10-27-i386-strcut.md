# i386 string waits: the string engine off the issue loop

Dated record, 2026-10-27. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit.

[The strings slice](2026-10-27-i386-strings.md) put D's string engine on the
loop through D's issue. nextpnr fell from 70.2 to 61.7 MHz, DC-limited on
six seeds of eight, and every seed's critical path started at dops' `ready`
registers. This slice takes those paths off without changing any cycle,
which the latency-free comparison below shows.

Run data: [`2026-10-27-i386-strcut.jsonl`](2026-10-27-i386-strcut.jsonl).
- The before figures are the strings slice's `e9f610d0a8` (its record's rows).
- Routes are of `77e83b0eba`, before the branch merged MUL/DIV (#1167) from
  the strings slice. The strings figures are from before it too.
- The full lockstep runs are of `77e83b0eba` and of the merge,
  `d86fe4be41`.
- Eight nextpnr seeds. A Quartus row's `fingerprint` is the first 12 hex
  digits of the SHA-256 of its `sources` map, as JSON with sorted keys.

## The paths

On the strings slice a string's first uop decided its next step from ECX as
D forwards it:
- dops selects ECX's value from the result registers (by `ready`);
- D compares it with 0, 1 and 2;
- `fes_i386_seq` builds the first element from that, or the NOP that ends
  a REP with a count of 0, into `dc`.

That is one path from dops' registers through two compares and seq's muxes
into `dc`'s data. ENTER's first uop latched its copies through dops' select
by register number, then a subtract.

## The cut

- **The first element is built without the count.** Under REP it looks
  like one of several. The string's first uop latches two flags from ECX:
  - `s_end1`: the first element ends the instruction (a count of 0, or 1
    but for CMPS, whose first uop is a load);
  - `s_kill1`: it does nothing (a count of 0).
  D then issues that element as the instruction's last, or as a NOP that
  ends it, in the cycle the old build issued it. `dc_more` is `dc.more`
  without `s_end1`, so `dc_load` gains one register input.
- **What D does not track for a NOP.** A killed element writes no GPR in D's
  tables, sets no busy bit and holds no load behind it, as the NOP it
  stands for did not.
- **The count's predicates.** Whether the copy is 0, 1 and 2 (`r_c0` to
  `r_c2`) is kept in registers beside it, which seq reads. Their compares
  end at flip-flops.
- **Fixed registers.** The first uop's registers are always ESI, EDI and
  ECX, or ESP and EBP for ENTER.
  - dops gives each GPR's value and pending bit, by register.
  - The copies latch from those values, and the start's waits read those
    bits, with no select by register number.
- **The wait behind a string's steps.** Which of ESI, EDI and ECX a uop
  reads (`rd_str`) is decoded into `dc`: by DC for its own uop and by seq
  for each step, with `fes_i386_pkg::str_reads`. That wait is now one AND
  with the busy bits.

| --- | --- | --- |
| D's deepest path | 11 LUT levels, to `r_dst` | 10, to dfwd's `lt` (9 on #1161) |
| DC's deepest path | 11, the decode into AG's register | 10, the same |

`issue` itself is no shallower: the cut takes the two paths that started at
dops' registers off it, not its depth.

**nextpnr averages 66.9 MHz against 61.7**, and no seed's critical path is
the string engine's loading of its copies.
- DC's three seeds (65.3, 65.3, 67.0) are DC's own decode, from Q's
  register into `dc0`, `dc_skid` and AG's register, as before the strings
  slice.
- The rest are EX's flush decision, Q's prefix loop, and on seed 6 the
  start's count compare into `s_kill1`. That path now ends at a flip-flop,
  but it is still ECX's forwarded value and a 32-bit compare.
- **DC averages 68.6 against #1161's 73.2.** Every other stage is lower than
  on #1161 too, by 1.7-9.2 MHz. The design is 12% larger in ALUTs (below), and
  the same device places it worse. So DC sits about where the CPU's other
  stages now do, not back at #1161's figure.

**Quartus averages 104.3 against 99.8** (#1161: 102.1), Q-limited on three
seeds.

## What the design doc should say

This is reported for the doc's owner to write; the doc is unchanged here.

- **A string's first element** is issued as the last, or as a NOP, by D
  from flags its first uop latches, since seq builds it before the count is
  in D's copy.
- **The string engine reads its fixed registers** directly from D's
  forwarding (each GPR's value and pending bit), not through a select by
  register number.
