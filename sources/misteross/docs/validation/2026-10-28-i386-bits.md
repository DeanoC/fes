# i386 bit test by an immediate, BSF and BSR

Dated record, 2026-10-28. Host simulation and routed diagnostics on Powerboat.
No package, RBF or kit.

This slice builds BT, BTS, BTR and BTC by an immediate (`0F BA` /4 to /7) and
BSF and BSR (`0F BC`, `0F BD`), each one uop, as the design's
[decode](../i386-cpu-design.md#decode-and-microcode) and
[execute](../i386-cpu-design.md#execute) sections ask. It is stacked on
[the mid-REP interrupts slice](2026-10-28-i386-rep-interrupts.md).

Run data: [`2026-10-28-i386-bits.jsonl`](2026-10-28-i386-bits.jsonl).

## The 386EX's flags

The manual leaves most of these flags undefined. The Phase 0 divergence
entries `bit-test-of` and `bsf-bsr-flags` already follow the 386EX, so the
corpus run checks them against SingleStepTests' states. Before any RTL, the
rules below were fitted to the corpus's register forms and then checked on
every state of the 24 files, memory forms included: all 54,246 that do not
fault match.

| Instruction | Rule |
| --- | --- |
| BT, BTS, BTR, BTC | CF is bit n, n the immediate mod the size. OF is bits n − 1 and n − 2 XORed, mod the size: the top two bits of the operand rotated right by n. SF, ZF, AF and PF stay. BTS, BTR and BTC set, clear or flip bit n |
| BSF, source 0 | ZF and PF set, CF, AF, SF and OF clear; the destination stays |
| BSF, bit 0 set | CF is bit 1, PF the parity of the source less 1, AF set, SF the top bit's complement, OF the top bit |
| BSF, index above 0 | PF the parity of the index; CF, AF, SF and OF clear |
| BSR, source 0 | As BSF's |
| BSR | CF is the bit below the index. PF the parity of the source less 1. AF set when bits 3:0 are not all 0. SF the complement of the source less 1's top bit. OF set at index 0, else the two bits below the index XORed |

LOCK is valid on BTS, BTR and BTC with a memory operand and raises #UD on BT
and on any register form, as the corpus shows; the decoder's rule that LOCK
needs a read-modify-write gives that.

## How it runs

- **Decode.** `0F BA` /4 to /7 is one ALU uop on the r/m operand with the
  immediate: BT a load, the others a read-modify-write. BSF and BSR read
  r/m as src2 and the destination as src1, whose value a source of 0 keeps.
  `0F BA` /0 to /3 stay unbuilt, as do BT, BTS, BTR and BTC by a register
  (below).
- **M2** builds the bit's mask from the immediate as y, its complement for
  BTR, so EX's logic unit makes BTS's, BTR's and BTC's result. It registers
  the indices of bit n and the two below it.
- **EX** takes CF and OF from bit selects of x. BSF and BSR scan y through
  one-hot vectors of its lowest and highest set bit, each an OR of the bits
  on one side: the index ORs out of the vector, and BSR's CF and OF are the
  vector ANDed with the bits below it, so no index is decremented and no
  bit is selected by one. Their flags take the last assignment in EX's flag
  select, since they come from y last.

**Not built:** BT, BTS, BTR and BTC by a register (`0F A3`, `AB`, `B3`,
`BB`). A memory operand's address moves by the register's value shifted
right by 3, a fifth term the AGU does not have, so it needs a sequence
through a temporary; and no uop yet takes its address from one.

## The testbench

- `SCOPE` gains the six stems, so the corpus run takes the 24 files (60,000
  states).
- Random programs gain BT, BTS, BTR and BTC by an immediate (mostly below
  32, now and then any byte) and BSF and BSR, in register and memory forms.
  Memory starts zeroed, so memory forms scan a 0 often.
- In random programs the divergent flags are left to the corpus, so there
  the oracle takes the RTL's.

**The slice costs nothing measurable,** on either flow. Quartus at its best
is 102.8 MHz against 101.1, Q-limited, as it was before the multiplier;
nextpnr 61.7 against 60.5. Best against best, Quartus's best seed is 61%
above nextpnr's on this RTL (104.47 against 64.82), its average 67% above
(102.8 against 61.7).

**The first version cost 5 MHz on nextpnr, and it was the scan.**
- Its netlist had EX 16 LUT levels and 2 carry cells against the base's 12
  and 1, M2 14 against 11, and DC 16 against 12. BSF and BSR found the index
  with a priority loop, then decremented it on a carry chain to select the
  bits below it.
- Synthesizing variants placed DC's extra depth too. The base with only the
  new decode cases has the base's depths (DC 12); everything but them has
  DC 16. So DC's depth came from EX's scan through ABC's mapping of the
  whole netlist, not from the decode.
- The one-hot scan brings each stage back: D 11, DC 12, EX 12 + 1 carry, M2
  12. A last carry chain in DC, BT's op as 19 plus the reg field, is a table
  now.

## What the design doc should say

This is reported for the doc's owner to write; the doc is unchanged here.

- **BSF and BSR's flags** are the 386EX's, tabled above; "the destination
  for a zero source follows the corpora" is: kept.
- **BT with a register bit offset** needs its memory operand's address moved
  by the register, a term the AGU does not have: a microcode or fixed
  sequence through a temporary, as the design's microcode list already
  says, and a temporary as an address base, which no uop has yet.
